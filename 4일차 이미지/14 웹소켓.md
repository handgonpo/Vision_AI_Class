
### 1️⃣ 웹소켓(WebSocket) 개요

웹소켓(WebSocket)이란?  
브라우저(클라이언트)와 서버가 연결을 계속 유지하면서 실시간으로 데이터를 주고받는 통신 방식입니다.
일반적인 웹 통신은 HTTP 요청 → 응답 → 연결 종료 구조입니다.

하지만 웹소켓은 다음과 같습니다.
```
연결 요청 → 연결 유지 → 실시간 양방향 통신
```
즉,
- 서버 → 클라이언트
- 클라이언트 → 서버
    
둘 다 언제든지 데이터를 보낼 수 있는 구조입니다.

### 2️⃣ HTTP 방식과 WebSocket 차이

HTTP 방식:
웹페이지 대부분은 HTTP 방식입니다.
```
클라이언트 → 요청 → 서버  
서버 → 응답 → 클라이언트  
연결 종료
```
예
```
페이지 새로고침  
게시글 조회  
상품 목록 조회
```
문제
- 매번 연결해야 함
- 실시간 통신 불가능

WebSocket 방식:
웹소켓은 한번 연결하면 유지됩니다.
```
연결 요청  
↓  
연결 유지  
↓  
실시간 데이터 교환
```
예
```
채팅 메시지  
실시간 게임  
주식 가격  
라이브 방송
```

### 3️⃣ WebSocket 동작 과정
	웹소켓은 처음에는 HTTP로 시작합니다.

`1단계`
클라이언트가 서버에게 요청
```
HTTP Upgrade 요청
```

예
```
GET /ws HTTP/1.1  
Upgrade: websocket
```

`2단계`
서버가 웹소켓 연결 허용
```
HTTP 101 Switching Protocols
```

`3단계`
이후에는 웹소켓 프로토콜로 통신
```
클라이언트 ↔ 서버
```
연결이 유지됩니다.

### 4️⃣ WebSocket 데이터 처리 방식
	웹소켓은 보통 DB를 거치지 않고 메모리에서 처리되는 경우가 많습니다.

예 : 채팅
```
사용자 A 메시지 입력  
↓  
서버 메모리  
↓  
다른 사용자에게 즉시 전송
```
이 과정은 보통 RAM 메모리에서 처리됩니다. 왜냐하면 DB를 거치면 느립니다.

### 5️⃣ WebSocket 데이터 흐름

채팅 예시 흐름
```
사용자 A  
   │  
   │  메시지 전송  
   ▼  
WebSocket 서버  
   │  
   │ 메모리에 저장  
   │  
   ▼  
사용자 B  
사용자 C  
사용자 D
```

실제 내부 흐름
```
Browser A  
   │  
   │ send()  
   ▼  
WebSocket Server  
   │  
   │ RAM (메모리)  
   │  
   │ broadcast  
   ▼  
Browser B  
Browser C  
Browser D
```

2️⃣ `[서버 코드 작성]` WebSocket 서버 만들기 : 
파일명 예시: `websocketsServer.py`
```python
from fastapi import FastAPI, WebSocket
from fastapi.responses import HTMLResponse

app = FastAPI()

@app.websocket("/ws") # 클라이언트는 ws://localhost:8000/ws 로 연결
async def websocket_endpoint(websocket: WebSocket):
    await websocket.accept() # 클라이언트의 WebSocket 연결 요청을 수락
    while True:
    
	    # 클라이언트로부터 텍스트 메시지를 기다림 (await → 비동기 처리)
        data = await websocket.receive_text()
		
		# 받은 메시지를 다시 클라이언트에게 전송 (Echo 방식)
        await websocket.send_text(f"Message text was: {data}")
```
- `/ws` 경로로 클라이언트가 WebSocket 연결 요청
- 연결 수락 후, 클라이언트 메시지를 받아서 다시 응답(echo) 전송

`[HTML 클라이언트 코드 작성]` WebSocket 클라이언트 구현
같은 서버 파일에 HTML 문자열 추가  
(`websocketsFullCode.py` 형태로 작성 가능)
```python
html = """
<!DOCTYPE html>
<html>
  <head><title>Chat</title></head>
  <body>
    <h1>WebSocket Chat</h1>
    <form action="" onsubmit="sendMessage(event)">
        <input type="text" id="messageText" autocomplete="off"/>
        <button>Send</button>
    </form>
    <ul id='messages'></ul>

    <script>
        const ws = new WebSocket("ws://localhost:8000/ws");

        ws.onmessage = function(event) {
            const messages = document.getElementById('messages');
            const message = document.createElement('li');
            const content = document.createTextNode(event.data);
            message.appendChild(content);
            messages.appendChild(message);
        };

        function sendMessage(event) {
            const input = document.getElementById("messageText");
            ws.send(input.value);
            input.value = '';
            event.preventDefault();
        }
    </script>
  </body>
</html>
"""
```

파일 구조

`main.py`
```python
from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from fastapi.responses import HTMLResponse

# FastAPI 앱 생성
app = FastAPI()

# -----------------------------
# HTML 클라이언트 코드
# 브라우저에서 채팅 UI 역할
# -----------------------------
html = """
<!DOCTYPE html>
<html>
<head>
    <title>FastAPI WebSocket Chat</title>
</head>
<body>

<h1>WebSocket Chat</h1>

<!-- 사용자 이름 입력 -->
<input type="text" id="username" placeholder="username">

<br><br>

<!-- 메시지 입력 -->
<form onsubmit="sendMessage(event)">
    <input type="text" id="messageText" autocomplete="off">
    <button>Send</button>
</form>

<ul id='messages'></ul>

<script>

    // FastAPI WebSocket 서버 연결
    var ws = new WebSocket("ws://127.0.0.1:8000/ws");

    // 서버에서 메시지 받으면 화면에 출력
    ws.onmessage = function(event) {
        var messages = document.getElementById('messages');

        var message = document.createElement('li');
        var content = document.createTextNode(event.data);

        message.appendChild(content);
        messages.appendChild(message);
    };

    // 메시지 전송 함수
    function sendMessage(event) {

        var username = document.getElementById("username").value;
        var input = document.getElementById("messageText");

        // JSON 형식 메시지 생성
        var payload = {
            username: username,
            message: input.value
        };

        // 서버로 메시지 전송
        ws.send(JSON.stringify(payload));

        input.value = '';
        event.preventDefault();
    }

</script>

</body>
</html>
"""


# -----------------------------------------
# WebSocket 연결 관리 클래스
# 현재 접속 중인 사용자 관리
# -----------------------------------------
class ConnectionManager:

    def __init__(self):
        # 현재 접속한 WebSocket 목록
        self.active_connections = []

    async def connect(self, websocket: WebSocket):

        # WebSocket 연결 허용
        await websocket.accept()

        # 접속 목록에 추가
        self.active_connections.append(websocket)

    def disconnect(self, websocket: WebSocket):

        # 연결 종료 시 목록에서 제거
        self.active_connections.remove(websocket)

    async def broadcast(self, message: str):

        # 현재 접속한 모든 사용자에게 메시지 전송
        for connection in self.active_connections:
            await connection.send_text(message)


# ConnectionManager 객체 생성
manager = ConnectionManager()


# -----------------------------------------
# 기본 페이지
# 브라우저에서 채팅 UI 열기
# -----------------------------------------
@app.get("/")
async def get():
    return HTMLResponse(html)


# -----------------------------------------
# WebSocket 채팅 엔드포인트
# -----------------------------------------
@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):

    # 사용자 접속 처리
    await manager.connect(websocket)

    try:

        # 접속 알림
        await manager.broadcast("새 사용자가 입장했습니다.")

        while True:

            # 클라이언트 메시지 수신
            data = await websocket.receive_json()

            username = data.get("username", "anonymous")
            message = data.get("message", "")

            # 메시지를 모든 사용자에게 전송
            await manager.broadcast(f"{username}: {message}")

    except WebSocketDisconnect:

        # 연결 종료 시 처리
        manager.disconnect(websocket)

        await manager.broadcast("한 사용자가 나갔습니다.")
```

```
Connection: Upgrade  
Upgrade: websocket
```

### 교과 15 응용 — IP Webcam과 WebSocket을 함께 사용하는 실시간 동작인식

앞에서는 WebSocket으로 채팅 메시지를 주고받았습니다. 이번에는 같은 원리를 **교과 15의 산업안전 동작인식 솔루션**에 연결해 봅니다.

교과 15에서는 스마트폰의 IP Webcam으로 촬영한 사람의 움직임을 FastAPI에서 분석하고, 분석 결과를 HTML 화면에 실시간으로 표시할 수 있습니다. 이때 **카메라 영상을 가져오는 통신**과 **AI 분석 결과를 웹 화면에 전달하는 통신**은 서로 다른 방식을 사용해도 됩니다.

#### 1. IP Webcam을 사용하면 WebSocket을 사용할 수 없나요?

**사용할 수 있습니다.** IP Webcam 앱이 WebSocket을 직접 지원할 필요는 없습니다.

- **IP Webcam → FastAPI:** 카메라가 제공하는 HTTP MJPEG 또는 RTSP 영상 주소로 프레임을 수신합니다. 실제 지원 방식은 사용하는 앱에 따라 다릅니다.
- **FastAPI 내부:** OpenCV로 프레임을 읽고, Pose Estimation으로 관절을 추출한 뒤 Action Recognition으로 동작을 분류합니다.
- **FastAPI → HTML:** 영상은 HTTP MJPEG 스트리밍 등으로 표시하고, 동작명·신뢰도·경고·FPS 같은 **분석 결과는 WebSocket**으로 전송할 수 있습니다.

즉, **입력은 HTTP/RTSP, 출력 결과는 WebSocket**인 구조가 가능합니다.

#### 2. 교과 15의 전체 연결 구조

```
┌──────────────────────────────┐
│ 스마트폰 IP Webcam           │
│ 사람의 동작 실시간 촬영      │
└──────────────┬───────────────┘
               │ HTTP MJPEG 또는 RTSP
               ▼
┌──────────────────────────────────────────────┐
│ FastAPI 서버 (Python)                        │
│                                              │
│  OpenCV: 카메라 프레임 수신                    │
│           ↓                                  │
│  YOLO Pose 등: 사람·관절(Keypoint) 추출        │
│           ↓                                  │
│  Action Recognition: 동작 분류                │
│           ↓                                  │
│  분석 결과 생성 (동작명·신뢰도·경고·FPS)         │
└────────────┬───────────────────┬─────────────┘
             │                   │
             │ HTTP MJPEG        │ WebSocket
             │ 영상 전송          │ 분석 결과(JSON) 전송
             ▼                   ▼
┌──────────────────────────────────────────────┐
│ HTML + JavaScript 웹 브라우저                  │
│                                              │
│  카메라 영상 표시 │ 동작명 · 경고 · FPS 표시     │
└──────────────────────────────────────────────┘
```

영상에 Skeleton이나 BBox를 표시하려면 FastAPI에서 프레임에 그려서 전송하거나, 브라우저에서 관절 좌표를 받아 별도로 그리는 방법을 선택할 수 있습니다.

#### 3. 각 구간에서 어떤 통신을 사용하나요?

|연결 구간|권장 통신|역할|
|---|---|---|
|스마트폰 IP Webcam → FastAPI|HTTP MJPEG 또는 RTSP|실시간 영상 입력|
|FastAPI 내부|Python 코드|OpenCV 전처리·Pose 추정·동작 분류|
|FastAPI → HTML 영상 영역|HTTP MJPEG 스트리밍|카메라 영상 및 필요 시 Skeleton 표시|
|FastAPI → HTML 결과 영역|**WebSocket**|동작명·신뢰도·경고·FPS 등 실시간 갱신|
|HTML → FastAPI|HTTP 또는 WebSocket|분석 시작·중지 등의 사용자 명령|

여기서 **WebSocket은 영상 수신의 필수 조건이 아니라, 서버가 분석 결과를 웹 화면으로 빠르게 전달하는 통신 수단**입니다.

#### 4. WebSocket이 HTTP보다 더 빠른가요?

**반복적인 결과 알림에서는 WebSocket이 유리할 수 있지만, 언제나 더 빠른 것은 아닙니다.** 비교 대상인 HTTP 방식에 따라 결과가 달라집니다.

|비교 항목|HTTP Polling|HTTP MJPEG 스트리밍|WebSocket|
|---|---|---|---|
|기본 방식|일정 주기로 요청·응답 반복|연결을 유지하며 영상 프레임 전송|연결 유지, 양방향 메시지 전송|
|실시간 결과 알림|다음 요청까지 기다릴 수 있음|주로 영상 표시에 사용|결과 발생 시 바로 전송하기 편리|
|교과 15 권장 용도|초기 상태 조회 등|**영상 표시**|**AI 분석 결과·경고 전달**|

예를 들어 브라우저가 HTTP Polling으로 1초마다 결과를 요청하면 새 동작을 인식해도 다음 요청 때까지 표시가 늦어질 수 있습니다. 반면 WebSocket을 연결해 두면 FastAPI가 결과를 만드는 즉시 브라우저로 보낼 수 있습니다.

그러나 HTTP MJPEG도 연결을 유지하면서 프레임을 연속 전송합니다. 따라서 **영상 자체를 보내는 속도는 WebSocket이 반드시 더 빠르다고 말할 수 없습니다.** 해상도, 인코딩, 네트워크, 서버 처리 방식에 따라 다릅니다.

#### 5. WebSocket을 사용하면 교과 15의 30 FPS 목표를 달성할 수 있나요?

**WebSocket만 변경한다고 AI 처리 FPS가 높아지지는 않습니다.** 프레임 처리 속도는 주로 다음 요소의 영향을 받습니다.

1. 카메라 영상의 해상도 및 프레임 수신 속도
2. YOLO Pose 추론 시간
3. Action Recognition 추론 시간
4. 이미지 인코딩·네트워크 전송 지연
5. 브라우저 화면 표시 비용

예를 들어 AI 분석이 실제로 초당 15프레임만 처리한다면 결과를 WebSocket으로 전달해도 **AI 분석 속도가 30 FPS로 올라가지는 않습니다.** 교과 15에서는 AI 처리 FPS와 웹 화면 표시 지연을 구분해서 측정해야 합니다.

참고로 웹 화면에 표시하는 예측 **신뢰도(Confidence)**와 테스트 데이터에서 측정한 모델 **정확도(Accuracy)**는 서로 다른 개념입니다. 두 수치를 같은 의미로 사용하지 않습니다.

#### 6. 교과 15 권장 구현 순서

```
1단계  IP Webcam 영상을 OpenCV로 읽기
  ↓
2단계  FastAPI에서 영상을 HTML에 표시하기 (HTTP MJPEG)
  ↓
3단계  YOLO Pose로 사람·관절을 추출하기
  ↓
4단계  Action Recognition으로 현재 동작 분류하기
  ↓
5단계  FastAPI WebSocket(/ws/results)으로 결과 전송하기
  ↓
6단계  JavaScript에서 메시지를 받아 동작명·경고·FPS 갱신하기
  ↓
7단계  분석 FPS와 화면 표시 지연을 각각 측정하기
```

WebSocket으로 전달하는 데이터는 다음과 같은 **JSON 메시지**로 구성할 수 있습니다. 아래 값은 형식을 보여 주기 위한 예시입니다.

```
{
  "action": "stop",
  "confidence": 0.92,
  "alert": false,
  "processing_fps": 28.5
}
```

**최종 정리:** 교과 15에서는 **IP Webcam → FastAPI(OpenCV·Pose·Action Recognition) → HTML** 구조를 사용하면서, 영상은 HTTP MJPEG로 표시하고 AI 분석 결과는 WebSocket으로 보내는 방식을 먼저 구현하는 것이 좋습니다. 이후 필요하면 WebSocket 영상 전송 방식도 추가하여 실제 지연시간·FPS·CPU 사용률을 비교할 수 있습니다.
