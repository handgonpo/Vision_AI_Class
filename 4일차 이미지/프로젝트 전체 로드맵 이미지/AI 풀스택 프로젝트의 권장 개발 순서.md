제일 먼저 해야할 일은 

① 무엇을 검사할 것인지 → ② 어떤 데이터가 필요한지 → ③ AI가 어떤 결과를 반환할 것인지 → ④ 무엇을 DB에 저장할 것인지를 순서대로 결정하는 것입니다.

### 1. STEP 1 — 검사 대상과 판정 기준을 먼저 정의합니다

프로젝트 예시: 컨베이어벨트 위 식품의 이물질 검출 시스템

카메라가 컨베이어 위의 식품을 촬영하고, YOLO가 이물질을 검출하며, OpenCV가 검사 영역과 
영상 품질을 확인한다고 가정하겠습니다.

|먼저 결정할 항목|정의 예시|
|---|---|
|검사 대상|컨베이어 위 식품|
|검사 단위|검사 영역을 통과하는 제품 1개|
|AI 모델|YOLO 객체검출|
|검출 클래스|플라스틱, 돌, 금속, 나뭇가지, 나뭇잎|
|OpenCV 역할|ROI 설정, 영상 품질 확인|
|판정 결과|OK / NG / 확인 필요|
|최종 서비스|실시간 영상, 불량 알림, 검사 이력·통계|

여기서 검사 단위를 먼저 정의하는 것이 중요합니다.

예를 들어 동일한 제품이 카메라에 30프레임 동안 보이더라도 검사 횟수를 30건으로 계산하면 안 됩니다. 제품이 검사 영역에 들어와 나갈 때까지 하나의 검사 ID로 관리하는 방식이 필요합니다.

연속적으로 식품이 흘러 제품 구분이 어려운 환경에서는 검사 구간이나 시간 창을 기준으로 별도 설계할 수 있습니다.

### 2. STEP 2 — AI 학습용 데이터 구조를 정의합니다

YOLO를 직접 학습하려면 먼저 이미지와 정답 라벨이 있어야 합니다.

학습 데이터 폴더 예시

```
dataset/  
├── images/  
│     ├── train/  
│     ├── val/  
│     └── test/  
├── labels/  
│     ├── train/  
│     ├── val/  
│     └── test/  
└── data.yaml
```

학습용 데이터는 다음과 같이 구분합니다.

|데이터|파일 형태|용도|
|---|---|---|
|촬영 이미지|JPG / PNG|YOLO 모델 입력|
|정답 라벨|YOLO TXT|이물 위치와 클래스|
|클래스 정의|YAML|검출 클래스 목록|
|데이터 분할|폴더|Train / Val / Test|

예를 들어 `image001.jpg`에 돌이 검출되어야 한다면 `image001.txt`에 정답 BBox 좌표를 기록합니다.

```
1 0.52 0.41 0.10 0.08
```

이 값은 예시 클래스 매핑에서 `1 = 돌`이고, 뒤의 네 값은 이미지 전체 크기를 기준으로 정규화한 BBox 중심 좌표와 너비·높이입니다.

중요: 이 단계에서는 JSON이 반드시 필요하지 않습니다. YOLO 학습용 라벨은 TXT 형식을 사용할 수 있고, JSON은 이후 서비스의 분석 결과 전달용으로 따로 설계할 수 있습니다.

### 3. STEP 3 — AI 모델의 입력과 출력을 정의합니다

모델이 데이터를 어떻게 받아 처리하는지부터 확인합니다.

![[Pasted image 20261028083755.png]]

여기서 영상 프레임은 보통 OpenCV의 이미지 배열 형태로 처리됩니다. JSON이 입력되는 것이 아니라 AI가 프레임을 분석한 결과를 JSON으로 변환하는 것입니다.

그리고 YOLO는 이물이 있는지를 검출하고 OpenCV는 ROI와 영상 상태 확인을 담당하도록 역할을 구분합니다.

### 4. STEP 4 — 검사 결과 JSON을 정의합니다

이제 AI 분석 결과를 웹 서비스에 어떤 형식으로 전달할지 결정합니다.

예를 들어 다음과 같은 JSON을 설계할 수 있습니다.

```json
{
  "inspection_id": "INS-0001",
  "camera_id": "CAM-01",
  "timestamp": "2026-10-28T10:30:00+09:00",
  "result": "NG",
  "detections": [
    {
      "class_id": 1,
      "class_name": "stone",
      "confidence": 0.95,
      "bbox_xyxy_px": [120, 80, 210, 165]
    }
  ],
  "image_width": 640,
  "image_height": 640,
  "fps": 25.5
}
```

이 데이터의 의미는 다음과 같습니다.

|JSON 필드|의미|화면 표시·활용|
|---|---|---|
|`inspection_id`|검사 고유번호|검사 이력 조회|
|`camera_id`|촬영 카메라|카메라 구분|
|`timestamp`|검사 시각|검사 이력|
|`result`|OK / NG / 확인 필요|판정 표시|
|`class_name`|검출된 이물 종류|불량 종류|
|`confidence`|해당 검출의 신뢰도 점수|검출 결과|
|`bbox_xyxy_px`|640×640 처리 영상의 BBox 좌표|사각형 표시|
|`fps`|처리 속도|성능 모니터링|

이 JSON은 예시 데이터 구조이며, 검사 판정은 YOLO의 신뢰도뿐 아니라 ROI, 영상 품질, 판정 규칙 등을 함께 고려해야 합니다. 특히 이물이 검출되지 않았다는 이유만으로 무조건 정상이라고 판정해서는 안 됩니다.

### 5. STEP 5 — JSON을 바탕으로 ERD를 설계합니다

이제 어떤 정보를 DB에 남길지 결정합니다.

JSON에 있는 모든 데이터를 DB에 저장할 필요는 없습니다.

예를 들어 초당 25프레임씩 AI가 분석하더라도 프레임별 추론 결과를 모두 저장하는 대신, 제품 1개의 최종 검사 결과를 저장할 수 있습니다.

최소한의 데이터베이스 구조는 다음과 같습니다.

```
inspections — 검사 이력

inspection_id PK  
camera_id  
inspected_at  
result (OK/NG/CHECK)  
image_path  
model_version
			   
			   ↓

           1 : N 관계

			   ↓ 
			   
detections — 검출 상세

detection_id PK  
inspection_id FK  
class_id  
confidence  
bbox_x1, bbox_y1  
bbox_x2, bbox_y2
```

하나의 검사에서 이물질이 3개 발견되었다면 `inspections`에는 검사 결과 1건을 저장하고 `detections`에는 이물 검출 결과 3건을 저장하는 구조입니다.

클래스 정의, 카메라, 모델 버전 정보를 별도 테이블로 분리하는 것은 프로젝트 규모에 따라 확장하면 됩니다.
