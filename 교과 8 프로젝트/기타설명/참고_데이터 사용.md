## 교과 7~8 데이터 사용 원칙

### 1. 교과 7에서는 제공된 900장을 모두 검수합니다

기업에서 제공한 원본 데이터 구조는 변경하지 않습니다.

```text
RAW/
├── 이물검출_학습데이터1/
│   ├── images/train/
│   └── labels/train/
│
└── 이물검출_학습데이터2/
    ├── images/train/
    ├── images/validation/
    ├── labels/train/
    └── labels/validation/
```

원본 `RAW` 데이터는 수정하지 않습니다.

실제 라벨 검수·수정 작업은 `WORK`에서 진행하며,  
원래 데이터가 어디에서 왔는지 알 수 있도록 같은 폴더 구조를 유지합니다.

```
WORK/
├── 이물검출_학습데이터1/
│   ├── images/train/
│   └── labels/train/
│
└── 이물검출_학습데이터2/
    ├── images/train/
    ├── images/validation/
    ├── labels/train/
    └── labels/validation/
```

교과 7에서는 다음 세 구간을 모두 검수합니다.

```
Dataset 1 / train
        ↓
전수 검수

Dataset 2 / train
        ↓
전수 검수

Dataset 2 / validation
        ↓
전수 검수

총 900장 검수
```

> **중요**
> 
> 900장을 검수한다는 것은 900장을 하나의 폴더로 합친다는 뜻이 아닙니다.  
> 원래 Dataset과 Split 정보를 그대로 유지한 상태에서 전체를 확인합니다.

---

### 2. 교과 8에서는 900장을 모두 모델 개발에 사용하지 않습니다

교과 7에서 검수가 끝난 900장 중 일부는  
교과 8의 학습·성능개선 과정에서 사용하지 않고 별도로 보존합니다.

이 데이터는 이후 교과 14에서  
교과 8 Final Model의 연결 성능을 확인하기 위한 **Bridge Holdout**으로 사용할 수 있습니다.

```
교과 7 FINAL
900장
        ↓
┌─────────────────────────────┐
│                             │
교과 8 개발용              Bridge Holdout
약 750장                   약 150장
│                             │
│                             └→ 교과 8 학습·튜닝에 사용하지 않음
│
├── Train
├── Validation
└── Frozen Test
```

예를 들어 150장을 Bridge Holdout으로 확정한다면  
나머지 750장을 다음과 같이 구성할 수 있습니다.

```
전체 900장

Train
약 600장
→ 모델이 실제로 학습하는 데이터
→ Baseline / Improved 학습에 반복 사용

Validation
약 75장
→ 학습 후 성능을 비교하는 데이터
→ 파인튜닝·개선 실험 때 여러 번 사용 가능

Frozen Test
약 75장
→ Final Model을 확정한 뒤
   최종 성능 확인에 사용
→ 원칙적으로 마지막에 한 번 사용

Bridge Holdout
약 150장
→ 교과 8에서는 학습·튜닝·모델 선택에 사용하지 않음
→ 교과 14 연결용으로 보존
```

단, 위 숫자는 교육 운영을 위한 예시입니다.

실제 분할은 교과 8의 Dataset Audit에서

- Dataset 1 / Dataset 2 출처
- 기존 train / validation
- 촬영 시점
- 유사 이미지
- Class 분포
- scene_type 분포

를 확인한 뒤 최종 확정합니다.

특히 같은 촬영 조건에서 연속으로 생성된 유사 이미지가  
Train과 Validation·Test·Bridge Holdout에 동시에 들어가지 않도록 주의합니다.

---

### 3. 각 데이터의 역할을 구분합니다

```
Train
→ 모델이 실제로 학습하는 데이터

Validation
→ 학습조건과 개선 결과를 비교하는 데이터

Frozen Test
→ Final Model을 정한 뒤 교과 8의 최종 성능을 확인하는 데이터

Bridge Holdout
→ 교과 8의 학습·튜닝에는 사용하지 않고
   교과 14로 연결할 때 모델의 일반화 성능을 확인하기 위해 보존하는 데이터
```

> **핵심**
> 
> 교과 7에서는 900장을 모두 검수합니다.
> 
> 하지만 교과 8에서는 900장을 모두 학습에 사용하지 않습니다.  
> 일부 데이터는 모델 개발 과정에서 제외하여 이후 프로젝트 연결용으로 보존합니다.

# 교과 7과 교과 8의 데이터 역할을 아주 쉽게 이해합니다

## 1. 교과 7에서는 데이터를 다시 Train / Validation / Test로 나누지 않습니다

교과 7의 목표는 **900장의 라벨을 제대로 검수하여 FINAL Dataset을 만드는 것**입니다.

즉 교과 7에서는 다음 작업에 집중합니다.

```
제공받은 이미지 + YOLO TXT
        ↓
900장 전체 라벨 검수
        ↓
잘못된 BBox 수정
        ↓
잘못된 Class 수정
        ↓
누락된 객체 추가
        ↓
QA
        ↓
FINAL Dataset 완성
```

따라서 교과 7에서는 새롭게

```
Train
Validation
Test
```

를 만들 필요가 없습니다.

> **새로운 Dataset Split은 교과 8에서 진행합니다.**

---

## 2. 교과 7의 FINAL Dataset은 무엇인가요?

쉽게 말하면 **검수가 끝난 이미지와 TXT 전체**입니다.

예를 들어:

```
FINAL Dataset

이미지 900장
+
YOLO TXT 900개
```

입니다.

다만 한 폴더 안에 JPG와 TXT를 모두 섞어 두는 것보다는 다음처럼 구분하는 것이 좋습니다.

```
data/
└── final/
    ├── images/
    │   ├── image001.jpg
    │   ├── image002.jpg
    │   └── ...
    │
    └── labels/
        ├── image001.txt
        ├── image002.txt
        └── ...
```

파일 이름만 서로 같으면 됩니다.

```
image001.jpg
image001.txt

image002.jpg
image002.txt
```

즉:

> **교과 7 FINAL = 검수가 완료된 전체 이미지 + 전체 YOLO TXT**

입니다.

## 3. 그러면 교과 8에서는 무엇을 하나요?

교과 8에서는 교과 7에서 받은 FINAL Dataset을 **코드로 분석한 뒤 Train / Validation / Test 등으로 나눕니다.**

전체 흐름은 이것만 이해하면 됩니다.

```
교과 7 FINAL Dataset

        ↓

        ↓
어떤 Class가 얼마나 있는지 자동 계산 (코드로작업)
        ↓
비슷한 이미지가 있는지 확인 (코드로 후보 찾기 + 사람이 최종 확인)
        ↓
Train / Validation / Test / Bridge
자동·반자동 Split  (코드로 작업이후 사람이 검수)
        ↓
분포 확인 (코드가 통계표 생성 → 사람이 판단)
        ↓
문제가 없으면 Split 확정
        ↓
YOLO 학습
```

```
교과 7 FINAL Dataset
이미지 900장 + TXT 900개
        ↓
[1] 교과 8 Dataset Audit
        ↓
Python으로 전체 데이터 읽기
        ↓
이미지/TXT Pair(짝이 맞는지) 확인
파일 수 확인
source_dataset 확인 (이 이미지가 원래 Dataset 1 / Dataset 2 중 어디서 왔는지)

        ↓
[3] 유사 이미지 / 촬영 Group 확인
        ↓

        ↓
사람이 이상한 Group만 확인
        ↓
[4] Split 후보 생성
        ↓
Class 분포
   +
촬영 Group
   +
source_dataset
   +
scene_type
을 고려하여

Train
Validation
Frozen Test
Bridge Holdout

자동·반자동 분할
        ↓
[5] Split Audit
        ↓
코드가 표와 통계 생성
        ↓
사람이 결과 확인
        ↓

        ↓
문제 없으면 Split 확정
        ↓

        ↓

        ↓

```

## 4. 사람이 900장을 다시 보면서 나누나요?

**아닙니다.**

예를 들어 사람이 다음처럼 하면 안 됩니다.

```
image001 → Train
image002 → Train
image003 → Validation
image004 → Test
...
```

900장을 하나씩 보면서 직접 정할 필요가 없습니다.

Python 코드가 YOLO TXT를 읽으면 각 이미지에 어떤 Class가 들어 있는지 자동으로 알 수 있습니다.

예를 들어 `image001.txt`가 다음과 같다고 하겠습니다.

```
3 0.34 0.21 0.05 0.07
3 0.62 0.44 0.04 0.06
6 0.42 0.73 0.09 0.11
```

코드는 자동으로 다음과 같이 분석합니다.

```
image001.jpg

Class 3 → 2개
Class 6 → 1개

총 객체 → 3개
포함 Class → [3, 6]
```

사람이 따로 기록할 필요가 없습니다.

---

## 5. 그러면 코드는 어떻게 데이터를 나누나요?

먼저 전체 데이터를 분석합니다.

예를 들어:

```
전체 900장

Class 0 → 120장
Class 1 → 80장
Class 2 → 150장
Class 3 → 250장
Class 5 → 40장
Class 6 → 300장
```

이라고 나오면 코드가 이 분포를 참고합니다.

그 다음:

```
Train
Validation
Frozen Test
Bridge Holdout
```

각각에 Class가 너무 한쪽으로 몰리지 않도록 나눕니다.

예를 들어 잘못 나누면:

```
Validation

Class 3 → 30장
Class 5 → 0장
```

이 될 수 있습니다.

그러면 Class 5의 성능은 Validation에서 평가할 수 없습니다.

그래서 코드는 가능한 한:

```
Train       → 모든 Class 포함
Validation  → 모든 주요 Class 포함
Test        → 모든 주요 Class 포함
Bridge      → 특정 Class가 한쪽으로 몰리지 않음
```

이 되도록 나눕니다.

---

## 6. 하지만 Class 비율만 보면 안 됩니다

이 부분이 중요합니다.

예를 들어 연속 촬영한 이미지가 있습니다.

```
image001
image002
image003
image004
```

네 장이 사실상 거의 같은 사진이라고 하겠습니다.

이것을 랜덤하게 나누면:

```
image001 → Train
image002 → Train
image003 → Validation
image004 → Test
```

가 될 수 있습니다.

그러면 Validation과 Test에 **Train에서 본 것과 거의 똑같은 사진**이 들어갑니다.

이것이 Data Leakage입니다.

그래서 비슷한 이미지는 하나의 그룹으로 묶습니다.

```
촬영 Group A

image001
image002
image003
image004
```

그리고 Group 전체를 한쪽에 넣습니다.

```
Group A → Train
```

다른 Group은:

```
Group B → Validation
Group C → Test
```

처럼 처리합니다.

즉 교과 8의 Split에서 가장 중요한 것은:

```
Class 분포
+
비슷한 이미지 Group
```

두 가지를 같이 보는 것입니다.

---

## 7. 그렇다면 파일번호 순서대로 나누면 되나요?

**아닙니다.**

예를 들어 단순히:

```
1~600번   → Train
601~675번 → Validation
676~750번 → Test
751~900번 → Bridge
```

처럼 나누는 것은 좋지 않습니다.

왜냐하면 파일번호가 촬영순서를 의미한다면:

```
1~300번은 벌레가 많고
301~500번은 파·고추가 많고
501~700번은 갈변이 많다
```

같은 문제가 있을 수도 있기 때문입니다.

따라서 **파일번호 자체로 나누는 것이 아니라 파일 내용을 코드가 분석해서 나눕니다.**

```
① 읽기

        ↓

② 조사하기
각 이미지에 어떤 Class가 있는지 계산

```

## 9. 교과 7에서는 무엇만 남겨주면 되나요?

교과 7에서는 Split을 새로 만들 필요는 없지만 **데이터의 출처 정보는 버리지 않는 것이 중요합니다.**

`dataset_manifest.csv`에는 다음 정도를 남겨둡니다.

```
file_name
source_dataset
original_split
scene_type
worker
status
qa_status
review_reason
```

가능하다면:

```
capture_group
```

도 남겨두면 좋습니다.

예:

```
image001,dataset1,train,session_A,...
image002,dataset1,train,session_A,...
image003,dataset1,train,session_A,...

image004,dataset2,validation,session_B,...
```

여기서 `session_A`는

> 같은 시간·장소·촬영조건에서 만들어진 비슷한 이미지 그룹

정도로 이해하면 됩니다.

하지만 Class별 객체 수 같은 것은 학생이 일일이 입력하지 않습니다.

```
Class 0 몇 개
Class 1 몇 개
Class 2 몇 개
...
```

이 정보는 **교과 8에서 Python이 TXT를 읽어서 자동 계산**합니다.

## 최종적으로 이것만 기억하면 됩니다

```
교과 7

900장 모두 검수
        ↓
FINAL 이미지 + YOLO TXT 완성
        ↓
출처 / 기존 Split / 작업상태 기록
        ↓
교과 8로 전달


교과 8

FINAL Dataset 받기
        ↓
코드로 TXT 900개 자동 분석
        ↓
Class 분포 확인
        ↓
비슷한 이미지 Group 확인
        ↓
코드로 Split 후보 생성
        ↓
사람은 결과표만 확인
        ↓
Train / Validation / Test / Bridge 확정
        ↓
YOLO 학습
```

따라서 질문하신 내용을 한 문장으로 정리하면:

> 교과 7에서는 새로운 Train/Validation/Test 분할까지 신경 쓰지 않아도 됩니다. 900장의 정확한 FINAL 이미지와 YOLO TXT를 완성하고 원본 출처 정보를 보존하면 됩니다. 교과 8에서 Python 코드가 YOLO TXT와 데이터 정보를 분석하여 Class 편향과 유사 이미지 Leakage를 고려해 Train/Validation/Test/Bridge를 자동·반자동으로 나눕니다.

단, “Class별로 먼저 폴더로 나눈 다음 파일번호 순서대로 자른다”가 아니라, Class 분포를 분석해서 전체 이미지들을 적절한 Split에 배정한다고 이해하시면 정확합니다.
