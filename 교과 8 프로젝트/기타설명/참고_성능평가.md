### Recall — 실제 이물질을 얼마나 놓치지 않았나요?

실제로 존재하는 이물질 중에서 모델이 찾아낸 비율입니다.

```
Recall이 높다
→ 실제 이물질을 놓치는 경우(FN)가 적다.
```

예를 들어 실제 이물질이 10개 있는데 모델이 9개를 찾았다면  
1개는 놓친 것입니다.

즉,

> **"실제 이물질을 AI가 얼마나 놓치지 않고 찾았는가?"**

를 보는 지표입니다.

제조 이물검출에서는 실제 이물을 놓치는 `FN`이 중요하기 때문에  
**Recall을 특히 주의해서 확인합니다.**

---

### FP와 FN은 무엇인가요?

```
FP (False Positive)
→ 실제로 이물이 없는데
   AI가 이물이 있다고 잘못 검출

FN (False Negative)
→ 실제로 이물이 있는데
   AI가 찾지 못하고 놓침
```

조각김치 검사에서는 다음처럼 생각할 수 있습니다.

```
정상 김치
→ "플라스틱이 있습니다."
→ FP

실제 플라스틱 존재
→ AI가 검출하지 못함
→ FN
```

---

### IoU — BBox를 얼마나 정확한 위치에 그렸나요?

객체를 찾았더라도 BBox 위치가 크게 틀리면  
정확하게 검출했다고 보기 어렵습니다.

`IoU(Intersection over Union)`는

**정답 BBox와 AI가 예측한 BBox가 얼마나 겹치는지**

를 나타냅니다.

```
IoU가 높음
→ 정답 BBox와 예측 BBox가 많이 겹침

IoU가 낮음
→ 객체는 찾았지만 BBox 위치가 부정확함
```

---

### mAP50 — 객체검출 모델의 전체 성능을 봅니다

`mAP`는 여러 Class에 대한 객체검출 성능을 종합해서 보는 대표 지표입니다.

`mAP50`에서 `50`은

```
IoU ≥ 0.50
```

을 기준으로 올바른 Detection인지 평가한다는 의미입니다.

예:

```
mAP50 = 0.86
→ mAP50 기준 성능이 0.86

또는
→ 86%로 표현
```

단, 이것을 단순히  
**"모델이 86% 맞았다"**라고 이해하면 안 됩니다.

Classification의 Accuracy와는 계산 방식이 다른  
**객체검출용 종합 성능지표**입니다.

---

### mAP50-95 — BBox까지 더 엄격하게 평가합니다

`mAP50-95`는 IoU 기준을 하나만 사용하는 것이 아니라

```
0.50
0.55
0.60
...
0.95
```

처럼 점점 엄격하게 바꾸어 평가한 뒤 평균을 냅니다.

따라서 일반적으로

```
mAP50
>
mAP50-95
```

가 됩니다.

쉽게 말하면

```
mAP50
→ "대체로 제대로 찾았는가?"

mAP50-95
→ "찾은 위치까지 얼마나 정확한가?"
```

라고 이해하면 됩니다.

---

### Class별 성능도 확인합니다

전체 mAP가 높아도 모든 이물질을 똑같이 잘 찾는 것은 아닙니다.

예를 들어

```
나뭇가지류      → 잘 찾음
플라스틱류      → 잘 찾음
작은 나뭇잎류   → 자주 놓침
```

일 수 있습니다.

따라서 전체 Precision · Recall · mAP뿐 아니라  
**Class별 Precision · Recall · mAP도 함께 확인합니다.**

---

## 네 가지 지표를 한 번에 기억합니다

```
Precision
→ 찾았다고 한 것이 얼마나 정확한가?
→ FP와 관련

Recall
→ 실제 이물을 얼마나 놓치지 않았는가?
→ FN과 관련

mAP50
→ 객체검출 모델의 전반적인 검출 성능은 어떤가?

mAP50-95
→ 더 엄격한 BBox 기준에서도 잘 검출하는가?
```

> **중요**
> 
> 좋은 모델은 mAP 숫자 하나만 높은 모델이 아닙니다.
> 
> 교과 8에서는  
> **Precision + Recall + mAP + Class별 성능 + 실제 FP/FN 이미지**를 함께 보고 모델의 성능을 판단합니다.
