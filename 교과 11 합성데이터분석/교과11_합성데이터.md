## 1. 교과 11에서는 무엇을 배우나요?

실제 AI 프로젝트에서는 데이터의 양이 부족한 경우도 있지만, 더 자주 문제가 되는 것은 **필요한 조건의 데이터가 부족한 상황**입니다.

예를 들어 조명 변화가 부족하거나, 특정 위치의 객체가 적거나, 불량 사례가 충분하지 않거나, 사람의 위치·크기·동작 속도 변화가 부족할 수 있습니다.

교과 11에서는 이런 데이터 부족 문제를 발견했을 때 단순히 데이터를 많이 만드는 것이 아니라, 문제에 맞는 보강 방법을 선택하고 품질을 확인한 뒤 실제 학습에 도움이 되는지 검증하는 과정을 배웁니다.

AI 학습데이터에 필요한 조건이 부족할 때, 데이터를 어떻게 보완하고 그 보완이 실제로 유효했는지 검증하는 과정

![[Pasted image 20261007122557.png]]

```text
모델을 학습했다
        ↓
성능이 생각보다 좋지 않다
        ↓
왜 틀렸는지 실패 사례를 본다
        ↓
특정 조건의 데이터가 부족하다는 것을 발견한다

예)
어두운 이미지에서 자주 틀림
회전된 물체에서 자주 틀림
작은 물체에서 자주 틀림
특정 불량 데이터가 너무 적음
        ↓
부족한 조건의 데이터를 보완한다
        ↓
Augmentation / Synthetic Data
        ↓
생성 데이터가 정상인지 QA
        ↓
Train에 추가
        ↓
같은 Validation / Test에서 다시 평가
        ↓
실제로 성능이 좋아졌는지 확인
```

## 2. Real Data · Augmentation · Synthetic Data를 구분합니다

| 구분 | 의미 | 교과 11 예시 |
|---|---|---|
| Real Data | 실제로 수집된 원본 데이터 | Apple 이미지, KTH Action Video, YCB-V Real Reference |
| Augmentation | 기존 데이터를 현실적인 범위에서 변형 | Brightness, Rotation, Jitter, Time Warp |
| Synthetic Data | 생성모델·합성·3D 환경 등으로 새로운 샘플 생성 | GAN, Diffusion, Cut-Paste, 3D Rendering |
- **Real Data**는 실제로 촬영하거나 수집한 원본 데이터입니다.  

- **Augmentation**은 새로운 데이터를 다시 촬영하지 않고, 이미 가지고 있는 Real Data를 회전·밝기 변화·Noise·Jitter 같은 방법으로 변형하여 학습에 사용할 데이터의 다양성을 늘리는 방법입니다.  
  
- **Synthetic Data**는 기존 데이터를 단순히 변형하는 수준을 넘어, GAN·Diffusion·Cut-Paste·3D Rendering 같은 방법으로 새로운 학습 샘플을 만들어내는 방법입니다.

따라서 이 부분은 교과 11에서 데이터를 보완하는 방법을 이해하기 위해 먼저 구분해야 하는 세 가지 데이터 개념입니다.

핵심은 **어떤 데이터가 부족한지 먼저 판단하는 것**입니다. 만든 데이터가 많아졌다는 이유만으로 바로 학습에 사용하지 않고, Label 의미와 현실성을 확인해야 합니다.

## 3. 교과 11의 40시간 전체 흐름

교과 11은 하루 8시간씩 5일, 총 40시간으로 진행합니다.

![[Pasted image 20261007123441.png]]

5일 동안 데이터 형태는 달라지지만 흐름은 단계적으로 확장됩니다.

| 일차 | 데이터 형태 | 핵심 학습 |
|---|---|---|
| 1일차 | Image | 일반 Augmentation과 VAE |
| 2일차 | Image | DCGAN·WGAN-GP·Pretrained Diffusion |
| 3일차 | Detection | Cut-Paste와 YOLO BBox |
| 4일차 | 3D / Segmentation | BlenderProc·YCB-V·Ground Truth 생성 |
| 5일차 | Keypoint Sequence | Sequence Augmentation과 성능검증 |

```text
1일차
기존 이미지 변형과 VAE
        ↓
2일차
새로운 이미지 생성 방식 비교
        ↓
3일차
이미지와 Detection Label 함께 생성
        ↓
4일차
3D 환경에서 RGB·BBox·Mask·Depth 생성
        ↓
5일차
동작 Sequence 보강 후 실제 성능 비교
```

## 4. 5일 동안 공통으로 지키는 데이터 원칙

### ① 평가 데이터를 보호합니다

Augmentation과 Synthetic Data는 학습 데이터를 보완하기 위한 것입니다. 
원칙적으로 Train을 보강하고, Validation과 Test는 비교 기준으로 유지합니다.

조건을 선택해야 하는 실험에서는 **Validation으로 조건을 판단하고, 
Test는 최종 조건을 확정한 뒤 마지막 평가에 사용**합니다.

### ② 생성됐다고 바로 학습에 사용하지 않습니다

```text
Synthetic / Augmented Data
        ↓
Automatic QA
        ↓
Human QA
        ↓
Approved Data
```

Automatic QA는 파일·좌표·Label 구조를 확인하고, Human QA는 사람이 보았을 때 의미와 현실성이 유지되는지 확인합니다.

### ③ 생성 이력을 남깁니다

Source, Method, Parameter, Seed, QA 결과 등을 Metadata로 기록하여 
**어디에서 어떻게 만들어진 데이터인지 다시 추적**할 수 있어야 합니다.

### ④ 실제 도움이 되었는지 확인합니다

Real Data와 Synthetic Data 사이에는 **Domain Gap**이 생길 수 있습니다.  
여기서 Domain Gap이란 **실제 데이터와 합성데이터의 모양·조명·배경·질감·노이즈 같은 특성이 
서로 달라 생기는 차이**를 말합니다.

따라서 합성 이미지가 보기에는 자연스럽고 좋아 보여도, 
실제 데이터의 특징과 너무 다르면 모델 학습에 도움이 되지 않을 수 있습니다.  
그래서 같은 Validation / Test 기준에서 **Baseline 모델과 보강 데이터를 추가한 모델의 성능을 
비교하여 실제로 도움이 되었는지 확인합니다.**

## 5. 1일차 — Image Augmentation · VAE

1일차에서는 **이미지 데이터가 부족하거나 변화가 충분하지 않을 때, 데이터를 어떻게 보완할 수 있는지** 가장 기본적인 방법부터 배웁니다.

본 실습에서는 **Fruits-360의 `Apple Red 1`** 이미지를 사용합니다. 
먼저 같은 사과 이미지에 밝기, 회전, Blur, Noise 같은 변화를 적용해 **기존 이미지를 현실적인 
범위에서 다양하게 만드는 Augmentation**을 실습합니다. 

즉, 새로운 사진을 다시 촬영하지 않고도 학습용 이미지의 조건을 다양하게 만드는 방법을 경험합니다. 

그다음에는 **VAE**를 이용합니다. Augmentation이 사람이 정한 방법으로 이미지를 직접 변형하는 방식이라면, VAE는 여러 이미지를 보면서 이미지의 특징을 학습하고 `Encoder → Latent Space → Decoder` 과정을 통해 이미지를 다시 복원하거나 새로운 이미지를 만들어 보는 방식입니다. 
1일차에서는 이 두 방법이 어떻게 다른지 직접 결과를 비교하며 이해합니다. 

전체 흐름은 다음처럼 이해하면 됩니다.

![[Pasted image 20261007124834.png]]

이날 중요한 것은 단순히 이미지를 많이 만드는 것이 아닙니다. 
**Train / Validation / Test를 올바르게 나누고, 생성한 데이터가 정상적인지 QA로 확인하며, 
어떤 원본과 조건에서 만들어졌는지 Metadata로 기록하고, 평가용 데이터가 학습에 섞이는 Leakage를 막는 기본 데이터 관리 방법**을 함께 익힙니다. 
이 원칙은 이후 2~5일차 실습에서도 계속 사용됩니다. 

Mini Challenge에서는 **`Banana 1`**을 사용하여 같은 흐름을 스스로 반복합니다. 
사과에서 따라 했던 코드를 그대로 복사하는 것이 아니라, 바나나에서도 어떤 Augmentation이 적절한지 판단하고 VAE 결과를 비교해 보면서 **다른 데이터에도 같은 원리를 적용할 수 있는지 확인**합니다.

> **1일차의 핵심**  
> 기존 이미지를 직접 변형하는 **Augmentation**과 이미지의 특징을 학습하는 **VAE**의 차이를 이해하고, 만든 데이터를 안전하게 관리·검수하는 기본 방법을 배우는 수업입니다.

## 6. 2일차 — DCGAN · WGAN-GP · Pretrained Diffusion

2일차에서는 1일차에서 확정한 **Apple Train**을 그대로 사용하여 DCGAN과 WGAN-GP가 이미지를 생성하는 방식을 비교합니다.

Diffusion은 Apple Train으로 다시 학습하지 않고 **준비된 Pretrained Model에 Prompt와 Seed를 적용하여 새로운 이미지를 생성**합니다. Real과 Synthetic을 비교하면서 Domain Gap과 생성 품질을 확인합니다.

Mini Challenge에서는 Banana Train에 같은 실험 구조를 적용하여 생성 방식의 차이를 해석합니다.

### 🔗 [[2일차_GAN_WGANGP_Diffusion]]

## 7. 3일차 — Detection · Cut-Paste · YOLO BBox

3일차에서는 **Background JPG와 RGBA Object PNG**를 합성하여 Detection 학습용 데이터를 만듭니다.

Position·Scale·Rotation이 적용된 최종 Object를 기준으로 Pixel BBox를 계산하고, 이를 YOLO 형식의 Normalized Label로 변환합니다. 생성된 BBox를 다시 이미지 위에 그려 Automatic QA와 Human QA로 확인하고 Metadata에 생성 조건을 기록합니다.

1~2일차가 주로 이미지를 다루었다면, 3일차부터는 **이미지와 정답 Label을 함께 생성하는 단계**로 확장됩니다.

### 🔗 [[3일차_Detection_CutPaste_YOLOBBox]]

## 8. 4일차 — 3D Rendering · Segmentation · BlenderProc · YCB-V

4일차에서는 3일차의 2D Cut-Paste에서 한 단계 더 나아가 **3D Object·Camera·Light를 직접 제어하는 합성데이터**를 다룹니다.

BlenderProc와 YCB-V를 이용하여 RGB뿐 아니라 COCO BBox, Semantic Mask, Instance Mask, Depth를 함께 생성합니다. Real Reference와 Synthetic Render를 비교하여 Domain Gap을 확인합니다.

Mini Challenge에서는 `power_drill`을 사용하여 **Camera Distance 하나만 변경하는 실험**을 진행하며, Metadata를 통해 다른 조건이 유지되었는지 확인합니다.

## 9. 5일차 — KTH Keypoint Sequence Augmentation · 성능검증

5일차에서는 데이터 형태가 이미지에서 **사람의 움직임을 나타내는 시계열 데이터**로 바뀝니다.

KTH Action Video를 YOLO Pose로 처리하여 COCO17 Keypoint Sequence를 만들고, Train Sequence에 Translation·Scale·Jitter·Time Warp를 적용합니다. 보강 결과는 Automatic QA와 Human QA를 통과한 경우에만 학습 후보로 사용합니다.

마지막에는 Random Forest와 204-D Statistical Feature를 이용하여 Baseline과 Augmented 모델을 비교합니다. Mini Challenge의 `Jitter 0.005 vs 0.015`는 **Validation으로 조건을 선택하고 Final Jitter를 Freeze한 뒤 선택된 조건만 Test에서 최종 평가**합니다.

5일차에서는 교과 11 전체의 질문이 실제 성능검증으로 마무리됩니다.

## 10. 교과 11에서 배운 방법은 교과 14·15와 어떻게 연결되나요?

교과 11에서 만든 연습용 데이터를 그대로 다음 프로젝트에 넘기는 것이 목적은 아닙니다.

교과 11에서는 **데이터 부족 문제를 발견하고, 적절한 보강 방법을 선택하고, QA하고, 실제 효과를 검증하는 방법**을 익힙니다.

```text
교과 11
데이터 부족 발견
→ 보강 방법 선택
→ QA
→ 효과 검증
        ↓
교과 14
제조 Vision AI에서 필요한 방법만 선택 적용
        ↓
교과 15
Action AI에서 필요한 Keypoint / Sequence 보강 선택 적용
```

교과 14에서는 조명·객체 위치·Detection 조건 등이 부족할 때 일반 Augmentation, Cut-Paste, 3D Rendering 등을 검토할 수 있습니다.

교과 15에서는 사람의 위치·크기·Pose 오차·동작 속도 조건이 부족할 때 Keypoint Sequence Augmentation을 검토할 수 있습니다.

핵심은 **필요하지 않은 합성기법을 억지로 사용하는 것이 아니라, 실제 데이터 문제에 맞는 방법만 선택하는 것**입니다.

## 11. 추가 합성데이터 도구

공식 커리큘럼에는 NVIDIA Cosmos Predict와 기업 Synthetic Data Solution 같은 도구도 포함될 수 있습니다.

다만 1~5일차의 필수 실습은 PyTorch·Diffusers·Cut-Paste·BlenderProc·YOLO Pose를 중심으로 진행합니다. 제공 환경에 따라 추가 합성데이터 도구를 시연할 수 있지만, 별도의 대규모 실습을 필수 과정처럼 확장하지 않습니다.

## 12. 교과 11을 마치면 무엇을 판단할 수 있어야 하나요?

교과 11의 목표는 생성모델의 이름이나 코드를 많이 외우는 것이 아닙니다.

다음 질문에 스스로 답할 수 있어야 합니다.

- 현재 데이터에서 무엇이 부족한가?
- 기존 데이터를 변형할 것인가, 새로운 Synthetic Data를 만들 것인가?
- 만든 데이터의 Label과 현실성은 믿을 수 있는가?
- 어떤 Source·Parameter·Seed로 만들었는지 추적할 수 있는가?
- Validation으로 조건을 공정하게 판단했는가?
- Final Test에서 실제로 성능에 도움이 되었는가?
- 성능이 좋아지지 않았다면 어떤 데이터와 조건을 다시 확인해야 하는가?

> **현재 데이터에서 무엇이 부족하며, 어떤 방법으로 보완하고, 만든 데이터를 어떻게 검수하고, 실제로 도움이 되었는지를 어떻게 확인할 것인가?**

이 질문에 답할 수 있다면 교과 11의 핵심 흐름을 이해한 것입니다.
