## 오늘의 목표

1일차에서는 이미지·저장 영상·스마트폰 실시간 영상이 결국 Image 또는 Frame으로 처리된다는 것을 확인하고, 검사할 위치인 ROI를 직접 정했습니다. 또한 같은 ROI도 제품 위치·카메라 위치·조명 조건에 따라 실패할 수 있다는 것을 확인했습니다.

2일차에서는 그 다음 질문을 다룹니다.

> 검사할 위치는 정했는데, 그 ROI가 컴퓨터가 검사하기 좋은 영상 상태인가?

2일차는 Image Enhancement를 중심으로 저대비·어두운·Noise 영상의 품질을 개선하고, 이미지마다 적절한 전처리 조합을 스스로 선택합니다.

오늘 수업이 끝나면 다음을 할 수 있어야 합니다.

```text
- 1일차에 만든 프로젝트와 파일 구조를 이어서 사용할 수 있다.
- OpenCV의 BGR, Gray, HSV가 각각 어떤 정보를 표현하는지 설명할 수 있다.
- Brightness와 Contrast가 픽셀값에 어떤 영향을 주는지 설명할 수 있다.
- Gamma Correction을 적용하고 여러 파라미터의 결과를 비교할 수 있다.
- CLAHE를 이용하여 저대비 ROI를 개선할 수 있다.
- Gaussian, Median, Bilateral Filter의 차이를 비교할 수 있다.
- Sharpening의 효과와 한계를 설명할 수 있다.
- Threshold와 Otsu를 이용하여 전처리 전·후의 분리 결과를 비교할 수 있다.
- 문제 이미지에 필요한 전처리를 스스로 선택하고 그 이유를 기록할 수 있다.
- 과도한 전처리가 오히려 결함을 없애거나 Noise를 키울 수 있음을 설명할 수 있다.
- 결과 이미지, 파라미터 표, 분석 문서, Git 기록을 남길 수 있다.
```

# 2. 1일차와 2일차는 어떻게 연결되나요?

![[Pasted image 20261020173554.png]]

1일차의 핵심 흐름은 다음이었습니다.

```text
Image / Video Frame / 실시간 Frame
                ↓
               ROI
                ↓
정상 · 불량의 차이를 관찰
                ↓
나중에 측정할 특징을 생각
```

2일차에는 이 ROI가 다음 검사에 적합한 상태인지 확인합니다.

```text
1일차
검사할 위치 결정
       ↓
      ROI

2일차
ROI 영상 품질 확인
       ↓
Image Enhancement
       ↓
Threshold / Otsu로
분리 가능성 확인

3일차
Morphology
       ↓
Contour
       ↓
Area / Count / Position
       ↓
Rule
       ↓
OK / NG
```

따라서 오늘의 전처리는 최종 판정이 아닙니다.

> 오늘은 “영상 개선”이 목적이 아니라, 3일차의 객체 분리와 측정이 더 안정적으로 되도록 입력을 준비하는 것이 목적입니다.

![[Pasted image 20261020171314.png]]

개념적으로는 세그멘테이션처럼 병뚜껑 영역을 분리하는 과정과 비슷합니다. 
그러나 정확히는 딥러닝 기반 Semantic Segmentation이 아니라 
OpenCV의 전처리와 Otsu(오츠) 이진화(Binary Segmentation) 를 사용한 것입니다.

병뚜껑과 배경을 최대한 잘 분리하여, 3일차에 Contour·면적·위치 등을 측정하고 뚜껑의 유무를 OK/NG로 판정할 수 있도록 준비하는 것입니다.

오츠 알고리즘의 역사 이야기

```
1979년 일본의 영상처리·패턴인식 연구자인 오츠 노부유키(大津展之, Nobuyuki Otsu)가 
발표한 알고리즘입니다. 사람이 직접 정하던 이진화 기준값(Threshold)을 이미지의 밝기 분포에 대한 통계적 분석을 통해 자동으로 선택하는 방법으로, 두 그룹 간 분산이 최대가 되는 임계값을 
찾습니다. 연구자의 이름을 따서 오츠의 방법(Otsu's Method) 또는 오츠 이진화라고 부릅니다.
```

2일차는 병뚜껑의 형태를 배경과 잘 구분할 수 있도록 이미지를 전처리하고 이진화하는 과정이며, 3일차는 분리된 영역의 면적·위치·형태를 측정하여 병뚜껑 유무를 판정하는 과정입니다.

# 7. Image Enhancement는 왜 필요한가요?

## 7.1 전처리는 이미지를 예쁘게 만드는 작업이 아닙니다

사진 편집에서는 보기 좋은 이미지를 만드는 것이 목적일 수 있습니다.

머신비전에서는 목적이 다릅니다.

```text
사람이 보기 좋은 이미지
         ≠
컴퓨터가 검사하기 좋은 이미지
```

예를 들어 같은 병뚜껑인데 조명이 바뀌었다고 생각해 봅니다.

```text
정상 조명
병뚜껑 밝기 ≈ 180

어두운 조명
병뚜껑 밝기 ≈ 70
```

3일차에 다음과 같은 기준을 사용한다고 가정합니다.

```text
픽셀값 > 120
→ 객체 후보

픽셀값 <= 120
→ 배경 후보
```

같은 정상 병뚜껑인데도 촬영조건 때문에 객체가 사라질 수 있습니다.

```text
조명 변화
    ↓
픽셀값 변화
    ↓
Binary 결과 변화
    ↓
Contour 결과 변화
    ↓
면적·개수 변화
    ↓
잘못된 OK / NG 가능성
```

따라서 전처리의 목적은 다음과 같습니다.

> ==촬영조건 때문에 발생한 영상 차이를 줄여서 
   뒤의 검사 단계가 더 안정적으로 동작하도록 만드는 것==

---

## 7.2 그렇다고 모든 문제를 소프트웨어로 고치지는 않습니다

머신비전에서 매우 중요한 원칙입니다.

예를 들어 강한 반사로 픽셀이 완전히 흰색 `255`로 포화되었다면 원래 정보가 이미 사라졌을 수 있습니다.

```text
강한 반사
    ↓
픽셀 포화
    ↓
원래 표면 정보 손실
    ↓
후처리만으로 완전 복구 어려움
```

이런 경우 실제 현장에서는 다음을 먼저 검토할 수 있습니다.

```text
조명 각도 변경
카메라 각도 변경
광량 조절
확산 조명
편광 필터
제품 위치 고정
```

따라서 오늘은 전처리로 해결할 문제와 촬영환경에서 해결할 문제를 구분하는 연습도 합니다.

# 8. Color Space를 왜 먼저 확인하나요?

`BGR·Gray·H·S·V 채널 이미지` `09_color_space.py`

7단락에서는 조명이나 촬영환경에 따라 이미지가 어두워지거나, 흐려지거나, Noise가 발생할 수 있다는 것을 배웠습니다.

이러한 문제가 있다면 이미지를 검사하기 좋은 상태로 개선해야 합니다.

그런데 이미지를 개선하기 전에 먼저 생각해야 할 것이 있습니다.

**컴퓨터가 이 이미지에서 무엇을 검사하고, 어떤 정보를 사용해야 할까요?**

```
이 검사에서 컴퓨터가 어떤 정보를 사용해야 하는가?
```

컬러 이미지 한 장에는 여러 정보가 함께 들어 있습니다.

```
제품 이미지
   ↓
색상 정보
밝기 정보
형태·경계 정보
```

모든 검사에서 이 정보를 전부 사용할 필요는 없습니다.

예를 들어 병뚜껑의 있음 / 없음만 검사한다고 생각해 봅니다.

```
병뚜껑의 색깔
→ 반드시 필요한가?

병뚜껑의 형태와 밝기 차이
→ 검사에 더 중요할 수 있음
```

이 경우에는 컬러 정보를 모두 유지하기보다 `Gray`로 변환하여 밝기와 형태를 중심으로 검사하는 것이 더 단순할 수 있습니다.

반대로 빨간색 스티커가 붙어 있는지 검사한다면:

```
형태만 본다
→ 부족할 수 있음

빨간색인가?
→ 중요한 검사 조건
```

이 경우에는 색상 정보를 분리해서 보기 쉬운 `HSV`가 더 적합할 수 있습니다.

따라서 Color Space를 확인하는 목적은:

```
이미지를 다른 색으로 보이게 만드는 것이 아니고   X

검사에 필요한 정보를
더 쉽게 측정할 수 있는 형태로 바꾸는 것입니다.   O
```

입니다.

---

## 8.1 대량의 이미지가 들어오면 어떻게 확인하나요?

실제 Dataset이 수백 장 또는 수천 장이라고 해서 처음부터 모든 이미지를 사람이 한 장씩 확인하면서 Color Space를 결정하는 것은 아닙니다.

먼저 대표적인 조건의 이미지를 확인합니다.

예를 들어:

```
정상 이미지 몇 장

불량 이미지 몇 장

밝은 조건

어두운 조건

반사가 있는 조건

제품 위치가 조금 다른 조건
```

등을 먼저 확인합니다.

2일차 실습에서도 같은 원리를 사용합니다.

```
cap_on_reference.jpg
→ 기준 영상

challenge.jpg
→ 어둡고 저대비 조건

glare.jpg
→ 강한 조명 조건
```

그리고 코드로 만든:

```
dark.jpg
low_contrast.jpg
noise.jpg
blur.jpg
```

를 함께 비교합니다.

이 자료를 보면서 먼저 다음 질문을 합니다.

```
검사하려는 차이가 무엇인가?

색깔이 중요한가?

밝기 차이가 중요한가?

형태와 경계만 있으면 되는가?

조명이 달라져도
검사에 사용할 정보가 유지되는가?
```

이 판단을 한 뒤 적절한 Color Space를 선택합니다.

> 실제 시스템에서는 이후 Histogram, 평균 밝기, 분산 등의 수치를 이용해 Dataset 전체의 영상 상태를 자동으로 분석할 수도 있습니다. 2일차에서는 먼저 대표 이미지를 직접 비교하며 원리를 이해합니다.

## 8.2 Color Space 선택은 전처리의 출발점입니다

전체 흐름을 다음처럼 이해하면 됩니다.

![[Pasted image 20260828132717.png]]

즉 무조건:

```
BGR
→ Gray
→ HSV
```

순서로 변환하는 것이 아닙니다.

세 가지 결과를 한 번 비교해 본 뒤 검사 목적에 맞는 표현을 선택하는 것입니다.

---

## 8.3 BGR — 원본 컬러 정보를 확인합니다

OpenCV의 `cv2.imread()`로 컬러 이미지를 읽으면 기본적으로 BGR 형태로 저장됩니다.

```
B = Blue
G = Green
R = Red
```

일반적으로 많이 사용하는 RGB와 채널 순서만 다릅니다.

```
일반적인 표현
R → G → B

OpenCV 기본
B → G → R
```

BGR은 특별한 검사기법이라기보다 OpenCV에서 읽은 원본 컬러 이미지의 기본 형태라고 이해하면 됩니다.

따라서 먼저 BGR 원본을 보고:

```
제품 색상이 검사에 중요한가?

색상 차이가 정상·불량을 구분하는가?

아니면 색상 없이도 구분 가능한가?
```

를 생각합니다.

---

## 8.4 Gray — 색상이 필요하지 않다면 밝기 정보만 사용합니다

Gray는 B·G·R의 컬러 정보를 하나의 밝기 정보로 변환합니다.

```
BGR
 ↓
Gray
 ↓
밝기 중심의 1채널 이미지
```

예를 들어 병뚜껑 존재 여부처럼:

```
병뚜껑 있음
vs
병뚜껑 없음
```

을 형태나 밝기 차이로 구분할 수 있다면 색상이 반드시 필요하지 않을 수 있습니다.

이런 문제에서는 Gray를 사용하면 이후 처리가 단순해집니다.

```
Gray
 ↓
Brightness / Contrast
 ↓
Threshold
 ↓
Morphology
 ↓
Contour
```

따라서 Gray는 특히 다음과 같은 경우 먼저 생각할 수 있습니다.

```
색상이 검사 기준이 아니다.

형태가 중요하다.

밝기 차이가 중요하다.

Threshold를 사용할 예정이다.

Contour로 면적이나 개수를 측정할 예정이다.
```

현재 병뚜껑 실습은 이쪽에 더 가깝습니다.

---

## 8.5 HSV — 색상 자체가 검사 기준이라면 사용합니다

HSV는 컬러 정보를 다음 세 가지로 분리합니다.

```
H = Hue
→ 어떤 색인가?

S = Saturation
→ 색이 얼마나 선명한가?

V = Value
→ 얼마나 밝은가?
```

예를 들어 제품에 빨간색 스티커가 붙어 있어야 한다고 생각해 봅니다.

```
정상
→ 빨간 스티커 있음

불량
→ 스티커 없음
또는
→ 다른 색 스티커
```

이 경우에는 단순한 Gray만으로는:

```
빨간색
파란색
초록색
```

이라는 색상 차이가 사라집니다.

따라서:

```
BGR 이미지
     ↓
HSV
     ↓
H 범위 확인
     ↓
빨간색 영역 분리
```

와 같은 방식이 더 적합할 수 있습니다.

또한 `V`를 보면 밝기 정보를 별도로 확인할 수 있으므로 조명 변화가 컬러 검사에 미치는 영향을 관찰하는 데도 도움이 됩니다.

---

## 8.6 어떤 Color Space를 선택해야 하나요?

처음부터 정답이 정해져 있는 것은 아닙니다.

검사 문제를 보고 선택합니다.

|검사 문제|먼저 생각할 Color Space|이유|
|---|---|---|
|병뚜껑 있음 / 없음|**Gray**|색상보다 형태·밝기 차이가 중요|
|와셔 개수|**Gray**|객체의 형태와 영역 분리가 중요|
|흠집·경계|**Gray**|밝기와 경계 정보가 중요|
|빨간색 스티커 검사|**HSV**|특정 색상 범위를 찾기 쉬움|
|제품 색상 불량|**HSV**|Hue와 Saturation 비교가 중요|
|원본 색상을 그대로 확인|**BGR**|OpenCV의 기본 컬러 정보 유지|

따라서 Color Space는 기술 이름부터 선택하는 것이 아니라 다음과 같이 결정합니다.

```
무엇을 검사하는가?
       ↓
정상과 불량의 차이가
어떤 정보에 있는가?
       ↓
색상?
밝기?
형태?
       ↓
적절한 Color Space 선택
```

---

## 8.7 이번 병뚜껑 실습에서는 왜 세 가지를 모두 비교하나요?

이번 병뚜껑 실습에서 최종적으로 BGR·Gray·HSV를 모두 사용하는 것이 목적은 아닙니다.

같은 이미지를 세 가지 방식으로 보면서 어떤 정보가 남고 어떤 정보가 사라지는지 직접 확인하기 위해서입니다.

```
같은 병뚜껑 이미지
        ↓
 ┌──────┼──────┐
```

# 10. Brightness와 Contrast는 왜 조절하나요?

앞에서는 같은 이미지를 `BGR`, `Gray`, `HSV`로 비교하면서 검사에 어떤 정보가 필요한지 확인했습니다.

현재 병뚜껑 존재 검사에서는 색상 자체보다 형태와 밝기 차이가 중요하다고 판단했으므로, 
이후에는 주로 Gray와 밝기 정보를 이용해 검사를 진행합니다.

그런데 같은 병뚜껑이라도 촬영할 때 조명이 달라지면 이미지의 밝기가 달라질 수 있습니다.

```text
같은 병뚜껑

정상 조명
→ 병뚜껑과 배경의 차이가 잘 보임

조명이 너무 어두움
→ 병뚜껑과 배경이 모두 어두워짐

대비가 부족함
→ 병뚜껑과 배경의 밝기 차이가 작아짐
```

이 상태로 다음 단계인 Threshold를 적용하면 같은 제품인데도 결과가 달라질 수 있습니다.

```text
촬영환경 변화
      ↓
밝기·대비 변화
      ↓
픽셀값 변화
      ↓
Threshold 결과 변화
      ↓
객체 영역이 제대로 분리되지 않을 수 있음
```

따라서 먼저 다음 질문을 합니다.
현재 이미지가 너무 어둡거나, 제품과 배경의 밝기 차이가 부족한가?
문제가 있다면 Brightness와 Contrast를 조절해 봅니다.

---

## 10.1 Brightness와 Contrast의 차이

### Brightness — 이미지 전체의 밝기를 조절합니다

Brightness를 높이면 전체 픽셀이 밝아지는 방향으로 이동합니다.

```
어두운 이미지

████████

      ↓ Brightness 증가

▓▓▓▓▓▓▓▓

      ↓

검사 대상이 더 잘 보일 수 있음
```

![[Pasted image 20260828135220.png]]

예를 들어 어두운 조건에서 촬영된 `dark.jpg`에 사용할 수 있습니다.

하지만 너무 많이 밝게 만들면 흰색에 가까운 영역의 정보가 사라질 수 있습니다.

---
### Contrast — 밝은 곳과 어두운 곳의 차이를 조절합니다

Contrast는 단순히 전체를 밝게 하는 것이 아니라 밝은 부분과 어두운 부분의 차이를 크게 또는 작게 만듭니다.

예를 들어:

![[Pasted image 20260828135844.png]]

```
낮은 Contrast

배경   = 120
제품   = 135

차이   = 15
```

제품과 배경이 비슷하게 보입니다.

Contrast를 높이면:

```
배경   → 더 어둡게
제품   → 더 밝게

        ↓

제품과 배경의 차이가 커질 수 있음
```

따라서 객체와 배경이 비슷한 밝기를 가지고 있을 때 Contrast 조정이 도움이 될 수 있습니다.

---

## 10.2 Brightness와 Contrast는 코드에서 어떻게 조절하나요?

OpenCV에서는 다음 관계로 단순하게 이해할 수 있습니다.

```
output = input × alpha + beta
```

여기서:

```
alpha
→ Contrast에 주로 영향

beta
→ Brightness에 주로 영향
```

예를 들어:

```
alpha = 1.0
beta = 40
```

이면 원래 픽셀값에 `40` 정도를 더하는 효과가 있으므로 전체적으로 밝아집니다.

```
원본
70  100  150

       ↓ beta +40

110  140  190
```

반면:

```
alpha = 1.5
beta = 0
```

이면 픽셀값의 차이가 더 크게 벌어지므로 Contrast가 증가합니다.

```
원본
70   100   150

       ↓ × 1.5

105   150   225
```

![[Pasted image 20260828140450.png]]

---

## 10.3 많이 조절하면 더 좋은가요?

그렇지 않습니다.

이미지 픽셀값은 일반적으로 다음 범위를 사용합니다.

```
0
→ 완전한 검정

255
→ 완전한 흰색
```

Brightness나 Contrast를 너무 강하게 적용하면 많은 픽셀이 `255`에 가까워질 수 있습니다.

```
원래 밝은 영역
220
230
240

      ↓ 과도한 밝기 증가

255
255
255
```

이렇게 되면 서로 달랐던 부분이 모두 흰색으로 바뀌면서 **세부정보를 구분할 수 없게 됩니다.**

즉:

```
밝게 만들었다
≠
검사하기 좋아졌다
```

입니다.

## 10.4 이번 실습에서는 무엇을 확인하나요?

이번에는 `dark.jpg`에 여러 `alpha`, `beta` 값을 적용하여 결과를 직접 비교합니다.

```

    ↓

    ↓
여러 결과 저장
    ↓

```

결과를 볼 때 단순히:

```
어느 이미지가 가장 밝은가?
```

를 보는 것이 아닙니다.

다음 질문으로 판단합니다.

```
병뚜껑이 더 잘 구분되는가?

병뚜껑의 홈과 경계가 유지되는가?

밝은 영역이 하얗게 날아가지는 않았는가?

Noise까지 함께 강조되지는 않았는가?

다음 Threshold에서
객체와 배경을 분리하기 쉬워졌는가?
```

즉 이번 실습의 목적은 이미지를 밝게 만드는 것 자체가 아니라, 검사에 도움이 되는 적절한 밝기와 대비를 찾는 것입니다.

전체 흐름은 다음과 같습니다.

```
Color Space 선택
      ↓
Gray 중심으로 검사하기로 판단
      ↓
영상 품질 확인
      ↓
너무 어두운가?
대비가 부족한가?
      ↓
Brightness / Contrast 조절
      ↓
여러 Parameter 비교
      ↓
다음 검사에 도움이 되는 값 선택
```

```python
# --------------------------------------------------

    "samples/day02/dark.jpg"
)


# --------------------------------------------------
# 3. Brightness 비교 결과를 저장할 폴더를 준비한다.
# --------------------------------------------------

output_dir = Path(
    "outputs/day02/brightness"
)

output_dir.mkdir(
    parents=True,
    exist_ok=True,
)

# 4. 기준 ROI 이미지를 읽는다.
# --------------------------------------------------

reference = cv2.imread(
    str(reference_path)
)


# --------------------------------------------------
# 5. 이미지가 정상적으로 읽히지 않았다면 오류를 발생시킨다.
# --------------------------------------------------

if reference is None:
    raise FileNotFoundError(
        f"기준 이미지를 읽지 못했습니다: {reference_path}"

# 6. 기준 이미지의 밝기를 약 55% 수준으로 낮춘다.
# --------------------------------------------------

dark = cv2.convertScaleAbs(
    reference,
    alpha=0.55,
    beta=0,
)


# --------------------------------------------------
# 7. 어둡게 만든 이미지를 dark.jpg로 저장한다.
# --------------------------------------------------

cv2.imwrite(
    str(dark_path),
    dark,
)

print("문제 이미지 생성:", dark_path)

#
# alpha = 1.0 고정
# beta = 0, 20, 50, 80

settings = [

    (1.0, 20),
    (1.0, 50),

    # 10. 현재 alpha, beta 값을 적용하고
    #     변환된 결과 이미지를 저장한다.

    result = cv2.convertScaleAbs(
        dark,
        alpha=alpha,
        beta=beta,
    )

    filename = (
        f"alpha_{alpha}_beta_{beta}.jpg"

        str(output_path),
        result,

    print("저장:", output_path)

    #
    # for 반복문이 다음 설정값으로 돌아간다.
    # beta=20 → beta=50 → beta=80
    # --------------------------------------------------


# --------------------------------------------------
# 12. 모든 결과 이미지를 각각 다른 파일명으로 저장한다.
#

#
# alpha_1.0_beta_0.jpg
# alpha_1.0_beta_20.jpg
# alpha_1.0_beta_50.jpg

print("Brightness 비교 이미지 저장 완료")

```

```
→ 형태와 경계가 잘 보임

```

# 12. Gamma Correction 이해하기

Brightness는 모든 픽셀에 비슷한 양을 더하는 방식으로 생각할 수 있습니다.

Gamma Correction은 밝기 분포를 **비선형적으로** 조절합니다.

따라서 어두운 중간 영역을 더 잘 보이게 하거나 반대로 너무 밝은 영상을 낮출 때 사용할 수 있습니다.

오늘 사용하는 코드에서는 다음 규칙을 따릅니다.

```text
gamma > 1.0
→ 더 밝아지는 방향

gamma < 1.0
→ 더 어두워지는 방향
```

> Gamma 구현 방법에 따라 표기 방향이 반대로 설명되는 자료도 있습니다.  
> 오늘 코드는 `1 / gamma`를 사용하므로 위 규칙으로 결과를 해석합니다.

```
Brightness
```

```
gamma = 1.2
gamma = 1.5
gamma = 2.0
```

```
gamma < 1.0
→ 더 어두워짐

gamma = 1.0
→ 변화 없음

gamma > 1.0
→ 더 밝아짐
```

입니다.

> 이번 실습의 목적은 가장 밝은 Gamma 값을 찾는 것이 아니라, 어두운 영역은 충분히 보이면서 밝은 영역의 정보는 지나치게 손실되지 않는 값을 찾는 것입니다.

다음 코드를 작성합니다.

```python

from pathlib import Path

import cv2
import numpy as np


# --------------------------------------------------
# 1. Gamma 결과를 저장할 폴더를 준비한다.
#    사용할 기준 이미지와 dark.jpg 경로도 정한다.
# --------------------------------------------------

reference_path = Path(
    "samples/day02/cap_on_reference.jpg"
)

dark_path = Path(
    "samples/day02/dark.jpg"
)

output_dir = Path(
    "outputs/day02/gamma"
)

output_dir.mkdir(
    parents=True,
    exist_ok=True,
)


# --------------------------------------------------
# 2. dark.jpg를 읽어본다.
# --------------------------------------------------

image = cv2.imread(
    str(dark_path)
)


# --------------------------------------------------
# 3. dark.jpg가 존재하는지 확인한다.
#
#    image가 None이면 이미지를 읽지 못했다는 뜻이다.
# --------------------------------------------------

if image is None:

    # --------------------------------------------------
    # 4. dark.jpg가 없다면
    #    cap_on_reference.jpg를 읽는다.
    # --------------------------------------------------

    print(
        "dark.jpg가 없어 기준 이미지에서 생성합니다."
    )

    reference = cv2.imread(
        str(reference_path)
    )

    if reference is None:
        raise FileNotFoundError(
            f"기준 이미지를 읽지 못했습니다: "
            f"{reference_path}"
        )


    # --------------------------------------------------
    # 5. 기준 이미지의 밝기를 낮춰
    #    dark.jpg를 자동으로 만든다.
    #
    #    alpha=0.55 → 원본 픽셀값을 약 55%로 줄임
    #    beta=0     → 별도의 밝기값을 더하지 않음
    # --------------------------------------------------

    image = cv2.convertScaleAbs(
        reference,
        alpha=0.55,
        beta=0,
    )

    cv2.imwrite(
        str(dark_path),
        image,
    )

    print(
        "문제 이미지 생성:",
        dark_path,
    )


# --------------------------------------------------
# 6. Gamma Correction 함수를 준비한다.
#
#    source → 변환할 이미지
#    gamma  → 적용할 Gamma 값
#
#    함수는 정의한 뒤 10번에서 호출한다.
# --------------------------------------------------

def adjust_gamma(
    source: np.ndarray,
    gamma: float,
) -> np.ndarray:

    # --------------------------------------------------
    # 7. Gamma 값이 0보다 큰지 확인한다.
    #
    #    0 이하이면 오류를 발생시킨다.
    # --------------------------------------------------

    if gamma <= 0:
        raise ValueError(
            "gamma는 0보다 커야 합니다."
        )


    # --------------------------------------------------
    # 8. 0~255의 픽셀값을
    #    Gamma 공식으로 변환하는
    #    Lookup Table을 만든다.
    #
    #    inv_gamma = 1 / gamma
    #
    #    Lookup Table은 원래 픽셀값을
    #    어떤 새로운 값으로 바꿀지 저장한 표이다.
    # --------------------------------------------------

    inv_gamma = 1.0 / gamma

    table = np.array(
        [
            (
                (value / 255.0)
                ** inv_gamma
            ) * 255
            for value in np.arange(256)
        ],
        dtype=np.uint8,
    )

    # Lookup Table을 이미지 전체에 적용한다.
    return cv2.LUT(
        source,
        table,
    )


# --------------------------------------------------
# 9. Gamma 값을 여러 개 준비한다.
#
#    0.6 / 0.8 / 1.0 / 1.2 / 1.5 / 2.0
# --------------------------------------------------

gamma_values = [
    0.6,
    0.8,
    1.0,
    1.2,
    1.5,
    2.0,
]


# --------------------------------------------------
# 10. 첫 번째 Gamma 값을 dark.jpg에 적용한다.
#
#     for 반복문에서 첫 번째 gamma=0.6을 가져온다.
#     adjust_gamma() 함수를 호출한다.
# --------------------------------------------------

for gamma in gamma_values:

    result = adjust_gamma(
        image,
        gamma,
    )


    # --------------------------------------------------
    # 11. 결과 이미지를 저장한다.
    #
    #     적용한 Gamma 값으로 파일명을 만든다.
    # --------------------------------------------------

    output_path = (
        output_dir
        / f"gamma_{gamma}.jpg"
    )

    cv2.imwrite(
        str(output_path),
        result,
    )

    print(
        "저장:",
        output_path,
    )


    # --------------------------------------------------
    # 12. 나머지 Gamma 값도 같은 방법으로 반복한다.
    #
    #     현재 반복이 끝나면 for문이 다음 값을 가져온다.
    #
    #     0.6 → 0.8 → 1.0 → 1.2 → 1.5 → 2.0
    #
    #     각 값마다 10번과 11번을 반복한다.
    # --------------------------------------------------


# --------------------------------------------------
# 13. 모든 결과 이미지를 비교한다.
#
#     아래 폴더에 저장된 6장의 이미지를 직접 확인한다.
#
#     outputs/day02/gamma/
#
#     gamma_0.6.jpg
#     gamma_0.8.jpg
#     gamma_1.0.jpg
#     gamma_1.2.jpg
#     gamma_1.5.jpg
#     gamma_2.0.jpg
# --------------------------------------------------

print("Gamma 비교 이미지 저장 완료")


# --------------------------------------------------
# 14. 어두운 영역은 잘 보이면서
#     밝은 영역의 정보가 지나치게 사라지지 않는지 확인한다.
#
#     확인할 내용:
#     - 병뚜껑의 외곽과 세로 홈이 잘 보이는가?
#     - 어두운 부분이 적절하게 밝아졌는가?
#     - 밝은 부분이 너무 하얗게 변하지 않았는가?
#     - Noise까지 지나치게 강조되지 않았는가?
#
#     학생이 결과 이미지를 직접 비교하고 판단한다.
# --------------------------------------------------
```

## 13.3 결과는 무엇을 비교하나요?

### Gamma 결과 비교

![[{B9BB3127-6491-4596-8A8A-7380CA54C359}.png]]

|   Gamma | 실제 결과 해석                                         | 판단               |
| ------: | ------------------------------------------------ | ---------------- |
| **0.6** | 전체가 매우 어두워져 병뚜껑의 홈과 세부 형태가 거의 보이지 않습니다.          | 너무 어두워 검사에 불리함   |
| **0.8** | `0.6`보다 조금 밝아졌지만 여전히 병뚜껑의 어두운 영역이 많이 묻혀 있습니다.    | 다소 어두움           |
| **1.0** | `dark.jpg`와 동일한 기준 이미지입니다.                       | 비교 기준            |
| **1.2** | 병뚜껑의 세로 홈과 경계가 조금 더 잘 보이기 시작합니다.                 | 개선 효과 있음         |
| **1.5** | 어두운 영역이 더 살아나면서 병뚜껑 형태가 비교적 명확하게 보입니다.           | 현재 결과에서 비교적 적절   |
| **2.0** | 전체가 상당히 밝아져 병뚜껑 세부는 잘 보이지만 배경과 밝은 영역도 많이 밝아졌습니다. | 과도한 밝기 가능성 확인 필요 |
현재 결과 흐름을 보면

```
gamma = 0.6
→ 너무 어두움

gamma = 0.8
→ 조금 밝아짐

gamma = 1.0
→ 기준

gamma = 1.2
→ 어두운 영역 개선 시작

gamma = 1.5
→ 병뚜껑 경계와 홈이 비교적 잘 보임

gamma = 2.0
→ 많이 밝아짐
→ 밝은 영역까지 과도하게 증가할 가능성
```

먼저 `gamma=1.0`을 기준으로 봅니다.

```text
병뚜껑 경계가 더 잘 보이는가?

어두운 영역의 정보가 살아났는가?

밝은 부분이 너무 하얗게 변했는가?

배경 Noise도 함께 강조되었는가?

이 결과가 Threshold에 도움이 될 것 같은가?
```

### Gamma는 무엇을 기준으로 선택하나요?

`잘 보인다`의 기준은 사람이 보기 좋은지가 아니라 다음 검사 단계가 잘 되는가입니다.

예를 들어 병뚜껑 검사라면:

```
Gamma 후보
0.6 / 0.8 / 1.0 / 1.2 / 1.5 / 2.0
        ↓
각 이미지에 동일한 Threshold / Otsu 적용
        ↓
병뚜껑 영역이 제대로 분리되는지 비교
        ↓
Contour 추출
        ↓
면적·경계가 안정적으로 측정되는지 비교
        ↓
가장 안정적인 Gamma 선택
```

따라서 판단 기준은 다음과 같습니다.

| 판단 기준        | 확인하는 내용                        |
| ------------ | ------------------------------ |
| 경계 보존        | 병뚜껑의 외곽과 홈이 사라지지 않았는가          |
| 어두운 영역 정보    | 너무 검게 뭉개진 부분이 없는가              |
| 밝은 영역 정보     | 흰색으로 날아간 부분이 없는가               |
| Noise        | 밝게 만들면서 불필요한 Noise까지 증가하지 않았는가 |
| Threshold 결과 | 객체와 배경이 더 깨끗하게 분리되는가           |
| Contour 결과   | 객체의 면적·형태가 안정적으로 측정되는가         |

만약 원본 상태가 이미 검사에 가장 적합하다고 판단했다면 
==`Gamma Correction을 사용하지 않는다.`== 가 올바른 결론입니다.

# 14. 저대비 영상과 CLAHE

## 14.1 Contrast가 낮다는 것은 무엇인가요?

예를 들어 배경과 제품의 밝기가 다음과 같다고 생각합니다.

```text
배경 밝기 ≈ 120
제품 밝기 ≈ 130
```

차이가 작으면 사람 눈에는 형태가 보이더라도 컴퓨터가 단순한 밝기 기준으로 분리하기 어려울 수 있습니다.

CLAHE는 이미지를 작은 영역으로 나누어 **지역별 Contrast를 개선**하는 방법입니다.

```text
Low Contrast ROI
       ↓
CLAHE
       ↓
지역별 대비 개선
       ↓
경계·문자·형태가
더 잘 구분될 수 있음
```

하지만 너무 강하게 적용하면 배경 Texture와 Noise도 함께 강조될 수 있습니다.

## 15.1 코드 작성하기

새 파일을 만듭니다.

```
src/12_clahe.py
```

다음 코드를 작성합니다.

```python

from pathlib import Path

import cv2


# --------------------------------------------------
# 1. 사용할 이미지와 결과 저장 경로를 정한다.
# --------------------------------------------------

reference_path = Path(
    "samples/day02/cap_on_reference.jpg"
)

low_contrast_path = Path(
    "samples/day02/low_contrast.jpg"
)

output_dir = Path(
    "outputs/day02/clahe"
)


# --------------------------------------------------
# 2. CLAHE 결과를 저장할 폴더를 준비한다.
# --------------------------------------------------

output_dir.mkdir(
    parents=True,
    exist_ok=True,
)


# --------------------------------------------------
# 3. 기준 ROI 이미지를 읽는다.
# --------------------------------------------------

reference = cv2.imread(
    str(reference_path)
)


# --------------------------------------------------
# 4. 기준 이미지를 정상적으로 읽었는지 확인한다.
#
#    읽지 못했다면 FileNotFoundError를 발생시킨다.
# --------------------------------------------------

if reference is None:
    raise FileNotFoundError(
        f"기준 이미지를 읽지 못했습니다: "
        f"{reference_path}"
    )


# --------------------------------------------------
# 5. 기준 이미지의 Contrast를 낮춰
#    실습용 저대비 이미지를 만든다.
#
#    alpha=0.35 → 픽셀값의 차이를 줄인다.
#    beta=80    → 픽셀값에 80을 더한다.
#
#    병뚜껑과 배경의 밝기 차이가 줄어든다.
# --------------------------------------------------

low_contrast = cv2.convertScaleAbs(
    reference,
    alpha=0.35,
    beta=80,
)


# --------------------------------------------------
# 6. 저대비 이미지를 low_contrast.jpg로 저장한다.
# --------------------------------------------------

cv2.imwrite(
    str(low_contrast_path),
    low_contrast,
)

print(
    "문제 이미지 생성:",
    low_contrast_path,
)


# --------------------------------------------------
# 7. 기준 이미지와 저대비 이미지를 Gray로 변환한다.
#
#    컬러 BGR → 흑백 Gray
#
#    CLAHE는 이번 실습에서
#    1채널 Gray 이미지에 적용한다.
# --------------------------------------------------

reference_gray = cv2.cvtColor(
    reference,
    cv2.COLOR_BGR2GRAY,
)

low_contrast_gray = cv2.cvtColor(
    low_contrast,
    cv2.COLOR_BGR2GRAY,
)


# --------------------------------------------------
# 8. 두 Gray 이미지를 각각 저장한다.
#
#    reference_gray.jpg
#    → 기준 이미지의 Gray 결과
#
#    low_contrast_gray.jpg
#    → Contrast를 낮춘 Gray 결과
#
#    두 이미지를 비교하여 저대비 상태를 확인한다.
# --------------------------------------------------

cv2.imwrite(
    str(
        output_dir
        / "reference_gray.jpg"
    ),
    reference_gray,
)

cv2.imwrite(
    str(
        output_dir
        / "low_contrast_gray.jpg"
    ),
    low_contrast_gray,
)


# --------------------------------------------------
# 9. CLAHE에서 사용할 파라미터를 준비한다.
#
#    clipLimit → 대비 향상 강도 조절
#    tileGridSize → 이미지를 나눌 격자 수
#
#    clipLimit = 1.0, 2.0, 3.0, 4.0
#    tileGridSize = (8, 8) 고정
# --------------------------------------------------

settings = [
    (1.0, (8, 8)),
    (2.0, (8, 8)),
    (3.0, (8, 8)),
    (4.0, (8, 8)),
]


# --------------------------------------------------
# 10. CLAHE 파라미터를 하나씩 가져와 반복한다.
#
#     첫 번째 반복:
#     clip_limit = 1.0
#     tile_size = (8, 8)
#
#     이후 2.0 → 3.0 → 4.0 순서로 반복한다.
# --------------------------------------------------

for clip_limit, tile_size in settings:

    # --------------------------------------------------
    # 11. 현재 파라미터로 CLAHE 객체를 생성한다.
    #
    #     clipLimit → 대비 향상 강도 설정
    #     tileGridSize → 지역 격자 수 설정
    # --------------------------------------------------

    clahe = cv2.createCLAHE(
        clipLimit=clip_limit,
        tileGridSize=tile_size,
    )


    # --------------------------------------------------
    # 12. 저대비 Gray 이미지에 CLAHE를 적용한다.
    #
    #     지역별 밝기 분포를 조절하여
    #     병뚜껑의 경계가 잘 구분되는지 확인한다.
    # --------------------------------------------------

    result = clahe.apply(
        low_contrast_gray
    )


    # --------------------------------------------------
    # 13. 적용한 clipLimit 값을 이용해
    #     결과 이미지의 파일명을 만든다.
    #
    #     예: clahe_clip_1.0.jpg
    # --------------------------------------------------

    output_path = (
        output_dir
        / f"clahe_clip_{clip_limit}.jpg"
    )


    # --------------------------------------------------
    # 14. CLAHE 결과 이미지를 저장한다.
    #
    #     저장 후 다음 clipLimit 값으로
    #     11~14번 과정을 반복한다.
    # --------------------------------------------------

    cv2.imwrite(
        str(output_path),
        result,
    )

    print(
        "저장:",
        output_path,
    )


# --------------------------------------------------
# 15. 모든 결과 이미지를 직접 비교한다.
#
#     reference_gray.jpg
#     low_contrast_gray.jpg
#     clahe_clip_1.0.jpg
#     clahe_clip_2.0.jpg
#     clahe_clip_3.0.jpg
#     clahe_clip_4.0.jpg
#
#     병뚜껑의 세로 홈과 외곽 경계가 잘 보이는가?
#     Noise가 지나치게 강조되지는 않았는가?
#
#     학생이 결과를 직접 관찰하고 분석한다.
# --------------------------------------------------

```

실행합니다.

```bash
python src/12_clahe.py
```

```text
[15. 결과 비교 및 분석]

15. 모든 CLAHE 결과 이미지를 비교한다.

    병뚜껑의 세로 홈이 잘 보이는가?
```

|   **2.0** | 병뚜껑의 세로 홈과 경계가 조금 더 분명하게 보입니다.                                 |

|   **4.0** | 가장 강한 대비가 나타납니다. 병뚜껑의 홈은 잘 보이지만 배경과 표면 Texture도 함께 강조되기 시작합니다. |

```
2.0

3.0
```

# 16. Noise와 Filter

![[Pasted image 20260828153017.png]]

카메라 영상의 Noise는 조명이 부족하거나 센서 감도가 높아졌을 때, 또는 촬영환경이 좋지 않을 때 영상에 작은 점·거친 입자처럼 나타나는 불필요한 정보입니다.

이런 Noise가 많으면 뒤에서 Threshold나 Contour를 적용할 때 실제 제품이 아닌 작은 점들까지 객체나 결함으로 잘못 인식될 수 있기 때문에, 검사 전에 적절한 Filter를 사용해 줄여줄 필요가 있습니다.

오늘은 세 가지 대표 Filter를 비교합니다.

```text
Gaussian Blur
Median Blur
Bilateral Filter
```

## 16.1 Gaussian Blur

주변 픽셀의 가중 평균을 이용해 이미지를 부드럽게 만듭니다.

```text
장점
→ 일반적인 Noise 감소

단점
→ 작은 결함과 경계도 함께 흐려질 수 있음
```

---

## 16.2 Median Blur

주변 픽셀의 중간값을 사용합니다.

점 형태의 Salt-and-Pepper Noise에 효과적인 경우가 많습니다.

```text
장점
→ 점 Noise 제거에 유리한 경우가 많음

단점
→ Kernel이 커지면 작은 형태가 사라질 수 있음
```

---

## 16.3 Bilateral Filter

픽셀의 위치와 밝기 차이를 함께 고려하여 Noise를 줄이면서 경계를 어느 정도 보존하려고 합니다.

```text
장점
→ 경계를 비교적 유지하면서 Smoothing

단점
→ 계산량이 상대적으로 큼
```

## 17.1 코드 작성하기

새 파일을 만듭니다.

```text
src/13_filter_compare.py
```

```python

from pathlib import Path

import cv2
import numpy as np


# --------------------------------------------------
# 1. 기준 이미지와 Noise 이미지의 경로를 정한다.
#    Filter 결과를 저장할 경로도 정한다.
# --------------------------------------------------

reference_path = Path(
    "samples/day02/cap_on_reference.jpg"
)

noise_path = Path(
    "samples/day02/noise.jpg"
)

output_dir = Path(
    "outputs/day02/filter"
)


# --------------------------------------------------
# 2. Filter 결과를 저장할 폴더를 생성한다.
# --------------------------------------------------

output_dir.mkdir(
    parents=True,
    exist_ok=True,
)


# --------------------------------------------------
# 3. 1일차에서 만든 병뚜껑 기준 ROI 이미지를 읽는다.
# --------------------------------------------------

reference = cv2.imread(
    str(reference_path)
)


# --------------------------------------------------
# 4. 기준 이미지를 정상적으로 읽었는지 확인한다.
#    읽지 못했다면 오류를 발생시킨다.
# --------------------------------------------------

if reference is None:
    raise FileNotFoundError(
        f"기준 이미지를 읽지 못했습니다: "
        f"{reference_path}"
    )


# --------------------------------------------------
# 5. Noise를 생성하기 위한 난수 Seed를 고정한다.
#
#    42는 난수 생성의 시작 기준값이다.
#    같은 이미지와 설정을 사용하면
#    실행할 때마다 동일한 Noise를 만들 수 있다.
# --------------------------------------------------

rng = np.random.default_rng(42)


# --------------------------------------------------
# 6. 기준 이미지에 추가할 Gaussian Noise를 생성한다.
#
#    loc=0      → Noise의 평균값
#    scale=18   → Noise의 표준편차
#    size       → 기준 이미지와 같은 배열 크기
#
#    각 픽셀에 더할 작은 변화량을 생성한다.
# --------------------------------------------------

gaussian_noise = rng.normal(
    loc=0,
    scale=18,
    size=reference.shape,
)


# --------------------------------------------------
# 7. 기준 이미지에 Gaussian Noise를 더한다.
#
#    float32로 변환하여 Noise를 더한 뒤
#    np.clip()으로 픽셀값을 0~255로 제한한다.
#
#    마지막에 uint8 이미지로 변환한다.
# --------------------------------------------------

noisy = reference.astype(
    np.float32
) + gaussian_noise

noisy = np.clip(
    noisy,
    0,
    255,
).astype(np.uint8)


# --------------------------------------------------
# 8. 점 형태 Noise를 추가할 픽셀 개수를 정한다.
#
#    이미지의 높이와 너비를 구한다.
#    전체 픽셀 수의 1%를 Noise 개수로 사용한다.
# --------------------------------------------------

height, width = noisy.shape[:2]

noise_count = int(
    height * width * 0.01
)


# --------------------------------------------------
# 9. 점 Noise를 추가할 위치를 무작위로 선택한다.
#
#    ys → 세로 좌표
#    xs → 가로 좌표
#
#    half → 검정 점과 흰색 점을 나누기 위한 값
# --------------------------------------------------

ys = rng.integers(
    0,
    height,
    noise_count,
)

xs = rng.integers(
    0,
    width,
    noise_count,
)

half = noise_count // 2


# --------------------------------------------------
# 10. 선택한 위치의 절반을 검정 점으로 만든다.
#
#     픽셀값 0 → 검정색
# --------------------------------------------------

noisy[
    ys[:half],
    xs[:half],
] = 0


# --------------------------------------------------
# 11. 나머지 위치를 흰색 점으로 만든다.
#
#     픽셀값 255 → 흰색
#
#     검정 점과 흰색 점이 추가되면서
#     Salt-and-Pepper Noise를 흉내 낸다.
# --------------------------------------------------

noisy[
    ys[half:],
    xs[half:],
] = 255


# --------------------------------------------------
# 12. Gaussian Noise와 점 Noise가 추가된 이미지를
#     noise.jpg로 저장한다.
# --------------------------------------------------

cv2.imwrite(
    str(noise_path),
    noisy,
)

print(
    "문제 이미지 생성:",
    noise_path,
)


# --------------------------------------------------
# 13. Noise가 추가된 이미지를 Gray로 변환한다.
#
#     이후 Filter 비교는 같은 Gray 이미지를
#     기준으로 진행한다.
# --------------------------------------------------

gray = cv2.cvtColor(
    noisy,
    cv2.COLOR_BGR2GRAY,
)


# --------------------------------------------------
# 14. Filter 비교 결과를 저장할 딕셔너리를 만든다.
#
#     original_gray.jpg에는
#     아직 Filter를 적용하지 않은 Gray 이미지를 넣는다.
#
#     이 이미지는 다른 Filter 결과와 비교할 기준이다.
# --------------------------------------------------

results = {
    "original_gray.jpg": gray,


    # --------------------------------------------------
    # 15. Gaussian Blur를 적용한다.
    #
    #     (3, 3) → 3×3 Kernel
    #     (7, 7) → 7×7 Kernel
    #
    #     주변 픽셀의 가중 평균을 이용하여
    #     이미지의 Noise를 부드럽게 줄인다.
    #
    #     Kernel이 커지면 경계도 더 흐려질 수 있다.
    # --------------------------------------------------

    "gaussian_3.jpg": cv2.GaussianBlur(
        gray,
        (3, 3),
        0,
    ),

    "gaussian_7.jpg": cv2.GaussianBlur(
        gray,
        (7, 7),
        0,
    ),


    # --------------------------------------------------
    # 16. Median Blur를 적용한다.
    #
    #     3 → 3×3 Kernel
    #     7 → 7×7 Kernel
    #
    #     주변 픽셀의 중간값을 이용한다.
    #     검정색·흰색 점 Noise 제거에 유리할 수 있다.
    # --------------------------------------------------

    "median_3.jpg": cv2.medianBlur(
        gray,
        3,
    ),

    "median_7.jpg": cv2.medianBlur(
        gray,
        7,
    ),


    # --------------------------------------------------
    # 17. Bilateral Filter를 적용한다.
    #
    #     9  → 주변 픽셀을 고려할 크기
    #     75 → 색상·밝기 차이에 대한 설정값
    #     75 → 공간적 거리 차이에 대한 설정값
    #
    #     경계를 어느 정도 유지하면서
    #     Noise를 줄이기 위한 Filter이다.
    # --------------------------------------------------

    "bilateral.jpg": cv2.bilateralFilter(
        gray,
        9,
        75,
        75,
    ),
}


# --------------------------------------------------
# 18. Filter 결과를 하나씩 가져와 반복한다.
#
#     results.items()에서
#     filename → 저장할 파일명
#     result   → Filter가 적용된 이미지
#
#     두 값을 하나씩 가져온다.
# --------------------------------------------------

for filename, result in results.items():

    # --------------------------------------------------
    # 19. 현재 Filter 결과 이미지의 저장 경로를 만들고
    #     파일로 저장한다.
    #
    #     저장 후 다음 결과로 반복한다.
    # --------------------------------------------------

    output_path = (
        output_dir / filename
    )

    cv2.imwrite(
        str(output_path),
        result,
    )

    print(
        "저장:",
        output_path,
    )


# --------------------------------------------------
# 20. 모든 Filter 결과를 직접 비교한다.
#
#     original_gray.jpg
#     gaussian_3.jpg
#     gaussian_7.jpg
#     median_3.jpg
#     median_7.jpg
#     bilateral.jpg
#
#     확인할 내용:
#
#     - 어떤 Filter에서 Noise가 가장 많이 줄었는가?
#     - 병뚜껑의 외곽 경계는 유지되는가?
#     - 병뚜껑의 세로 홈은 남아 있는가?
#     - 작은 특징까지 사라지지는 않았는가?
#
#     학생이 결과 이미지를 직접 비교하고 분석한다.
# --------------------------------------------------

print("Filter 비교 이미지 저장 완료")
```

실행합니다.

```bash
python src/13_filter_compare.py
```

### 각 Filter의 차이를 이해합니다

① Gaussian Blur — Noise는 줄지만 경계도 흐려집니다.

`gaussian_3.jpg`를 보면 검정색 병뚜껑 내부에 작은 밝은 점들이 아직 많이 보입니다. `gaussian_7.jpg`에서는 점들이 더 흐려졌지만 병뚜껑의 경계도 함께 흐려졌습니다.

```
Gaussian 3×3
→ Noise가 일부 부드러워짐
→ 병뚜껑 외곽은 비교적 유지
→ 작은 점들이 여전히 남음

Gaussian 7×7
→ 이미지가 더 부드러워짐
→ 병뚜껑 경계도 함께 흐려짐
→ 작은 특징을 구분하기 어려워질 수 있음
```

즉, Kernel을 크게 한다고 무조건 좋은 것은 아닙니다.

② Median Blur — 이번 점 Noise 제거에 효과적입니다.

이번 결과에서 특히 비교해야 할 것은 `median_3.jpg`와 `median_7.jpg`입니다.

`Median 3×3`에서는 검정색·흰색 점들이 크게 줄어든 반면 병뚜껑의 외곽 형태는 비교적 잘 남아 있습니다.

`Median 7×7`에서는 Noise가 더 많이 줄어 표면이 매우 매끄럽게 보입니다. 하지만 병뚜껑의 작은 홈이나 경계도 부드러워졌습니다.

```
Median 3×3
→ 튀는 점 Noise 크게 감소
→ 외곽 형태 비교적 유지
→ 일부 잔잔한 입자 남음

Median 7×7
→ 점 Noise 더욱 감소
→ 표면이 훨씬 매끄러워짐
→ 작은 홈과 경계가 약해질 수 있음
```

여기서 중요한 질문이 있습니다.

우리는 지금 병뚜껑 표면을 매끄럽게 만드는 것이 목적일까요?

아닙니다. 병뚜껑이 있는지 없는지를 검사하는 것이 목적입니다.

따라서 병뚜껑의 형태를 잘 유지하면서 불필요한 Noise를 줄이는 방법이 검사에 더 적합할 수 있습니다.

③ Bilateral Filter — 표면은 부드럽지만 밝은 점들이 남아 있습니다.

`bilateral.jpg`를 보면 병뚜껑 내부의 잔잔한 입자는 상당히 줄었습니다. 그러나 흰색으로 튀는 작은 점들은 여전히 보입니다.

Bilateral Filter는 주변 픽셀과의 밝기 차이도 고려합니다. 따라서 주변보다 유난히 밝거나 어두운 점을 경계처럼 보존하여, 이번처럼 강한 점 Noise가 남을 수 있습니다.

```
Bilateral
→ 표면의 잔잔한 Noise 감소
→ 병뚜껑 형태 비교적 유지
→ 밝은 점 Noise는 상당수 남음
```

즉, 경계를 보존하는 Filter라고 해서 모든 종류의 Noise를 잘 제거하는 것은 아닙니다.

### 이번 결과에서 어떤 Filter가 좋은 후보인가요?

현재 이미지를 눈으로 비교하면 다음과 같이 정리할 수 있습니다.

|판단 기준|유리해 보이는 결과|이유|
|---|---|---|
|튀는 점 Noise 제거|Median 7×7|표면에 남은 점들이 가장 적어 보임|
|점 Noise 감소와 외곽 형태의 균형|Median 3×3|튀는 점들이 줄고 병뚜껑 형태도 비교적 유지|
|잔잔한 입자 감소|Median 7×7, Bilateral|표면이 부드러워짐|
|밝은 점 Noise 제거|Median 계열|Gaussian·Bilateral보다 밝은 점이 적게 남음|
|최종 병뚜껑 검사 적합성|아직 결정할 수 없음|Otsu로 객체를 분리한 결과가 필요|

따라서 현재 단계에서는 `Median 3×3`과 `Median 7×7`을 우선 비교 후보로 선택하는 것이 합리적입니다.

`Median 3×3`은 병뚜껑의 형태를 유지하는 데 유리해 보이고, `Median 7×7`은 Noise를 더 많이 제거한 결과입니다.

하지만 병뚜껑 유무 검사에서는 반드시 홈의 세부 무늬까지 선명해야 하는 것은 아닙니다. 병뚜껑 전체 영역을 안정적으로 찾을 수 있다면 작은 무늬가 일부 줄어들어도 괜찮을 수 있습니다.

그래서 어느 것이 최종적으로 적합한지는 다음 이진화 결과까지 확인해야 합니다.

### 이번 실습의 최종 결론

이번 실행 결과에서는 Gaussian, Median, Bilateral Filter가 같은 Noise 이미지에 서로 다른 영향을 주는 것을 확인했습니다.

특히 `Median 3×3`은 병뚜껑의 외곽 형태를 비교적 유지하면서 점 Noise를 크게 줄였고, `Median 7×7`은 Noise를 더 많이 제거했지만 작은 특징도 부드럽게 만들었습니다. Bilateral Filter는 표면을 부드럽게 만들었으나 밝은 점 Noise가 남아 있었습니다.

따라서 이번 실습에서 배운 핵심은 다음과 같습니다.

> Noise가 가장 적은 이미지가 반드시 검사에 가장 좋은 이미지는 아닙니다.
> 
> 지금은 병뚜껑의 유무를 검사하고 있으므로, Noise를 줄이는 동시에 병뚜껑의 전체 형태와 경계를 유지하는 것이 중요합니다.
> 
> 현재 결과에서는 Median 3×3과 Median 7×7이 좋은 후보이며, 이후 Otsu 이진화를 적용하여 실제로 병뚜껑과 배경이 잘 분리되는지 확인한 뒤 적합한 방법을 선택합니다.

# 18. Blur는 언제 문제가 되나요?

![[Pasted image 20261023171201.png]]

머신비전 영상이 흐려지는 원인은 여러 가지가 있습니다.

```text
카메라 초점이 정확하지 않음
카메라 또는 제품의 진동
제품이 움직이는 동안 촬영
셔터속도가 느림
과도한 Blur Filter 적용
```

이렇게 영상이 흐려지면 제품의 경계와 작은 결함이 주변 픽셀과 섞이면서 약해질 수 있습니다.

예를 들어 작은 흠집을 검사한다고 생각합니다.

```text
작은 흠집
    ↓
Blur 발생
    ↓
주변 픽셀과 섞임
    ↓
흠집 경계가 약해짐
    ↓
불량을 놓칠 가능성
```

따라서 Noise를 줄이기 위해 Blur를 사용할 때도 다음 두 가지를 함께 확인해야 합니다.

```
Noise 감소
    +
검사 특징 보존
```

Noise가 많이 사라졌다고 반드시 좋은 전처리는 아닙니다. 검사해야 할 경계나 작은 결함까지 사라지지 않았는지 함께 확인해야 합니다.

# 19. Sharpening은 언제 사용하나요?

![[Pasted image 20261023171209.png]]

Sharpening은 조금 흐려진 영상에서 이미 존재하는 경계를 더 강조하고 싶을 때 사용할 수 있습니다.

예를 들어:

```text
병뚜껑 세로 홈이 약간 흐림
        ↓
경계가 완전히 사라진 것은 아님
        ↓
Sharpening 적용
        ↓
홈과 외곽 경계를 더 강조
```

따라서 다음과 같은 경우에 후보가 될 수 있습니다.

```
초점이 약간 흐림

경계가 조금 약함

전처리 과정에서
형태가 약간 부드러워짐
```

하지만 Sharpening은 없어진 정보를 복구하는 기술은 아닙니다.

```
약한 Blur
→ Sharpening으로 경계 강조 가능

심한 Blur
→ 원래 정보가 많이 손실됨
→ Sharpening만으로 복구 어려움
```

또한 원본에 Noise가 많으면:

```
경계 강조
    +
Noise도 함께 강조
```

될 수 있습니다.

따라서 Sharpening 역시 무조건 사용하는 것이 아니라 검사에 필요한 경계가 실제로 더 안정적으로 보이는지 확인한 뒤 사용 여부를 결정합니다.

## 20.1 코드 작성하기

새 파일을 만듭니다.

```
src/14_sharpen.py
```

```python

from pathlib import Path

import cv2
import numpy as np


# --------------------------------------------------
# 1. 사용할 이미지와 결과 저장 경로를 정한다.
#
#    reference_path → 1일차 병뚜껑 기준 ROI
#    blur_path      → 흐리게 만든 이미지 저장 경로
#    output_dir     → Sharpening 비교 결과 폴더
# --------------------------------------------------

reference_path = Path(
    "samples/day02/cap_on_reference.jpg"
)

blur_path = Path(
    "samples/day02/blur.jpg"
)

output_dir = Path(
    "outputs/day02/sharpen"
)


# --------------------------------------------------
# 2. Sharpening 결과를 저장할 폴더를 생성한다.
#
#    parents=True → 상위 폴더도 필요하면 생성
#    exist_ok=True → 폴더가 이미 있어도 오류 없음
# --------------------------------------------------

output_dir.mkdir(
    parents=True,
    exist_ok=True,
)


# --------------------------------------------------
# 3. 기준 ROI 이미지를 읽는다.
#
#    cv2.imread()로 병뚜껑 이미지를 불러온다.
# --------------------------------------------------

reference = cv2.imread(
    str(reference_path)
)


# --------------------------------------------------
# 4. 이미지를 정상적으로 읽었는지 확인한다.
#
#    reference가 None이면 파일을 읽지 못한 것이다.
#    오류 메시지를 출력하고 실행을 중단한다.
# --------------------------------------------------

if reference is None:
    raise FileNotFoundError(
        f"기준 이미지를 읽지 못했습니다: "
        f"{reference_path}"
    )


# --------------------------------------------------
# 5. 기준 이미지에 Gaussian Blur를 적용한다.
#
#    (7, 7) → 7×7 Kernel 사용
#    0      → Sigma 값을 OpenCV가 자동 계산
#
#    병뚜껑의 경계와 세부 형태를 일부러 흐리게 만든다.
# --------------------------------------------------

blurred = cv2.GaussianBlur(
    reference,
    (7, 7),
    0,
)


# --------------------------------------------------
# 6. 흐리게 만든 이미지를 blur.jpg로 저장한다.
#
#    이후 Sharpening 효과를 비교할 문제 이미지이다.
# --------------------------------------------------

cv2.imwrite(
    str(blur_path),
    blurred,
)

print(
    "문제 이미지 생성:",
    blur_path,
)


# --------------------------------------------------
# 7. Sharpening Kernel을 만든다.
#
#    3×3 행렬을 사용한다.
#
#       0  -1   0
#      -1   5  -1
#       0  -1   0
#
#    중심 픽셀의 값을 강조하고
#    주변 픽셀과의 차이를 이용하여 경계를 강조한다.
#
#    dtype=np.float32 → 실수형 Kernel
# --------------------------------------------------

kernel = np.array(
    [
        [0, -1, 0],
        [-1, 5, -1],
        [0, -1, 0],
    ],
    dtype=np.float32,
)


# --------------------------------------------------
# 8. Blur 이미지에 Sharpening을 적용한다.
#
#    cv2.filter2D() → Kernel을 이미지 전체에 적용
#
#    blurred → 입력 이미지
#    -1      → 출력 이미지의 자료형 깊이를 입력과 동일하게 유지
#    kernel  → 7번에서 만든 Sharpening Kernel
#
#    결과를 sharpened에 저장한다.
# --------------------------------------------------

sharpened = cv2.filter2D(
    blurred,
    -1,
    kernel,
)


# --------------------------------------------------
# 9. 기준 ROI 이미지를 reference.jpg로 저장한다.
#
#    Blur와 Sharpening을 적용하지 않은
#    원래 병뚜껑 이미지이다.
# --------------------------------------------------

cv2.imwrite(
    str(
        output_dir / "reference.jpg"
    ),
    reference,
)


# --------------------------------------------------
# 10. Blur 이미지를 blurred.jpg로 저장한다.
#
#     5번에서 Gaussian Blur를 적용한 결과이다.
#     기준 이미지와 비교하여 경계가 얼마나
#     흐려졌는지 확인할 수 있다.
# --------------------------------------------------

cv2.imwrite(
    str(
        output_dir / "blurred.jpg"
    ),
    blurred,
)


# --------------------------------------------------
# 11. Sharpening 결과를 sharpened.jpg로 저장한다.
#
#     8번에서 경계를 강조한 결과이다.
#     Blur 이미지보다 경계가 강조되었는지 비교한다.
# --------------------------------------------------

cv2.imwrite(
    str(
        output_dir / "sharpened.jpg"
    ),
    sharpened,
)


# --------------------------------------------------
# 12. 결과 저장 완료 메시지를 출력한다.
#
#     저장된 이미지 3장을 직접 비교한다.
#
#     reference.jpg
#     blurred.jpg
#     sharpened.jpg
#
#     확인할 내용:
#     - Blur 후 병뚜껑 경계가 흐려졌는가?
#     - Sharpening으로 경계가 다시 강조되었는가?
#     - 원본과 동일하게 복원되었는가?
#     - Noise나 불필요한 경계도 강조되었는가?
# --------------------------------------------------

print(
    "Sharpening 결과 저장 완료"
)
```

# 21. Threshold는 무엇을 하는 기술인가요?

현재 병뚜껑 이미지는 Gray로 바꾸어도 픽셀값이 모두 똑같지 않습니다.

예를 들어:

```
병뚜껑
→ 어두운 픽셀

배경
→ 밝은 픽셀
```

이라고 생각할 수 있습니다.

Threshold는 하나의 기준값을 정해서 픽셀을 두 그룹으로 나누는 방법입니다.

![[Pasted image 20260828171152.png]]

예를 들어:

```
Threshold = 120
```

으로 정하면 이번 병뚜껑 실습에서는:

```
0 ~ 119
→ 어두운 영역
→ 병뚜껑 후보

120 ~ 255
→ 밝은 영역
→ 배경 후보
```

처럼 나눌 수 있습니다.

이번 병뚜껑은 원래 어두운 색이고 배경은 밝은 색입니다.

그래서 Threshold 결과를 보기 쉽게 반대로 바꿉니다. 그것이 **Inverse Binary** 입니다.

```
어두운 병뚜껑
→ 흰색으로 표시

밝은 배경
→ 검정색으로 표시
```

즉, 병뚜껑 부분만 흰색 객체처럼 보이게 만들어서, 다음 단계에서 병뚜껑 영역을 쉽게 찾기 위한 방법입니다.

---

## 21.1 Threshold 값은 왜 여러 개 비교하나요?

Threshold는 Gray 이미지의 밝기값을 기준으로 객체와 배경을 나누는 기준선입니다.

문제는 이미지마다 밝기가 다르기 때문에 처음부터 어떤 값이 가장 적절한지 알 수 없다는 것입니다.

예를 들어 이번 실습에서는 다음 세 값을 비교합니다.

```
Threshold = 80
Threshold = 120
Threshold = 160
```

같은 이미지라도 기준값이 달라지면 흰색으로 선택되는 영역이 달라집니다.

```
같은 Gray 이미지
       ↓
 ┌─────┼─────┐
 ↓     ↓     ↓
 80   120   160
 ↓     ↓     ↓
병뚜껑이 선택되는 범위가 달라짐
```

따라서 이번 실습의 목적은 80, 120, 160 중 정답을 외우는 것이 아니라, Threshold 값에 따라 객체와 배경의 분리 결과가 어떻게 달라지는지 직접 확인하는 것입니다.

이후에는 사람이 값을 하나씩 정하지 않아도 되도록 Otsu가 이미지의 밝기 분포를 보고 기준값을 자동으로 선택하는 방법도 비교합니다.

---

## 21.2 Otsu는 무엇이 다른가요?

![[Pasted image 20260828172449.png]]

고정 Threshold에서는 사람이 값을 정합니다.

```
사람
→ 80?
→ 120?
→ 160?
```

반면 Otsu는 Gray 이미지의 밝기 분포를 분석하여 객체와 배경을 나누기 위한 Threshold 값을 자동으로 계산합니다.

```
고정 Threshold 
→ 사람이 값 선택 

Otsu 
→ 이미지에서 값 자동 계산
```

하지만 Otsu도 항상 정답은 아닙니다.

```
조명이 고르지 않음

배경이 복잡함

반사가 심함

제품과 배경의 밝기가 너무 비슷함
```

따라서 Otsu도 자동 정답이 아니라 객체 분리를 위한 하나의 방법으로 이해합니다.

# 22. `15_threshold_otsu.py` — 저대비 영상에서 객체 분리 비교하기

![[Pasted image 20260828173424.png]]

앞의 `12_clahe.py`에서는 기준 ROI 이미지로부터 일부러 밝기 차이를 줄인 저대비 이미지를 만들었습니다.

```
samples/day02/low_contrast.jpg
```

이번 실습에서는 이 이미지를 Gray로 변환한 뒤, Threshold 기준값에 따라 병뚜껑과 배경이 어떻게 다르게 분리되는지 확인합니다.

```
low_contrast.jpg
        ↓
      Gray
        ↓
 ┌───────────────┐
 │               │
고정 Threshold    Otsu
80 / 120 / 160    자동 선택
 │               │
 └───────┬───────┘
         ↓
   Binary 결과 비교
```

고정 Threshold에서는 사람이 `80`, `120`, `160`처럼 기준값을 직접 정합니다.

반면 Otsu는 이미지의 밝기 분포를 분석하여 객체와 배경을 나누기 위한 기준값을 자동으로 계산합니다.

이번 단계에서 확인할 핵심은 하나입니다.

같은 이미지라도 Threshold 기준값에 따라 객체와 배경의 분리 결과가 크게 달라질 수 있다.

따라서 여기서는 어떤 값이 정답인지 결정하는 것이 아니라,

```
Threshold 값 변경
       ↓
흰색으로 선택되는 영역 변화
       ↓
병뚜껑과 배경의 분리 결과 변화
```

를 직접 확인합니다.

아직 이 단계에서는 CLAHE가 좋은지, Gaussian이 좋은지 비교하지 않습니다.

다음 `16_preprocess_compare.py`에서 동일한 Otsu 방식을 적용하여:

```
원본 + Otsu

Gaussian + Otsu

CLAHE + Otsu
```

즉 두 실습의 역할을 나누면 다음과 같습니다.

```
15_threshold_otsu.py
→ Threshold 기준값에 따라
  분리 결과가 어떻게 달라지는지 이해

16_preprocess_compare.py
→ 앞에서 배운 전처리가
  실제 객체 분리에 도움이 되었는지 확인
```

이렇게 이해하면 됩니다.

15번은 Threshold 자체를 이해하는 실습이고, 16번은 전처리 효과를 Threshold 결과로 검증하는 실습입니다.

```python
    )


    # --------------------------------------------------
    # 6. 기준 이미지를 정상적으로 읽었는지 확인한다.
    #
    #    기준 이미지도 읽지 못하면
    #    FileNotFoundError를 발생시킨다.
    # --------------------------------------------------

    if reference is None:
        raise FileNotFoundError(
            f"기준 이미지를 읽지 못했습니다: "
            f"{reference_path}"
        )


    # --------------------------------------------------
    # 7. 기준 이미지의 대비를 낮추고 저장한다.
    #
    #    alpha=0.35 → 밝기 차이를 줄인다.
    #    beta=80    → 픽셀값에 80을 더한다.
    #
    #    결과를 low_contrast.jpg로 저장한다.
    # --------------------------------------------------

    image = cv2.convertScaleAbs(
        reference,
        alpha=0.35,
        beta=80,
    )

    cv2.imwrite(
        str(low_contrast_path),
        image,
    )

    print(
        "문제 이미지 생성:",
        low_contrast_path,
    )


# --------------------------------------------------
# 8. 저대비 이미지를 Gray로 변환한다.
#
#    BGR → Gray
#
#    밝기값을 기준으로 이진화하기 위해
#    컬러 이미지를 1채널 Gray로 변환한다.
# --------------------------------------------------

gray = cv2.cvtColor(
    image,
    cv2.COLOR_BGR2GRAY,
)


# --------------------------------------------------
# 9. Gray 이미지를 저장한다.
#
#    이진화 전의 이미지이다.
#    Threshold 결과와 비교할 기준으로 사용한다.
# --------------------------------------------------

cv2.imwrite(
    str(output_dir / "gray.jpg"),
    gray,
)


# --------------------------------------------------
# 10. 고정 Threshold 값을 준비한다.
#
#     80, 120, 160을 각각 비교한다.
#
#     이 값은 사람이 직접 지정한 임계값이다.
# --------------------------------------------------

threshold_values = [
    80,
    120,
    160,
]


# --------------------------------------------------
# 11. Threshold 값을 하나씩 가져와 반복한다.
#
#     첫 번째: 80
#     두 번째: 120
#     세 번째: 160
# --------------------------------------------------

for value in threshold_values:

    # --------------------------------------------------
    # 12. 현재 Threshold 값으로 이진화를 수행한다.
    #
    #     gray  → 입력 이미지
    #     value → 현재 임계값
    #     255   → 흰색 픽셀값
    #
    #     THRESH_BINARY_INV:
    #     임계값 이하 → 흰색(255)
    #     임계값 초과 → 검정색(0)
    #
    #     어두운 병뚜껑을 흰색 영역으로 표현한다.
    # --------------------------------------------------

    _, binary = cv2.threshold(
        gray,
        value,
        255,
        cv2.THRESH_BINARY_INV,
    )


    # --------------------------------------------------
    # 13. 현재 Threshold 결과 이미지를 저장한다.
    #
    #     threshold_80.jpg
    #     threshold_120.jpg
    #     threshold_160.jpg
    #
    #     저장 후 다음 임계값으로 반복한다.
    # --------------------------------------------------

    output_path = (
        output_dir
        / f"threshold_{value}.jpg"
    )

    cv2.imwrite(
        str(output_path),
        binary,
    )

    print(
        "저장:",
        output_path,
    )


# --------------------------------------------------
# 14. 같은 Gray 이미지에 Otsu 이진화를 적용한다.
#
#     고정 Threshold:
#     → 사람이 80, 120, 160을 지정했다.
#
#     Otsu:
#     → 이미지의 밝기 분포를 분석하여
#       임계값을 자동으로 계산한다.
#
#     THRESH_BINARY_INV:
#     → 어두운 병뚜껑을 흰색으로 표현한다.
#
#     otsu_value → 자동 계산된 임계값
#     otsu       → 이진화 결과 이미지
# --------------------------------------------------

otsu_value, otsu = cv2.threshold(
    gray,
    0,
    255,
    cv2.THRESH_BINARY_INV
    + cv2.THRESH_OTSU,
)


# --------------------------------------------------
# 15. Otsu 결과를 저장하고 임계값을 출력한다.
#
#     otsu.jpg → 자동 이진화 결과
#
#     최종적으로 다음 이미지를 비교한다.
#
#     gray.jpg
#     threshold_80.jpg
#     threshold_120.jpg
#     threshold_160.jpg
#     otsu.jpg
# --------------------------------------------------

otsu_path = (
    output_dir / "otsu.jpg"
)

cv2.imwrite(
    str(otsu_path),
    otsu,
)

print(
    "Otsu Threshold:",
    otsu_value,
)

print(
    "저장:",
    otsu_path,
)
```

### 이번 실습에서 확인한 핵심

같은 이미지라도 Threshold 기준값에 따라 Binary 결과가 완전히 달라질 수 있습니다.

현재 결과에서는 `120`과 `Otsu`가 비교적 좋은 후보로 보이지만, 아직 최종 선택은 아닙니다.

> 다음 실습에서는 전처리를 적용한 뒤 Otsu 결과가 더 안정적으로 바뀌는지 비교합니다.

즉 이번 실습의 핵심은 “120을 외우는 것”이 아니라, 너무 낮거나 높은 Threshold 값이 왜 객체 분리를 실패하게 만드는지 이해하는 것입니다.

```python

from pathlib import Path

import cv2


# --------------------------------------------------
# 1. 사용할 이미지와 결과 저장 경로를 정한다.
#
#    reference_path
#    → 1일차에서 만든 병뚜껑 기준 ROI 이미지
#
#    low_contrast_path
#    → 대비를 낮춘 실습용 이미지
#
#    output_dir
#    → 전처리 비교 결과를 저장할 폴더
# --------------------------------------------------

reference_path = Path(
    "samples/day02/cap_on_reference.jpg"
)

low_contrast_path = Path(
    "samples/day02/low_contrast.jpg"
)

output_dir = Path(
    "outputs/day02/compare"
)


# --------------------------------------------------
# 2. 결과 이미지를 저장할 폴더를 생성한다.
#
#    폴더가 없다면 새로 만든다.
#    이미 존재한다면 그대로 사용한다.
# --------------------------------------------------

output_dir.mkdir(
    parents=True,
    exist_ok=True,
)


# --------------------------------------------------
# 3. 저대비 이미지 low_contrast.jpg를 읽는다.
#
#    앞의 CLAHE 실습에서 만든 이미지를 재사용한다.
# --------------------------------------------------

image = cv2.imread(
    str(low_contrast_path)
)


# --------------------------------------------------
# 4. 저대비 이미지를 정상적으로 읽었는지 확인한다.
#
#    image가 None이면 5~6번을 실행한다.
#    정상적으로 읽었다면 5~6번을 건너뛴다.
# --------------------------------------------------

if image is None:

    print(
        "low_contrast.jpg가 없어 "
        "기준 이미지에서 생성합니다."
    )


    # --------------------------------------------------
    # 5. 병뚜껑 기준 ROI 이미지를 읽고 확인한다.
    #
    #    저대비 이미지를 다시 만들기 위한 원본이다.
    #    읽지 못했다면 오류를 발생시킨다.
    # --------------------------------------------------

    reference = cv2.imread(
        str(reference_path)
    )

    if reference is None:
        raise FileNotFoundError(
            f"기준 이미지를 읽지 못했습니다: "
            f"{reference_path}"
        )


    # --------------------------------------------------
    # 6. 기준 이미지의 Contrast를 낮추고 저장한다.
    #
    #    alpha=0.35 → 픽셀값의 차이를 줄인다.
    #    beta=80    → 픽셀값에 80을 더한다.
    #
    #    결과를 low_contrast.jpg로 저장한다.
    # --------------------------------------------------

    image = cv2.convertScaleAbs(
        reference,
        alpha=0.35,
        beta=80,
    )

    cv2.imwrite(
        str(low_contrast_path),
        image,
    )

    print(
        "문제 이미지 생성:",
        low_contrast_path,
    )


# --------------------------------------------------
# 7. 저대비 이미지를 Gray로 변환한다.
#
#    BGR → Gray
#
#    병뚜껑과 배경의 밝기 차이를 이용하여
#    다음 이진화 실습을 진행한다.
# --------------------------------------------------

gray = cv2.cvtColor(
    image,
    cv2.COLOR_BGR2GRAY,
)


# --------------------------------------------------
# 8. 전처리 없이 Otsu 이진화를 적용한다.
#
#    Gray 이미지에 별도의 개선 처리를 하지 않고
#    Otsu를 바로 적용한다.
#
#    THRESH_BINARY_INV:
#    → 어두운 병뚜껑을 흰색 객체로 표현
#
#    original_value
#    → Otsu가 자동으로 선택한 임계값
#
#    original_otsu
#    → 이진화 결과 이미지
# --------------------------------------------------

original_value, original_otsu = cv2.threshold(
    gray,
    0,
    255,
    cv2.THRESH_BINARY_INV
    + cv2.THRESH_OTSU,
)


# --------------------------------------------------
# 9. 같은 Gray 이미지에 Gaussian Blur를 적용한다.
#
#    Kernel = 5×5
#
#    주변 픽셀의 가중 평균을 이용해
#    Noise를 부드럽게 줄인다.
#
#    결과를 gaussian 변수에 저장한다.
# --------------------------------------------------

gaussian = cv2.GaussianBlur(
    gray,
    (5, 5),
    0,
)


# --------------------------------------------------
# 10. Gaussian Blur 결과에 Otsu를 적용한다.
#
#     Gaussian으로 처리한 이미지를 이진화한다.
#
#     gaussian_value
#     → 자동 계산된 임계값
#
#     gaussian_otsu
#     → 이진화 결과 이미지
# --------------------------------------------------

gaussian_value, gaussian_otsu = cv2.threshold(
    gaussian,
    0,
    255,
    cv2.THRESH_BINARY_INV
    + cv2.THRESH_OTSU,
)


# --------------------------------------------------
# 11. CLAHE 객체를 생성한다.
#
#     clipLimit=2.0
#     → 지역 대비 향상 강도 설정
#
#     tileGridSize=(8, 8)
#     → 이미지를 가로 8개, 세로 8개 구역으로 나눔
#
#     CLAHE는 지역별 Contrast를 개선하는 방법이다.
# --------------------------------------------------

clahe = cv2.createCLAHE(
    clipLimit=2.0,
    tileGridSize=(8, 8),
)


# --------------------------------------------------
# 12. 같은 Gray 이미지에 CLAHE를 적용한다.
#
#     병뚜껑과 주변 배경의 지역적인
#     밝기 차이를 개선한다.
#
#     결과를 clahe_image에 저장한다.
# --------------------------------------------------

clahe_image = clahe.apply(
    gray
)


# --------------------------------------------------
# 13. CLAHE 결과에 Otsu 이진화를 적용한다.
#
#     CLAHE로 개선한 이미지에서
#     병뚜껑과 배경을 분리한다.
#
#     clahe_value
#     → 자동 계산된 임계값
#
#     clahe_otsu
#     → 이진화 결과 이미지
# --------------------------------------------------

clahe_value, clahe_otsu = cv2.threshold(
    clahe_image,
    0,
    255,
    cv2.THRESH_BINARY_INV
    + cv2.THRESH_OTSU,
)


# --------------------------------------------------
# 14. 세 가지 Otsu 임계값을 출력한다.
#
#     Original + Otsu
#     Gaussian + Otsu
#     CLAHE + Otsu
#
#     입력 이미지가 다르므로
#     Otsu가 선택한 임계값도 달라질 수 있다.
# --------------------------------------------------

print(
    "Original Otsu:",
    original_value,
)

print(
    "Gaussian Otsu:",
    gaussian_value,
)

print(
    "CLAHE Otsu:",
    clahe_value,
)


# --------------------------------------------------
# 15. 비교 화면에 사용할 이미지 크기를 정한다.
#
#     가로 = 400px
#     세로 = 300px
#
#     네 장의 이미지를 같은 크기로 표시한다.
# --------------------------------------------------

view_size = (
    400,
    300,
)


# --------------------------------------------------
# 16. 비교 화면을 만드는 make_view() 함수를 정의한다.
#
#     source    → 표시할 이미지
#     title     → 이미지 위에 표시할 제목
#     is_binary → 이진화 이미지 여부
#
#     함수 내부 처리:
#
#     ① 이미지에 맞는 크기 변경 방법을 선택한다.
#     ② 이미지를 400×300으로 변경한다.
#     ③ Gray 이미지를 화면용 BGR로 변환한다.
#     ④ 이미지 위쪽에 검정색 제목 영역을 만든다.
#     ⑤ 제목을 흰색 글자로 표시한다.
#     ⑥ 완성된 화면 이미지를 반환한다.
#
#     함수는 여기서 정의만 하며,
#     실제 실행은 17~18번에서 호출할 때 이루어진다.
# --------------------------------------------------

def make_view(
    source,
    title,
    is_binary=False,
):

    # 이진화 이미지는 픽셀값이 섞이지 않도록
    # 가장 가까운 픽셀을 사용하는 방법으로 변경
    if is_binary:
        interpolation = cv2.INTER_NEAREST
    else:
        interpolation = cv2.INTER_AREA

    # 비교 화면 크기로 변경
    resized = cv2.resize(
        source,
        view_size,
        interpolation=interpolation,
    )

    # Gray 이미지라면 화면용 BGR로 변환
    if len(resized.shape) == 2:
        canvas = cv2.cvtColor(
            resized,
            cv2.COLOR_GRAY2BGR,
        )
    else:
        canvas = resized.copy()

    # 이미지 상단에 제목 영역 생성
    cv2.rectangle(
        canvas,
        (0, 0),
        (view_size[0], 40),
        (0, 0, 0),
        -1,
    )

    # 제목 표시
    cv2.putText(
        canvas,
        title,
        (10, 27),
        cv2.FONT_HERSHEY_SIMPLEX,
        0.6,
        (255, 255, 255),
        2,
    )

    return canvas


# --------------------------------------------------
# 17. 비교 화면의 위쪽 두 이미지를 만든다.
#
#     왼쪽:
#     Low Contrast Gray
#     → 저대비 Gray 이미지
#
#     오른쪽:
#     Original + Otsu
#     → 별도 전처리 없이 Otsu 적용
#
#     cv2.hconcat()
#     → 이미지를 가로 방향으로 연결한다.
# --------------------------------------------------

top = cv2.hconcat(
    [
        make_view(
            gray,
            "Low Contrast Gray",
        ),
        make_view(
            original_otsu,
            "Original + Otsu",
            is_binary=True,
        ),
    ]
)


# --------------------------------------------------
# 18. 비교 화면의 아래쪽 두 이미지를 만든다.
#
#     왼쪽:
#     Gaussian + Otsu
#
#     오른쪽:
#     CLAHE + Otsu
#
#     두 이미지를 가로로 연결한다.
# --------------------------------------------------

bottom = cv2.hconcat(
    [
        make_view(
            gaussian_otsu,
            "Gaussian + Otsu",
            is_binary=True,
        ),
        make_view(
            clahe_otsu,
            "CLAHE + Otsu",
            is_binary=True,
        ),
    ]
)


# --------------------------------------------------
# 19. 위쪽과 아래쪽 이미지를 세로로 연결한다.
#
#     cv2.vconcat()
#     → 이미지를 세로 방향으로 연결한다.
#
#     최종 2×2 비교 화면을 만든다.
#
#     ┌───────────────────┬───────────────────┐
#     │ Low Contrast Gray │ Original + Otsu   │
#     ├───────────────────┼───────────────────┤
#     │ Gaussian + Otsu   │ CLAHE + Otsu      │
#     └───────────────────┴───────────────────┘
# --------------------------------------------------

compare = cv2.vconcat(
    [
        top,
        bottom,
    ]
)


# --------------------------------------------------
# 20. 최종 비교 이미지를 저장하고 경로를 출력한다.
#
#     저장 파일:
#     outputs/day02/compare/preprocess_compare.png
#
#     저장한 이미지를 직접 열어
#     병뚜껑과 배경의 분리 결과를 비교한다.
# --------------------------------------------------

output_path = (
    output_dir
    / "preprocess_compare.png"
)

cv2.imwrite(
    str(output_path),
    compare,
)

print(
    "저장:",
    output_path,
)
```

# 25. 전처리가 실제 검사에 도움이 되었는지 판단합니다

이제 앞에서 관찰한 결과를 바탕으로 판단합니다.

이번 결과에서는:

```
Original + Otsu
→ 전처리 없이도 비교적 잘 분리됨

Gaussian + Otsu
→ 큰 개선은 없고 일부 경계가 단순해짐

CLAHE + Otsu
→ 일부 영역은 강조되지만
   불필요한 영역도 함께 나타남
```

따라서 이번 이미지에서는 **전처리를 추가했다고 반드시 객체 분리가 좋아진 것은 아닙니다.**

```
전처리 적용
     ↓
무조건 좋아지는 것은 아님

Otsu 결과 비교
     ↓
실제로 도움이 되는 경우에만 사용
```

현재 결과에서는 `Original + Otsu`도 충분한 후보입니다.

> 전처리를 사용하지 않는 것이 더 안정적이라면, 추가 전처리를 하지 않는 것도 올바른 판단입니다.

그런데 모든 영상 품질 문제를 전처리로 해결할 수 있을까요?

이번 실습에서는 새로운 Python 코드를 작성하지 않습니다. 두 사진을 직접 비교하고, 촬영환경이 객체 분리에 미치는 영향을 이해하는 것이 목적입니다.

두 이미지의 촬영 거리나 각도가 다르다면 경계 위치를 정확하게 비교하기 어렵기 때문에, 여기서는 주로 **강한 반사가 영상 정보를 얼마나 알아보기 어렵게 만드는지** 확인합니다.

## 26.2 두 이미지를 비교합니다

먼저 `cap_on_reference.jpg`를 열어 병뚜껑의 외곽선과 세로 홈, 주변 배경과의 밝기 차이를 확인합니다.

그다음 `glare.jpg`를 열어 같은 부분을 살펴봅니다.

다음 질문에 답해 봅니다.

1. 기준 이미지에서는 병뚜껑의 외곽선이 잘 보이나요?
    
2. `glare.jpg`에서는 빛이 강하게 반사되어 하얗게 보이는 부분이 있나요?
    
3. 그 반사 영역에서 병뚜껑의 홈이나 경계를 구분하기 어려운가요?
    
4. 병뚜껑과 배경의 경계가 반사 때문에 이어져 보이거나 사라진 것처럼 보이는 부분이 있나요?
    

여기서 중요한 것은 `glare.jpg`가 얼마나 밝은지 평가하는 것이 아닙니다.

**강한 반사 때문에 컴퓨터가 검사에 사용할 병뚜껑의 형태와 경계 정보를 구분하기 어려워졌는지** 확인하는 것입니다.

## 26.3 강한 반사가 왜 문제가 될까요?

일반적인 8비트 Gray 이미지에서 픽셀 밝기는 `0~255` 범위로 표현됩니다.

```
0   → 가장 어두운 값
255 → 가장 밝은 값
```

촬영할 때 조명이 너무 강해 특정 영역이 센서에서 포화되면, 원래 서로 다른 밝기를 가지고 있던 표면도 동일한 최대 밝기값으로 기록될 수 있습니다.

```
강한 조명
    ↓
병뚜껑 표면에서 빛 반사
    ↓
일부 영역의 픽셀 포화
    ↓
서로 다른 표면 정보가
비슷한 밝기값으로 기록됨
    ↓
병뚜껑의 홈과 경계 구분이 어려워짐
    ↓
Otsu 이진화에서도
객체와 배경 분리가 어려워질 수 있음
```

이처럼 포화로 정보가 손실되면 Brightness를 낮추거나 CLAHE를 적용해도 원래의 세부정보를 완전히 복구할 수 없습니다.

단, 사진이 하얗게 보인다고 반드시 모든 픽셀이 포화되었다는 뜻은 아닙니다. 이번에는 육안으로 **반사와 정보 손실이 의심되는 영역**을 관찰합니다. 실제 포화 여부를 정확히 확인하려면 픽셀값을 별도로 측정해야 합니다.

## 26.4 촬영환경을 어떻게 개선할 수 있을까요?

`glare.jpg`에서 병뚜껑의 일부가 빛에 가려 잘 보이지 않는다면, 어떤 방법이 적절할지 생각해 봅니다.

|개선 방법|기대하는 효과|
|---|---|
|조명 각도 변경|강한 반사가 카메라로 직접 들어오는 현상을 줄입니다.|
|조명 밝기 조절|지나치게 밝은 영역의 포화를 줄일 수 있습니다.|
|카메라 위치·각도 조정|반사가 발생하는 위치를 바꾸어 병뚜껑의 경계를 더 잘 보이게 할 수 있습니다.|

이 방법들은 이미 촬영된 사진을 수정하는 것이 아니라, **새로운 사진을 촬영할 때 검사에 필요한 정보를 제대로 확보하기 위한 방법**입니다.

## 26.5 이번 실습의 결과를 정리합니다

두 사진을 비교한 뒤 다음 세 가지 질문에 답해 봅니다.

**질문 1.** `glare.jpg`에서 기준 이미지보다 구분하기 어려워진 병뚜껑의 부분은 어디인가요?

**질문 2.** 빛이 강하게 반사된 영역에서는 Otsu 이진화로 병뚜껑과 배경을 정확하게 분리하기 어려울 가능성이 있나요? 그렇게 판단한 이유는 무엇인가요?

**질문 3.** 이러한 문제를 줄이기 위해 조명 밝기, 조명 각도, 카메라 위치 중 무엇을 먼저 변경해 보고 싶나요?

이번 실습은 Otsu 결과를 실제로 계산하여 비교하는 단계가 아니므로, 2번 질문은 지금까지 배운 내용을 바탕으로 **예상되는 문제를 설명**하면 됩니다.

### 이번 실습의 핵심 정리

지금까지는 전처리 기술을 적용하여 영상 품질을 개선하는 방법을 배웠습니다.

하지만 강한 반사로 촬영 단계에서 중요한 정보가 손실되었다면 전처리만으로는 이를 완전히 복구할 수 없습니다.

따라서 머신비전에서는 다음 두 가지를 구분해야 합니다.

```
영상에 정보가 남아 있지만
밝기·대비·Noise 때문에 구분이 어려운 경우
    ↓
영상 전처리로 개선 가능한지 검토

촬영 단계에서 강한 반사나 포화로
검사에 필요한 정보가 손실된 경우
    ↓
조명·카메라 등 촬영환경 개선 검토
```

> **핵심:** 머신비전의 목적은 이미지를 무조건 선명하게 만드는 것이 아니라, 검사에 필요한 제품의 형태와 경계 정보를 안정적으로 확보하는 것입니다. 따라서 소프트웨어를 적용하기 전에 촬영환경 자체가 적절한지도 판단할 수 있어야 합니다.

---

핵심: 전처리가 가능한지 결정하는 것은 어둡거나 밝은 정도가 아니라, 검사에 필요한 원본 정보가 남아 있는가입니다.

- 어두운 이미지 → 정보가 남아 있다면 Brightness·Gamma로 개선 가능
    
- 저대비 이미지 → CLAHE로 개선 가능
    
- Noise가 있는 이미지 → Filter로 개선 가능
    
- 약간 흐린 이미지(Blur) → Sharpening으로 일부 개선 가능
    
- 강한 반사(Glare) → 픽셀이 포화되어 형체나 경계 정보가 사라졌다면 복구 어려움
    
- 심한 Blur → 원래 경계 정보가 손실되었다면 복구 어려움

```python
from pathlib import Path
import shutil

import cv2


image_path = Path(
    "samples/day02/challenge.jpg"
)

temp_dir = Path(
    "roi_temp"
)

backup_path = (
    temp_dir / "challenge_original.jpg"
)

temp_dir.mkdir(
    parents=True,
    exist_ok=True,
)


# --------------------------------------------------
# 이미지 읽기
# --------------------------------------------------

image = cv2.imread(
    str(image_path)
)

if image is None:
    raise FileNotFoundError(
        f"이미지를 읽지 못했습니다: {image_path}"
    )


# --------------------------------------------------
# 원본 백업
# --------------------------------------------------

if not backup_path.exists():

    shutil.copy2(
        image_path,
        backup_path,
    )

    print(
        "원본 백업:",
        backup_path,
    )


# --------------------------------------------------
# 화면 크기 조절
# --------------------------------------------------

height, width = image.shape[:2]

max_width = 900
max_height = 700

scale = min(
    1.0,
    max_width / width,
    max_height / height,
)

display_width = int(
    width * scale
)

display_height = int(
    height * scale
)

preview = cv2.resize(
    image,
    (
        display_width,
        display_height,
    ),
)


# --------------------------------------------------
# ROI 선택 변수
# --------------------------------------------------

start_point = None
end_point = None

dragging = False
roi_selected = False


# --------------------------------------------------
# 마우스 이벤트
# --------------------------------------------------

def mouse_callback(
    event,
    x,
    y,
    flags,
    param,
):

    global start_point
    global end_point
    global dragging
    global roi_selected

    # 마우스 왼쪽 버튼 누름
    if event == cv2.EVENT_LBUTTONDOWN:

        start_point = (
            x,
            y,
        )

        end_point = (
            x,
            y,
        )

        dragging = True
        roi_selected = False


    # 마우스를 누른 상태로 이동
    elif (
        event == cv2.EVENT_MOUSEMOVE
        and dragging
    ):

        end_point = (
            x,
            y,
        )


    # 마우스 버튼 놓음
    elif event == cv2.EVENT_LBUTTONUP:

        end_point = (
            x,
            y,
        )

        dragging = False
        roi_selected = True

        print(
            "ROI 선택:",
            start_point,
            "→",
            end_point,
        )


# --------------------------------------------------
# Window
# --------------------------------------------------

window_name = (
    "ROI - Drag and press ENTER"
)

cv2.namedWindow(
    window_name,
    cv2.WINDOW_AUTOSIZE,
)

cv2.setMouseCallback(
    window_name,
    mouse_callback,
)


print()
print("ROI 선택 방법")
print("-----------------------------")
print("1. 병뚜껑 왼쪽 위에서")
print("   마우스 왼쪽 버튼을 누릅니다.")
print()
print("2. 버튼을 누른 상태로")
print("   오른쪽 아래까지 드래그합니다.")
print()
print("3. 마우스를 놓습니다.")
print()
print("4. 초록색 사각형을 확인합니다.")
print()
print("5. ENTER 또는 SPACE : 저장")
print("6. C : 다시 선택")
print("7. ESC : 취소")
print("-----------------------------")
print()


# --------------------------------------------------
# ROI 선택 화면
# --------------------------------------------------

while True:

    canvas = preview.copy()

    if (
        start_point is not None
        and end_point is not None
    ):

        cv2.rectangle(
            canvas,
            start_point,
            end_point,
            (0, 255, 0),
            2,
        )

    cv2.imshow(
        window_name,
        canvas,
    )

    key = (
        cv2.waitKey(20)
        & 0xFF
    )


    # ESC
    if key == 27:

        cv2.destroyAllWindows()

        print(
            "ROI 선택 취소"
        )

        raise SystemExit


    # C
    if key in (
        ord("c"),
        ord("C"),
    ):

        start_point = None
        end_point = None

        dragging = False
        roi_selected = False

        print(
            "ROI 다시 선택"
        )


    # ENTER 또는 SPACE
    if key in (
        13,
        10,
        32,
    ):

        if not roi_selected:

            print(
                "먼저 ROI를 드래그하세요."
            )

            continue

        break


cv2.destroyAllWindows()


# --------------------------------------------------
# 좌표 정리
# --------------------------------------------------

x1, y1 = start_point
x2, y2 = end_point

left = min(
    x1,
    x2,
)

right = max(
    x1,
    x2,
)

top = min(
    y1,
    y2,
)

bottom = max(
    y1,
    y2,
)


# --------------------------------------------------
# 화면 좌표 → 원본 좌표
# --------------------------------------------------

left = int(
    left / scale
)

right = int(
    right / scale
)

top = int(
    top / scale
)

bottom = int(
    bottom / scale
)


# --------------------------------------------------
# ROI Crop
# --------------------------------------------------

roi = image[
    top:bottom,
    left:right,
]

if roi.size == 0:

    raise ValueError(
        "ROI 영역이 올바르지 않습니다."
    )


# --------------------------------------------------
# ROI 저장
# --------------------------------------------------

cv2.imwrite(
    str(image_path),
    roi,
)


print()
print("ROI 저장 완료")
print("-----------------------------")
print("left   :", left)
print("top    :", top)
print("right  :", right)
print("bottom :", bottom)
print()
print(
    "저장:",
    image_path,
)
```

# 29. 필요한 전처리 후보를 선택합니다

ROI로 자른 `challenge.jpg`를 다시 확인합니다.

이번 이미지에서는 병뚜껑이 밝은 색이고 주변 배경도 회색 계열이므로 다음을 먼저 관찰합니다.

```
병뚜껑과 배경의 밝기 차이가 충분한가?

병뚜껑의 외곽 경계가 잘 보이는가?

세로 홈과 작은 형태가 유지되는가?

전체 이미지가 너무 어둡거나 뿌옇지는 않은가?

전처리를 하지 않아도
객체와 배경이 충분히 분리될 수 있는가?
```

문제를 정의한 뒤 필요한 기술만 후보로 선택합니다.

예:

```
전체 밝기가 부족하다
→ Brightness / Gamma

병뚜껑과 배경의 대비가 약하다
→ Contrast / CLAHE

경계가 약하다
→ Sharpening

현재 상태로 충분하다
→ 전처리 미사용
```

# 30. `17_day02_challenge.py`를 완성합니다

```
src/17_day02_challenge.py
```

강사는 기본 구조와 Otsu 비교 코드까지 제공합니다.

학생은 **TODO 부분에서 자신이 선택한 전처리만 작성**합니다.

```python
from pathlib import Path

import cv2


image_path = Path(
    "samples/day02/challenge.jpg"
)

output_dir = Path(
    "outputs/day02/challenge"
)

output_dir.mkdir(
    parents=True,
    exist_ok=True,
)


image = cv2.imread(
    str(image_path)
)

if image is None:
    raise FileNotFoundError(
        f"이미지를 읽지 못했습니다: {image_path}"
    )


# --------------------------------------------------
# TODO
#
# 1. 이미지의 문제를 판단합니다.
# 2. 필요한 전처리를 선택합니다.
# 3. Parameter를 직접 정합니다.
# 4. result에 최종 결과를 저장합니다.
# --------------------------------------------------


result = image.copy()


# --------------------------------------------------
# 전처리 결과 저장
# --------------------------------------------------

result_path = (
    output_dir
    / "challenge_result.jpg"
)

cv2.imwrite(
    str(result_path),
    result,
)


# --------------------------------------------------
# Gray 변환
# --------------------------------------------------

def to_gray(source):

    if len(source.shape) == 2:
        return source

    return cv2.cvtColor(
        source,
        cv2.COLOR_BGR2GRAY,
    )


original_gray = to_gray(
    image
)

result_gray = to_gray(
    result
)


# --------------------------------------------------
# 전처리 전 Otsu
#
# 이번 Challenge에서는
# 밝은 병뚜껑을 흰색 객체로 확인합니다.
# --------------------------------------------------

_, original_otsu = cv2.threshold(
    original_gray,
    0,
    255,
    cv2.THRESH_BINARY
    + cv2.THRESH_OTSU,
)


# --------------------------------------------------
# 전처리 후 Otsu
# --------------------------------------------------

_, result_otsu = cv2.threshold(
    result_gray,
    0,
    255,
    cv2.THRESH_BINARY
    + cv2.THRESH_OTSU,
)


cv2.imwrite(
    str(
        output_dir
        / "challenge_original_otsu.jpg"
    ),
    original_otsu,
)

cv2.imwrite(
    str(
        output_dir
        / "challenge_result_otsu.jpg"
    ),
    result_otsu,
)


print("입력 :", image_path)
print("결과 :", result_path)
print("Challenge 완료")
```

학생이 직접 수정하는 핵심 부분은:

```python
result = image.copy()
```

선택한 전처리를 적용한 결과를 `result`에 저장합니다.

### 왜 앞 실습과 Threshold 방식이 다른가요?

앞에서 사용한 기준 이미지는 검은 병뚜껑이었기 때문에:

```
어두운 병뚜껑
→ 흰색 객체
```

로 만들기 위해 `THRESH_BINARY_INV`를 사용했습니다.

이번 Challenge에서는 병뚜껑이 밝은 색이므로:

```
밝은 병뚜껑
→ 흰색 객체
```

로 보기 위해 `THRESH_BINARY`를 사용합니다.

> Threshold 방식도 항상 하나를 외우는 것이 아니라 검사할 객체를 어떻게 분리할 것인지에 따라 선택합니다.
