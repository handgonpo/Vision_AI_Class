예를 들어 병뚜껑을 검사한다고 생각해 봅니다.

사람은 다음처럼 말할 수 있습니다.

```text
뚜껑이 있다.
→ 정상

뚜껑이 없다.
→ 불량
```

그러나 컴퓨터에게는 이 표현만으로 검사를 시킬 수 없습니다.

컴퓨터가 계산할 수 있는 값으로 바꾸어야 합니다.

![[Pasted image 20260827115916.png]]

```text
병 이미지
    ↓
병뚜껑이 있어야 하는 부분을 본다.
    ↓
그 영역에서 측정할 특징을 찾는다.
    ↓
예: 면적
    ↓
나중에 정상 범위와 비교한다.
    ↓
OK / NG
```

오늘은 아직 실제 면적 기준을 결정하지 않습니다.

먼저 다음 두 가지를 해보는 것이 목표입니다.

```text

```

# 7. 실습 이미지 준비하기

오늘은 전체 데이터셋이 필요하지 않습니다.

먼저 서로 조금 다른 이미지 5~10장 정도를 `samples`에 준비합니다.

예:

```text
samples/
├── sample01.jpg
├── sample02.jpg
├── sample03.jpg
├── sample04.jpg
└── sample05.jpg
```

가능하면 정상과 불량 또는 제품 위치가 조금씩 다른 이미지를 함께 준비합니다.

예를 들어 병뚜껑 실습이라면 다음과 같은 이미지가 좋습니다.

```text
sample01.jpg → 정상, 제품 중앙
sample02.jpg → 정상, 조금 왼쪽
sample03.jpg → 정상, 조금 오른쪽
sample04.jpg → 뚜껑 없음
sample05.jpg → 조명이나 위치가 다른 이미지
```

# 10. ROI를 직접 정해 보기

## 10.1 ROI란 무엇인가요?

ROI는 `Region Of Interest`의 약자입니다.

전체 이미지 중에서 실제로 검사할 영역을 의미합니다.

예를 들어 검사 대상이 병뚜껑이라면 병 전체를 항상 계산할 필요는 없습니다.

![[Pasted image 20260827140708.png]]

ROI를 사용하는 이유는 다음과 같습니다.

```text
전체 장면
→ 필요한 부분만 선택
→ 불필요한 배경 감소
→ 검사할 특징에 집중
```

오늘은 ROI를 자동으로 찾지 않습니다.

먼저 좌표를 직접 정해 보면서 검사 영역을 정하는 것이 왜 중요한지 경험합니다.

---

## 10.2 OpenCV에서 ROI 좌표 사용하기

이미지에서 원하는 부분만 잘라내려면 왼쪽 위 좌표와 오른쪽 아래 좌표를 정합니다.

예를 들어 병뚜껑 부분을 다음처럼 선택했다고 생각합니다.

```
(x1, y1) ┌──────────┐
         │  병뚜껑   │
         │   ROI    │
         └──────────┘ (x2, y2)
```

좌표의 의미는 다음과 같습니다.

```
x = 가로 위치
y = 세로 위치
```

예:

```python
x1 = 200
y1 = 100
x2 = 700
y2 = 500
```

OpenCV에서 이미지를 실제로 자를 때는 다음과 같이 작성합니다.

```python
roi = image[y1:y2, x1:x2]
```

처음 보면 `x`와 `y`의 순서가 반대로 보여 헷갈릴 수 있습니다.

OpenCV의 이미지 배열에서는 세로(y)를 먼저 쓰고, 가로(x)를 나중에 씁니다.

```
우리가 좌표를 생각할 때
(x, y)

OpenCV에서 이미지를 자를 때
[y, x]
```

따라서 이것만 기억하면 됩니다.

> 좌표를 정할 때는 `(x, y)`, 이미지를 자를 때는 `[y, x]` 순서입니다.

처음에는 좌표를 정확하게 계산하려고 하기보다, ROI를 잘라 저장한 뒤 원하는 병뚜껑 부분이 제대로 잘렸는지 직접 눈으로 확인하면 됩니다.

```python

image_path = Path("samples/sample01.jpg")
output_dir = Path("outputs/roi")

image = cv2.imread(str(image_path))

if image is None:
    raise FileNotFoundError(image_path)

x1 = 200
y1 = 100
x2 = 700
y2 = 500

# 좌표가 이미지 범위를 벗어나지 않도록 제한합니다.
x1 = max(0, min(x1, width))
x2 = max(0, min(x2, width))
y1 = max(0, min(y1, height))
y2 = max(0, min(y2, height))

if x1 >= x2 or y1 >= y2:
    raise ValueError(
        f"잘못된 ROI 좌표입니다: {(x1, y1, x2, y2)}"
    )

roi = image[y1:y2, x1:x2]

output_dir.mkdir(parents=True, exist_ok=True)

roi_path = output_dir / "sample01_roi.jpg"
preview_path = output_dir / "sample01_roi_preview.jpg"

# 잘라낸 ROI 저장
cv2.imwrite(str(roi_path), roi)

# 원본에서 ROI 위치를 확인할 Preview 저장
preview = image.copy()
cv2.rectangle(
    preview,
    (x1, y1),
    (x2, y2),
    (0, 255, 0),
    3,
)

cv2.imwrite(str(preview_path), preview)

print("원본 크기 :", image.shape)
print("ROI 좌표  :", (x1, y1, x2, y2))
print("ROI 크기  :", roi.shape)
print("ROI 저장  :", roi_path)
print("Preview   :", preview_path)
```

# 13. 여러 이미지에 같은 ROI 적용하기

실제 검사는 한 장으로 끝나지 않습니다.

한 장에서 병뚜껑 영역에 맞게 ROI를 정했다면, 이제 같은 ROI를 여러 이미지에도 적용했을 때 검사 대상이 제대로 들어오는지 확인해야 합니다.

`src/04_batch_roi.py`를 만듭니다.

```python
from pathlib import Path

import cv2


input_dir = Path("samples")
output_dir = Path("outputs/roi")
output_dir.mkdir(parents=True, exist_ok=True)

# 자신의 이미지에 맞게 수정합니다.
x1 = 200
y1 = 100
x2 = 700
y2 = 500

extensions = ("*.jpg", "*.jpeg", "*.png")

image_files = []
for pattern in extensions:
    image_files.extend(input_dir.glob(pattern))

image_files = sorted(image_files)

print("전체 이미지 수:", len(image_files))

if not image_files:
    raise RuntimeError(
        "samples 폴더에 jpg/jpeg/png 이미지가 없습니다."
    )

success_count = 0

for image_path in image_files:
    image = cv2.imread(str(image_path))

    if image is None:
        print("읽기 실패:", image_path.name)
        continue

    height, width = image.shape[:2]

    cx1 = max(0, min(x1, width))
    cx2 = max(0, min(x2, width))
    cy1 = max(0, min(y1, height))
    cy2 = max(0, min(y2, height))

    if cx1 >= cx2 or cy1 >= cy2:
        print("ROI 실패:", image_path.name)
        continue

    roi = image[cy1:cy2, cx1:cx2]

    roi_path = output_dir / f"{image_path.stem}_roi.jpg"
    preview_path = output_dir / f"{image_path.stem}_preview.jpg"

    cv2.imwrite(str(roi_path), roi)

    preview = image.copy()
    cv2.rectangle(
        preview,
        (cx1, cy1),
        (cx2, cy2),
        (0, 255, 0),
        3,
    )
    cv2.imwrite(str(preview_path), preview)

    success_count += 1
    print(image_path.name, "→", roi_path.name)

print("처리 완료:", success_count, "/", len(image_files))
```

```

2. 결과를 저장할 폴더를 정한다.

3. 결과 폴더가 없으면 만든다.

8. 이미지가 하나도 없으면 오류를 발생시킨다.

9. 성공적으로 처리한 이미지 개수를 0으로 시작한다.

10. 이미지 목록을 하나씩 반복한다.

    10-3. 현재 이미지의 가로와 세로 크기를 확인한다.

          현재 이미지 크기에 맞게 보정한다.

    10-5. ROI 좌표가 잘못되었다면
```

하지만 같은 좌표를 다른 이미지에 적용하면 다음과 같은 일이 생길 수 있습니다.

```
sample02
병이 조금 왼쪽에 있음
→ 병뚜껑 일부가 ROI 밖으로 나감

sample03
병이 조금 오른쪽에 있음
→ ROI가 병뚜껑 전체를 포함하지 못함

sample04
병뚜껑 없음
→ ROI 위치는 맞지만 검사 대상이 없음
```

여기서 중요한 것은 ROI가 실패했다고 해서 코드가 틀렸다고 바로 판단하지 않는 것입니다.

먼저 다음 질문을 확인합니다.

```
ROI 좌표가 잘못된 것인가?

제품 위치가 이미지마다 달라진 것인가?

카메라 위치나 촬영 거리가 달라진 것인가?

제품 자체의 크기나 방향이 달라진 것인가?
```

## 13.1 고정 ROI가 잘 동작하려면 어떤 조건이 필요한가요?

고정 ROI는 다음과 같은 환경에서 가장 안정적으로 사용할 수 있습니다.

```
카메라 위치가 고정되어 있다.
제품이 놓이는 위치가 거의 일정하다.
촬영 거리가 일정하다.
이미지 해상도가 동일하다.
제품의 크기와 방향이 크게 변하지 않는다.
```

제조현장의 컨베이어 검사처럼 카메라와 제품 위치를 일정하게 유지할 수 있다면 고정 ROI가 매우 간단하고 효과적인 방법이 될 수 있습니다.

반대로 다음과 같은 상황에서는 같은 ROI가 실패할 가능성이 높습니다.

```
제품이 좌우로 크게 움직임
제품 높이가 달라짐
카메라 위치가 바뀜
이미지 해상도가 달라짐
제품이 회전함
촬영 거리가 달라짐
```

---

## 13.2 Dataset을 준비할 때도 촬영조건이 중요합니다

머신비전에서는 알고리즘만큼 데이터를 어떤 조건에서 촬영했는지도 중요합니다.

고정 ROI를 사용하는 실습에서는 가능하면 다음 조건을 일정하게 유지합니다.

```
카메라 위치
카메라 높이
제품과 카메라 사이 거리
이미지 해상도
제품이 놓이는 기본 위치
배경
```

예를 들어 병뚜껑 검사 데이터를 만든다면 다음과 같이 준비할 수 있습니다.

```
정상 이미지
→ 같은 병
→ 같은 카메라
→ 같은 해상도
→ 비슷한 위치

불량 이미지
→ 같은 촬영조건
→ 병뚜껑만 없음
```

이렇게 해야 정상과 불량의 차이가 병뚜껑 유무 때문인지, 아니면 ​카메라 위치·해상도·배경 차이 때문인지 구분하기 쉬워집니다.

---

## 13.3 그렇다고 모든 이미지를 완전히 똑같게 만들 필요는 없습니다

실제 환경에서는 제품 위치가 조금씩 달라질 수 있습니다.

따라서 오늘 실습에서는 일부 이미지의 위치를 조금 다르게 준비해도 좋습니다.

```
sample01 → 중앙
sample02 → 조금 왼쪽
sample03 → 조금 오른쪽
sample04 → 병뚜껑 없음
sample05 → 위치 또는 조명이 조금 다름
```

이렇게 준비하는 이유는 일부러 실패를 만들기 위해서입니다.

같은 ROI를 적용해 본 뒤 다음을 관찰합니다.

```
어느 정도 위치 변화까지는 괜찮은가?

어느 순간부터 ROI가 병뚜껑을 놓치는가?

ROI를 크게 만들면 해결되는가?

ROI를 너무 크게 만들면 불필요한 배경이 많이 포함되지 않는가?
```

즉, ROI의 크기와 위치에도 적절한 범위가 있다는 것을 경험합니다.

---

## 13.4 ROI가 벗어난 결과는 어떻게 해석하나요?

예를 들어 정상 병뚜껑 이미지인데 병뚜껑 일부가 ROI 밖으로 벗어났다고 생각합니다.

이 결과를 다음처럼 해석합니다.

```
제품은 정상이다.

하지만

검사 영역이 제품을 제대로 포함하지 못했다.

따라서 이후 검사에서
정상 제품을 불량으로 판단할 가능성이 있다.
```

이것은 제품의 불량이 아니라 검사조건의 실패입니다.

따라서 머신비전에서는 다음 두 문제를 구분해야 합니다.

```
제품 문제
→ 실제 정상 / 불량의 차이

검사환경 문제
→ ROI 위치
→ 카메라 위치
→ 조명
→ 해상도
→ 제품 정렬 상태
```

이 구분이 매우 중요합니다.

---

## 13.5 ROI가 실패했다면 어떻게 개선할 수 있을까요?

오늘은 해결 방법을 모두 구현하지 않습니다.

먼저 다음 세 가지 방향이 있다는 것만 이해합니다.

```
방법 1
제품 위치를 일정하게 유지한다.
→ 카메라와 제품 배치를 고정

방법 2
ROI를 조금 넓게 잡는다.
→ 작은 위치 변화까지 포함

방법 3
제품 위치를 먼저 찾은 뒤 ROI를 정한다.
→ 이후 Template Matching
→ Feature Matching
→ Detection
→ Alignment 등 활용
```

1일차에는 방법 1과 방법 2 정도를 직접 생각해 보는 것으로 충분합니다.

제품 위치를 자동으로 찾는 방법은 이후 수업에서 학습합니다.

---

## 13.6 오늘 이 실습에서 확인해야 하는 것

여러 이미지에 같은 ROI를 적용한 뒤 다음을 확인합니다.

- [ ] 모든 이미지의 해상도가 같은가?
- [ ] 정상 이미지에서 병뚜껑이 ROI 안에 들어오는가?
- [ ] 위치가 조금 달라져도 ROI가 유지되는가?
- [ ] 병뚜껑이 없는 이미지에서는 같은 위치를 검사하고 있는가?
- [ ] ROI가 너무 좁거나 너무 넓지는 않은가?
- [ ] 실패한 이미지는 제품 문제인가, 검사조건 문제인가?

오늘 중요한 것은 모든 이미지에서 ROI를 완벽하게 맞추는 것이 아닙니다.

> 같은 좌표를 여러 이미지에 적용했을 때 어떤 조건에서는 잘 동작하고 어떤 조건에서는 실패하는지 발견하는 것이 학습의 목적입니다.

이 경험을 통해 머신비전에서는 코드뿐 아니라 카메라 위치, 제품 위치, 해상도, 조명과 같은 촬영조건을 일정하게 관리하는 것도 검사 성능의 일부​라는 것을 이해합니다.

# 15. ROI 비교 결과 간단히 기록하기

아래와 같은 표를 `reports/day01_problem_definition.md`에 추가합니다.

자신이 ROI를 맞출때 어떤 기준으로 맞췄는가? 
이번 실습에서는 `sample01`의 병뚜껑에 ROI를 가능한 가깝게 맞추어 설정했습니다.

그 결과 첫 번째 이미지에서는 병뚜껑이 잘 들어왔지만, 다른 이미지에서는 병의 위치나 병뚜껑의 크기가 조금 달라지면서 ROI 안에 완전히 들어오지 않는 경우가 나타났습니다.

## 15.1 결과 기록
| 이미지        | 실제 상태    . | ROI 결과    . | 관찰                                           |
| ---------- | ---------- | ----------- | -------------------------------------------- |
| `sample01` | 뚜껑 있음      | 성공          | 처음 ROI를 설정한 기준 이미지로, 병뚜껑이 ROI 안에 잘 들어옴       |
| `sample02` | 뚜껑 있음      | 부분 성공       | 병뚜껑의 크기와 위치가 기준 이미지와 조금 달라 ROI가 매우 좁게 맞음     |
| `sample03` | 뚜껑 있음      | 부분 실패       | 병뚜껑 일부가 ROI 경계에 걸리거나 잘려서 이후 측정값이 달라질 가능성이 있음 |
| `sample04` | 뚜껑 없음      | ROI 정상      | 검사할 위치는 올바르지만 실제 병뚜껑이 없는 불량 이미지              |
| `sample05` | 뚜껑 없음      | ROI 정상      | 동일한 병 입구 영역을 검사하고 있으며 병뚜껑이 존재하지 않음           |
위와 같이 `reports/day01_problem_definition.md`에 이 표를 기록에 남깁니다. 다만 ROI 좌표를 조금 바꿀 때마다 전부 기록할 필요는 없습니다. 의미 있게 변경했을 때만 기록하면 됩니다.

추천 기록 기준은 `1차 시도 → 개선 시도 → 최종 선택` 정도입니다.

예시
```
1차 ROI
→ sample01에 최대한 바짝 맞춤
→ 다른 정상 이미지에서 일부가 잘리는 문제 발견

        ↓

2차 ROI
→ 좌우·상하에 약간의 여유를 줌
→ 여러 정상 이미지가 ROI 안에 들어오는지 다시 확인

        ↓

최종 ROI
→ 정상적인 위치 변화는 포함하면서
   불필요한 배경은 너무 많이 포함하지 않는 범위 선택
```

작성 예시
![[{8B1CC184-0600-4669-8487-77172F1F6085}.png]]

여기서 `sample04`, `sample05`는 ROI 실패가 아닙니다.

```
ROI 실패
→ 검사해야 할 위치를 제대로 포함하지 못한 경우

제품 불량
→ ROI 위치는 맞지만
   그 안에 있어야 할 병뚜껑이 없는 경우
```

따라서 다음 두 가지를 구분해야 합니다.

```
sample02 · sample03
→ 정상 제품인데 ROI가 너무 좁아질 수 있음
→ 검사 영역 설정의 문제

sample04 · sample05
→ ROI 위치는 정상
→ 실제 병뚜껑이 없음
→ 제품 상태의 차이
```

따라서 ROI는 단순히 대상에 최대한 딱 맞게 자르는 것”이 목적이 아니라, 
정상적인 위치 변화는 포함하면서 불필요한 배경은 최대한 줄이는 적절한 검사 영역을 찾는 것이 중요합니다.

이번 결과에서 다음을 확인했습니다.
```
한 장에서 잘 맞는 ROI ≠ 모든 이미지에서 잘 맞는 ROI
```

여러 이미지에 적용해 보아야 실제로 사용할 수 있는 ROI인지 판단할 수 있습니다.

또한 다음 두 문제를 구분해야 합니다.

```
ROI가 제품을 놓쳤다
→ 검사 영역 문제

ROI는 정상인데 병뚜껑이 없다
→ 실제 불량 후보
```

이번 실습의 핵심은 ROI를 한 장에 완벽하게 맞추는 것이 아니라, 여러 이미지에 적용해 보고 
어느 정도의 위치 변화까지 안정적으로 검사할 수 있는지 확인하는 것입니다.

## 15.2 이 기록은 어디에 사용하나요?

단순한 메모가 아니라 왜 현재 ROI를 선택했는지 설명하는 근거가 됩니다.

```
초기 설정
→ 문제 발견
→ 수정
→ 결과 비교
→ 최종 기준 결정
```

이 기록은 이후에 다음과 같이 활용합니다.
```
- 실패 원인 분석
- 최종 ROI 선택 근거
- 다른 학생이나 팀원이 코드를 볼 때 판단 과정 확인
- 이후 Calibration과 검사 기준 설정
- 최종 보고서에서 개선 과정 설명
```

> 중요: 모든 좌표 변경을 기록하는 것이 아니라, 결과가 달라진 중요한 시도만 남깁니다.

# 16. 영상 파일을 Frame으로 읽기

앞에서는 이미지 한 장을 읽고 ROI를 적용했습니다.

실제 머신비전에서는 저장된 사진뿐 아니라 카메라나 동영상에서 연속적으로 들어오는 영상도 많이 사용합니다.

영상은 특별히 다른 데이터가 아니라 여러 장의 이미지가 시간 순서대로 이어진 것으로 이해하면 됩니다.

```text
Video
 ↓
Frame 1
Frame 2
Frame 3
Frame 4
...
```

즉,

```
이미지 실습
→ 한 장 처리

영상 실습
→ 여러 장을 시간 순서대로 반복 처리
```

오늘은 영상에서 Frame을 읽고 저장해 보면서, 나중에 같은 ROI나 검사 로직을 각 Frame에 반복 적용할 수 있다는 구조만 이해하면 됩니다.

## 16.2 `src/05_video_input.py`

이 코드는 영상 파일을 열고 → 한 프레임씩 읽고 → 30프레임마다 한 장씩 이미지로 저장하는 코드입니다.

```python
from pathlib import Path

import cv2


video_path = Path("samples/sample.mp4")
output_dir = Path("outputs/frames")
output_dir.mkdir(parents=True, exist_ok=True)

cap = cv2.VideoCapture(str(video_path))

if not cap.isOpened():
    raise RuntimeError(
        f"영상을 열 수 없습니다: {video_path}"
    )

fps = cap.get(cv2.CAP_PROP_FPS)
width = int(cap.get(cv2.CAP_PROP_FRAME_WIDTH))
height = int(cap.get(cv2.CAP_PROP_FRAME_HEIGHT))

print("영상 :", video_path)
print("FPS  :", fps)
print("크기 :", width, "x", height)

frame_count = 0
saved_count = 0

while True:
    ret, frame = cap.read()

    if not ret:
        break

    frame_count += 1

    # 약 30 Frame마다 한 장 저장하는 예제
    if frame_count % 30 == 0:
        output_path = (
            output_dir / f"frame_{frame_count:05d}.jpg"
        )

        cv2.imwrite(str(output_path), frame)
        saved_count += 1

        print("저장:", output_path.name)

cap.release()

print("전체 Frame:", frame_count)
print("저장 Frame:", saved_count)
```

의사코드

```

   → samples/sample.mp4

2. Frame 이미지를 저장할 폴더를 정한다.
   → outputs/frames

3. 저장 폴더가 없으면 만든다.

4. OpenCV로 영상을 연다.

5. 영상이 정상적으로 열리지 않으면
   오류를 발생시키고 종료한다.

6. 영상의 정보를 확인한다.
   → FPS
   → 가로 크기
   → 세로 크기

7. 전체 Frame 개수를 세기 위한 값을 0으로 시작한다.

8. 저장한 Frame 개수를 세기 위한 값을 0으로 시작한다.

9. 영상을 처음부터 끝까지 반복해서 읽는다.

   9-1. 현재 Frame을 한 장 읽는다.

   9-2. 더 이상 읽을 Frame이 없으면
        반복을 끝낸다.

   9-3. 전체 Frame 개수를 1 증가시킨다.

   9-4. 현재 Frame 번호가 30의 배수인지 확인한다.

        예:
        30
        60
        90
        120
        ...

   9-5. 30의 배수라면
        현재 Frame을 JPG 이미지로 저장한다.

   9-6. 저장한 Frame 개수를 1 증가시킨다.

10. 영상 사용을 종료한다.

11. 전체 Frame 수와
    실제 저장한 Frame 수를 출력한다.
```

```

   ↓

   ↓

   ↓

   ↓

   ↓

   ↓
```

## 16.3 저장 영상의 Frame에도 ROI를 적용합니다

앞에서는 영상을 한 Frame씩 읽고 30 Frame마다 이미지를 저장했습니다.

이번에는 각 Frame에서 검사할 영역인 ROI를 잘라서 저장해 봅니다.

핵심 원리는 이미지 ROI와 같습니다.

```
이미지 한 장
→ ROI

영상
→ Frame 1 → ROI
→ Frame 2 → ROI
→ Frame 3 → ROI
→ ...
```

즉 영상이라고 해서 ROI 방법이 달라지는 것이 아닙니다.

---

### 먼저 ROI 위치를 정합니다

앞에서 저장한 Frame 중 하나를 열어 봅니다.

예:

```
outputs/frames/frame_00090.jpg
```

영상에서 검사하고 싶은 부분을 확인한 뒤 ROI 좌표를 정합니다.

예:

```python
x1 = 200
y1 = 100
x2 = 700
y2 = 500
```

좌표의 의미는 이미지 실습과 같습니다.

```
(x1, y1)
    ┌─────────────────┐
    │                 │
    │       ROI       │
    │                 │
    └─────────────────┘
                     (x2, y2)
```

> 아래 좌표는 예시입니다. 실제 영상에 맞게 검사할 영역의 좌표를 변경합니다.

## 16.4 `src/06_video_roi.py`

다음 파일을 만듭니다.

```
src/06_video_roi.py
```

```python
from pathlib import Path

import cv2


video_path = Path("samples/sample.mp4")

output_dir = Path("outputs/video_roi")
output_dir.mkdir(parents=True, exist_ok=True)


# 검사할 ROI 좌표
# 실제 영상에 맞게 수정합니다.
x1 = 200
y1 = 100
x2 = 700
y2 = 500


cap = cv2.VideoCapture(str(video_path))

if not cap.isOpened():
    raise RuntimeError(
        f"영상을 열 수 없습니다: {video_path}"
    )


frame_count = 0
saved_count = 0


while True:

    ret, frame = cap.read()

    if not ret:
        break


    frame_count += 1

    height, width = frame.shape[:2]


    # ROI 좌표가 영상 밖으로 나가지 않도록 조정
    cx1 = max(0, min(x1, width))
    cx2 = max(0, min(x2, width))

    cy1 = max(0, min(y1, height))
    cy2 = max(0, min(y2, height))


    if cx1 >= cx2 or cy1 >= cy2:
        print("잘못된 ROI 좌표입니다.")
        break


    # 30 Frame마다 결과 저장
    if frame_count % 30 == 0:

        # ROI 자르기
        roi = frame[
            cy1:cy2,
            cx1:cx2
        ]


        # ROI 이미지 저장
        roi_path = (
            output_dir
            / f"frame_{frame_count:05d}_roi.jpg"
        )

        cv2.imwrite(
            str(roi_path),
            roi
        )


        # 원본 Frame 복사
        preview = frame.copy()


        # ROI 위치 표시
        cv2.rectangle(
            preview,
            (cx1, cy1),
            (cx2, cy2),
            (0, 255, 0),
            3
        )


        # ROI 표시된 전체 Frame 저장
        preview_path = (
            output_dir
            / f"frame_{frame_count:05d}_preview.jpg"
        )

        cv2.imwrite(
            str(preview_path),
            preview
        )


        saved_count += 1

        print(
            "저장:",
            roi_path.name
        )


cap.release()


print("전체 Frame:", frame_count)
print("ROI 저장 Frame:", saved_count)
```

## 16.5 코드를 이해해 봅니다

이 코드의 핵심은 두 줄입니다.

먼저 현재 Frame에서 ROI를 잘라냅니다.

```python
roi = frame[cy1:cy2, cx1:cx2]
```

그리고 원본 Frame에는 ROI 위치를 확인할 수 있도록 사각형을 그립니다.

```python
cv2.rectangle(
    preview,
    (cx1, cy1),
    (cx2, cy2),
    (0, 255, 0),
    3
)
```

따라서 두 종류의 결과가 만들어집니다.

```
preview
→ 전체 Frame에서 ROI가 어디인지 확인

roi
→ 실제 검사할 영역만 잘라낸 이미지
```

# 17. 스마트폰 카메라를 이용한 실시간 영상 입력

WSL2 환경에서는 USB 웹캠이 OpenCV에서 바로 인식되지 않는 경우가 있습니다.

따라서 오늘은 웹캠 대신 스마트폰 카메라를 네트워크 카메라처럼 사용하여 실시간 영상을 입력해 봅니다.

전체 구조는 다음과 같습니다.

```text
스마트폰 카메라
      ↓
Wi-Fi로 실시간 영상 전송
      ↓
HTTP 또는 RTSP 주소
      ↓
WSL2 OpenCV
      ↓
실시간 Frame
      ↓
이후 ROI · 검사 처리
```

즉 스마트폰이 카메라 역할을 하고, WSL2의 OpenCV는 네트워크를 통해 실시간 영상을 받아 처리합니다.

---

## 17.1 스마트폰을 실시간 카메라로 준비합니다

이번 실습에서는 WSL2에서 USB 웹캠을 직접 연결하는 대신 **스마트폰을 네트워크 카메라로 사용**합니다.

전체 구조는 다음과 같습니다.

```text
스마트폰 카메라
      ↓
같은 Wi-Fi
      ↓
스마트폰이 영상 주소 제공
      ↓
Windows / WSL2에서 주소로 접속
      ↓
OpenCV가 실시간 Frame을 읽음
```

## 17.6 실시간 영상에서 ROI를 직접 선택합니다

이미지 실습에서는 숫자로 ROI 좌표를 입력했습니다.

이번에는 실시간 영상이므로 조금 더 실제적인 방법을 사용합니다.

첫 번째 Frame을 화면에 띄운 뒤 **마우스로 병뚜껑 영역을 직접 선택**합니다.

새 파일을 만듭니다.

```
src/08_phone_camera_roi.py
```

다음 코드를 작성합니다.

```python
from pathlib import Path
import cv2


# --------------------------------------------------
# 기본 설정
# --------------------------------------------------

stream_url = "http://192.168.219.115:8080/video"

output_dir = Path("outputs/live_roi")
output_dir.mkdir(parents=True, exist_ok=True)


# --------------------------------------------------
# ROI 선택 상태
# --------------------------------------------------

drawing = False

start_x = 0
start_y = 0

end_x = 0
end_y = 0

roi_selected = False


# --------------------------------------------------
# 마우스로 ROI 선택
# --------------------------------------------------

def mouse_callback(event, x, y, flags, param):

    global drawing
    global start_x, start_y
    global end_x, end_y
    global roi_selected

    # 마우스 왼쪽 버튼을 누르면 시작점 기록
    if event == cv2.EVENT_LBUTTONDOWN:

        drawing = True

        start_x = x
        start_y = y

        end_x = x
        end_y = y

        roi_selected = False


    # 마우스를 움직이는 동안 영역 표시
    elif event == cv2.EVENT_MOUSEMOVE and drawing:

        end_x = x
        end_y = y


    # 마우스 버튼을 놓으면 ROI 확정
    elif event == cv2.EVENT_LBUTTONUP:

        drawing = False

        end_x = x
        end_y = y

        roi_selected = True

        print(
            "ROI 선택:",
            start_x,
            start_y,
            end_x,
            end_y
        )


# --------------------------------------------------
# 스마트폰 영상 연결
# --------------------------------------------------

cap = cv2.VideoCapture(stream_url)

if not cap.isOpened():
    raise RuntimeError(
        "스마트폰 영상을 열 수 없습니다."
    )


window_name = "Phone Camera"

cv2.namedWindow(window_name)

cv2.setMouseCallback(
    window_name,
    mouse_callback
)


print()
print("===================================")
print("스마트폰 실시간 ROI 실습")
print("===================================")
print("마우스 드래그 : ROI 선택")
print("r            : ROI 다시 선택")
print("1            : 뚜껑 있음 저장")
print("2            : 뚜껑 없음 저장")
print("q / ESC      : 종료")
print("Ctrl + C     : 터미널에서 강제 종료")
print("===================================")
print()


try:

    while True:

        ret, frame = cap.read()

        if not ret:
            print("Frame을 읽을 수 없습니다.")
            break


        preview = frame.copy()


        # ------------------------------------------
        # ROI 선택 중
        # ------------------------------------------

        if drawing:

            cv2.rectangle(
                preview,
                (start_x, start_y),
                (end_x, end_y),
                (0, 255, 255),
                2
            )


        # ------------------------------------------
        # ROI가 선택된 경우
        # ------------------------------------------

        if roi_selected:

            x1 = min(start_x, end_x)
            y1 = min(start_y, end_y)

            x2 = max(start_x, end_x)
            y2 = max(start_y, end_y)


            # 전체 화면에 ROI 표시
            cv2.rectangle(
                preview,
                (x1, y1),
                (x2, y2),
                (0, 255, 0),
                3
            )


            cv2.putText(
                preview,
                "CAP ROI",
                (x1, max(30, y1 - 10)),
                cv2.FONT_HERSHEY_SIMPLEX,
                0.8,
                (0, 255, 0),
                2
            )


            # ROI 자르기
            roi = frame[y1:y2, x1:x2]


            if roi.size > 0:

                cv2.imshow(
                    "Cap ROI",
                    roi
                )


        # 전체 실시간 영상
        cv2.imshow(
            window_name,
            preview
        )


        # ------------------------------------------
        # 키 입력
        # ------------------------------------------

        key = cv2.waitKey(1) & 0xFF


        # q 또는 ESC → 종료
        if key == ord("q") or key == 27:
            print("프로그램을 종료합니다.")
            break


        # r → ROI 초기화
        elif key == ord("r"):

            roi_selected = False

            print("ROI를 다시 선택하세요.")

            try:
                cv2.destroyWindow("Cap ROI")
            except cv2.error:
                pass


        # 1 → 병뚜껑 있음 저장
        elif key == ord("1") and roi_selected:

            output_path = (
                output_dir / "cap_on.jpg"
            )

            cv2.imwrite(
                str(output_path),
                roi
            )

            print(
                "병뚜껑 있음 저장:",
                output_path
            )


        # 2 → 병뚜껑 없음 저장
        elif key == ord("2") and roi_selected:

            output_path = (
                output_dir / "cap_off.jpg"
            )

            cv2.imwrite(
                str(output_path),
                roi
            )

            print(
                "병뚜껑 없음 저장:",
                output_path
            )


        # 창의 X 버튼으로 닫았는지도 확인
        try:

            if (
                cv2.getWindowProperty(
                    window_name,
                    cv2.WND_PROP_VISIBLE
                )
                < 1
            ):
                print("창이 닫혀 프로그램을 종료합니다.")
                break

        except cv2.error:
            break


# Ctrl + C 처리
except KeyboardInterrupt:

    print()
    print("Ctrl + C가 입력되었습니다.")
    print("프로그램을 종료합니다.")


# 어떤 상황에서도 자원 정리
finally:

    cap.release()

    cv2.destroyAllWindows()

    print("카메라 연결을 종료했습니다.")
```

이 코드는 기본적으로 계속 실시간 영상을 보여주는 코드입니다.

# 18 이미지·저장 영상·실시간 영상의 차이

지금까지 세 가지 입력 방식을 확인했습니다.

```text
Image 파일
→ 이미지 한 장

Video 파일
→ 저장된 Frame을 순서대로 읽음

스마트폰 카메라
→ 현재 촬영되는 Frame을 실시간으로 읽음
```

하지만 OpenCV 입장에서는 결국 모두 이미지 또는 Frame입니다.

![[Pasted image 20260827170413.png]]

따라서 앞으로 배우게 될 머신비전 검사기술은 입력 방식이 달라져도 동일한 원리로 적용할 수 있습니다.

예를 들어 실시간 영상에도 다음과 같은 처리를 적용할 수 있습니다.

```text
스마트폰 카메라
      ↓
실시간 Frame
      ↓
ROI
      ↓
Threshold · Contour 등
      ↓
검사 결과
```

> 오늘의 핵심은 스마트폰 연결 자체가 아니라, 실제 카메라에서 들어오는 영상도 결국 Frame 단위로 처리하며 저장 영상과 같은 검사 로직을 적용할 수 있다는 것을 이해하는 것입니다.

# 18. Dataset의 역할을 구분합니다

지금까지 이미지, 저장 영상, 스마트폰 실시간 영상에서 ROI를 직접 적용해 보았습니다.

이제부터는 데이터를 아무 폴더에나 섞어 두지 않고 사용 목적에 따라 구분하는 습관을 들입니다.

|폴더|역할|언제 사용하는가|
|---|---|---|
|`calibration`|검사 기준을 정하기 위한 데이터|정상 범위·Threshold 등을 결정할 때|
|`train`|AI 모델을 학습하기 위한 데이터|AI 모델을 사용하는 경우|
|`validation`|학습·설정 중간 비교|AI 모델이나 설정을 비교할 때|
|`test`|확정된 방법의 최종 확인|기준을 정한 뒤 성능을 확인할 때|
|`challenge`|일부러 어려운 조건의 데이터|실패 조건을 찾아볼 때|

교과 9의 Rule 기반 검사에서 특히 기억할 것은 다음입니다.

```
Calibration
→ 기준을 정할 때 사용

Test
→ 정한 기준이 새로운 데이터에서도
   동작하는지 확인

Challenge
→ 어떤 조건에서 실패하는지 확인
```

아직 1일차에는 실제 Threshold나 정상 범위를 결정하지 않습니다.

지금은 각 데이터가 왜 따로 관리되어야 하는지만 이해하면 됩니다.

# 20. 먼저 검사 문제를 눈으로 판단합니다

코드를 실행하기 전에 이미지를 먼저 봅니다.

다음 질문에 답해 봅니다.

```
무엇을 검사하려는가?
        ↓
정상은 어떤 모습인가?
        ↓
불량은 어떤 모습인가?
        ↓
이미지 전체를 볼 필요가 있는가?
        ↓
어느 부분만 보면 판단할 수 있는가?
        ↓
그 부분을 ROI로 만들 수 있는가?
```

예를 들어 색상 스티커를 선택했다면:

```
검사 대상
→ 제품의 빨간색 스티커

정상
→ 지정 위치에 스티커 존재

불량
→ 스티커 없음 또는 위치 이탈

검사할 부분
→ 스티커가 있어야 하는 영역
```

아직 `HSV`, `Threshold`, `Contour` 같은 기술을 먼저 고르지 않습니다.

순서는 항상 다음과 같습니다.

```
문제
→ 눈으로 보이는 차이
→ 검사할 위치
→ ROI
→ 이후 필요한 기술
```

# 22. 어떤 ROI가 좋은지 스스로 판단합니다

ROI 결과를 보면서 다음 기준으로 판단합니다.

|상황|어떻게 판단할까?|
|---|---|
|모든 정상 이미지에서 검사 대상이 충분히 들어옴|현재 ROI 사용 가능|
|정상 대상 일부가 잘림|ROI가 너무 좁음|
|배경이 지나치게 많이 포함됨|ROI가 너무 넓음|
|제품이 조금 이동하면 ROI에서 벗어남|위치 변화에 너무 민감함|
|제품 위치가 크게 달라짐|고정 ROI만으로는 어려울 수 있음|

중요한 것은 ROI를 최대한 작게 만드는 것이 아닙니다.

좋은 ROI는 다음 조건을 만족해야 합니다.

```
검사 대상은 충분히 포함
        +
불필요한 배경은 가능한 줄임
        +
정상적인 위치 변화는 어느 정도 허용
```

예를 들어:

```
ROI v1

기준 이미지에 너무 바짝 맞춤
        ↓
다른 정상 이미지에서 일부가 잘림
        ↓
너무 좁음
```

조금 수정합니다.

```
ROI v2

검사 대상 주변에 약간 여유 추가
        ↓
여러 정상 이미지가 모두 포함됨
        ↓
더 적절함
```

모든 좌표 변경을 기록할 필요는 없습니다.

의미 있게 변경한 버전만 비교합니다.

# 23. ROI를 사용할 수 있는 상황인지 판단합니다

ROI를 만들었다고 해서 모든 검사 문제에서 고정 ROI가 좋은 방법은 아닙니다.

이번 Challenge 결과를 보고 다음 중 하나를 선택합니다.

```
A. 고정 ROI 사용 가능

제품과 카메라 위치가 비교적 일정하고
여러 이미지에서도 같은 영역에
검사 대상이 들어온다.
```

```
B. ROI를 조금 넓혀야 함

제품 위치가 조금씩 달라지지만
일정 범위 안에서 움직인다.
```

```
C. 고정 ROI만으로는 어려움

제품 위치나 회전이 크게 달라져
검사 대상이 계속 다른 위치에 나타난다.
```

`C`가 나와도 실패가 아닙니다.

오히려 중요한 판단입니다.

```
고정 ROI로 충분하지 않다
        ↓
나중에는

Template Matching
Feature Matching
Object Detection
정렬(Alignment)

등 다른 방법을 검토할 수 있다.
```

아직 이 기술들을 구현할 필요는 없습니다.

외부 저장소 업로드와 관계없이 Local Git만으로도 버전관리를 연습할 수 있습니다.

처음 한 번 실행합니다.

```bash
git init
```

현재 상태를 확인합니다.

```bash
git status
```

코드와 문서를 추가합니다.

```bash
git add .
```

Commit합니다.

```bash
git commit -m "feat: setup subject9 machine vision day01"
```

ROI와 문제 정의까지 수정했다면 다시 기록합니다.

```bash
git add .
git commit -m "feat: add image input and ROI practice"
```

문서 정리를 끝냈다면 다음처럼 기록할 수 있습니다.

```bash
git add .
git commit -m "docs: add day01 inspection problem definition"
```

기록을 확인합니다.

```bash
git log --oneline
```

예:

```text
a128bd2 docs: add day01 inspection problem definition
d421abc feat: add image input and ROI practice
f191ac8 feat: setup subject9 machine vision day01
```

외부 Git 서버 또는 기관 내부 Git 사용은 수업 운영 지침에 따라 진행합니다.

# 30. 오늘 반드시 가져가야 할 핵심

오늘 `cv2.imread()` 사용법이나 ROI 좌표 숫자를 외우는 것이 가장 중요한 것은 아닙니다.

오늘 반드시 익혀야 하는 사고방식은 이것입니다.

```text
사람의 생각
"병뚜껑이 없다"

        ↓

검사할 위치
"병뚜껑이 있어야 하는 ROI"

        ↓

컴퓨터가 측정할 특징
"면적 또는 다른 수치"

        ↓

이후 수업에서
실제 측정 방법과 기준값을 만든다.

        ↓

최종적으로
OK / NG
```

ROI는 일종의 전처리 단계이며 핵심을 짧게 요약하면 다음과 같습니다.

```
전체 이미지
    ↓
필요 없는 배경 제거
    ↓
검사해야 할 위치만 선택
    ↓
ROI
    ↓
그 영역에서만
Threshold / Contour / Template / OCR 등 수행
```

병뚜껑 검사에서는 전체 병 사진을 다 볼 필요가 없고 병뚜껑이 있어야 하는 위치만 잘라서 검사하면 됩니다.

그래서 ROI의 목적은 보통 두 가지입니다.

- 불필요한 배경을 줄여서 검사 대상을 더 명확하게 본다.
- 검사 범위를 줄여서 이후 연산과 판정을 더 안정적으로 한다.

다만 한 가지 중요한 조건이 있습니다.

- 고정 ROI는 검사 대상이 항상 비슷한 위치에 들어온다는 전제가 있어야 합니다.

다음 2일차부터는 오늘 확보한 이미지와 ROI를 가지고 검사하기 좋은 영상 상태를 만드는 Image Enhancement를 학습합니다.
