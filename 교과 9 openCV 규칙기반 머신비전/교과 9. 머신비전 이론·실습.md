## 교과 9에서는 무엇을 배우나요?

교과 8에서는 이미지와 라벨을 이용해 AI 객체검출 모델을 학습하고, 새로운 이미지에서 대상을 찾아보았습니다.

교과 9에서는 조금 다른 관점에서 시작합니다. 공장에서 제품을 검사한다고 생각해 보세요. **정상 제품과 불량 제품은 무엇이 다를까요? 그 차이를 컴퓨터가 어떻게 측정하고 판단할 수 있을까요?**

우리는 이미지와 영상을 관찰한 뒤 검사 목적에 맞는 방법을 선택합니다. OpenCV로 면적·개수·모양을 측정하거나, 로고를 비교하고, 문자를 읽고, 정상과 다른 이상 패턴을 찾아봅니다. 그런 다음 실제 데이터로 검사 기준을 정하고, 처음 보는 데이터에서 잘 동작하는지 확인합니다.

즉, 교과 9의 목표는 기술 이름을 많이 외우는 것이 아니라 **새로운 검사 문제를 보고 적절한 방법을 선택하며, 결과와 실패 원인을 설명할 수 있는 능력**을 기르는 것입니다.

9일차 Hybrid 검사는 무엇인가요?

![[Pasted image 20261019114419.png]]

즉 여러 검사가 각각 결과를 반환하면, 최종 판정 규칙에 따라 하나의 OK/NG 결과로 정리하는 것입니다.

9일차 Hybrid 검사의 핵심은 서로 다른 검사 모델이나 검사 방법의 결과를 결합하여, 
단독 검사보다 더 효과적인 판정이 가능한지 검증하는 것입니다.

즉, 딥러닝 코드와 머신러닝 코드를 단순히 하나의 Python 파일로 합치는 것이 아닙니다.

예를 들어 아래와 같이 이해하면 됩니다.

```
동일한 제품 이미지
        ↓
 ┌───────────────┬───────────────┐
 ↓                               ↓
검사기 A                        검사기 B
One-shot                        Few-shot
 ↓                               ↓
정상 / 이상                      정상 / 이상
 ↓                               ↓
 └───────────────┬───────────────┘
                 ↓
        Hybrid 판정 규칙
                 ↓
         최종 정상 / 이상
                 ↓
         실제 정답과 비교
                 ↓
    Accuracy / Precision / Recall
                 ↓
      단독 검사와 성능 비교
```


이 과정에서 배우는 것은 크게 세 가지입니다.

1. 개별 성능 검증: 각각의 검사 방법이 얼마나 정확한지 확인합니다.
    
2. 검사 결과 결합: OR, AND 등의 정책을 이용하여 두 검사기의 판정을 하나로 만듭니다.
    
3. Hybrid 성능 검증: 결합한 결과가 단독 검사보다 좋아졌는지, 오탐이나 미검출은 어떻게 달라졌는지 비교합니다.
    

### 중요한 차이점

Hybrid는 반드시 ML + 딥러닝을 결합해야 하는 것은 아닙니다.

- 규칙 기반 OpenCV + 딥러닝 이상검출
    
- One-shot + Few-shot
    
- OCR + 규칙 기반 검사
    

모두 검사 목적과 입력 데이터가 적합하다면 Hybrid 구조로 사용할 수 있습니다.

다만 결합한다고 성능이 반드시 향상되는 것은 아닙니다. 오히려 오탐이 증가할 수도 있으므로 동일한 평가 데이터에서 성능을 검증해야 합니다.

### 유형 A — 1~3일차: 병뚜껑 유무를 검사하는 프로그램

이 과정은 일반적인 ML 모델 학습보다 사람이 정한 측정 기준으로 동작하는 검사기를 만드는 것입니다.

#### 1일차 — 병뚜껑 이미지 확보

스마트폰 IP Webcam으로 병을 촬영하고, 병뚜껑이 있는 부분을 ROI로 저장합니다. 뚜껑이 있는 이미지와 없는 이미지를 확보합니다.

#### 2일차 — 전처리

영상의 밝기·대비·노이즈를 비교하고 Threshold/Otsu를 이용하여 병뚜껑을 검출하기 쉬운 이진 이미지로 바꿉니다.

#### 3일차 — 면적 측정과 OK/NG 판정

Contour로 흰색 객체의 면적을 계산하고, 뚜껑이 있는 경우와 없는 경우의 측정값을 비교합니다.

### 유형 C — 6일차: OCR로 제품의 SN을 검사하는 프로그램

이 과정에서는 Tesseract OCR 엔진을 사용합니다.

Tesseract는 이미 문자 인식 기능이 준비되어 있는 프로그램입니다. 
우리가 처음부터 OCR 신경망을 학습시키지는 않습니다.

```
제품 이미지 6장
       ↓
SN 문자 영역 ROI 선택
       ↓
전처리 방법 비교
       ↓
Tesseract OCR 실행
       ↓
13자리 숫자인가?
       ↓
Expected SN과 같은가?
       ↓
OK / NG
       ↓
실제 정답과 비교하여 성능 평가
```

여기서는 성능지표가 두 개로 나뉩니다.

|지표|의미|교재 결과|
|---|---|---|
|OCR Exact Accuracy|실제 인쇄된 번호를 정확히 읽었는가?|6/6, 100%|
|Inspection Accuracy|제품의 정상·불량을 올바르게 판정했는가?|6/6, 100%|
하지만 어제 FastAPI 화면에서 확인한 것처럼 기준 번호에 일치하는지는 제품 판정이고, OCR이 실제 문자를 정확히 읽었는지는 별도 정답과 비교해야 합니다.

더 중요한 것은 6일차 후반의 환경 변화 테스트입니다.

실제 교재에서는 Blur, Tilt, Glare 상태에서 OCR 인식이 실패하는 사례가 나옵니다.

따라서 기본 이미지 6장에서 100%가 나왔어도 촬영환경이 바뀌면 실패할 수 있음을 확인하는 검사입니다.

### 유형 D — 7~8일차: 여기서부터 딥러닝 모델을 활용합니다

앞의 유형과 가장 큰 차이가 여기 있습니다.

7~8일차는 ImageNet에서 사전학습된 ResNet18을 불러와 사용합니다.

YOLO와 마찬가지로 신경망 기반 딥러닝 모델이지만, 사용하는 목적이 다릅니다.

YOLO는 주로 객체의 종류와 위치를 검출하는 데 사용하는 반면, 이 실습의 ResNet18은 이미지의 특징을 숫자로 추출하는 용도입니다.

#### 7일차 — 정상 이미지가 충분할 때

```
MVTec bottle 정상 이미지
           ↓
사전학습된 ResNet18
           ↓
정상 이미지의 특징 추출
           ↓
Normal Reference 생성
           ↓
Validation으로 Threshold 결정
           ↓
Rule Freeze
           ↓
처음 보는 Test 이미지
           ↓
정상 특징과 거리 비교
           ↓
Normal / Anomaly
           ↓
Accuracy · Precision · Recall
```

핵심은 ResNet18을 새로 학습시키는 것이 아니라, 이미 학습된 모델로 정상 제품의 특징을 추출하고 그 특징으로 정상 기준을 만든다는 점입니다.

#### 8일차 — 사용할 데이터가 매우 적을 때

7일차와 같은 MVTec bottle 원본을 이용하지만, 일부러 기준으로 사용할 데이터의 수를 줄입니다.

One-shot — 정상 이미지 1장을 기준으로 사용
			정상 이미지 1장의 ResNet18 특징을 기준으로 삼고, 새로운 이미지가 얼마나 비슷한지 검사합니다.

Few-shot — 정상·불량 이미지 몇 장으로 기준을 만듦
			정상과 불량의 대표 특징(Prototype)을 만든 뒤, 새로운 이미지가 어느 쪽과 가까운지 비교합니다.

8일차에서는 Few-shot이 90%로 개선되었지만, 두 방식 모두 불량을 놓친 FN이 2건씩 발생했습니다.

여기서도 ResNet18을 처음부터 학습시키거나 Fine-tuning하는 과정이 핵심은 아닙니다.

### 그렇다면 9일차와 10일차는 무엇을 하는 것일까요?

이 두 일차의 역할은 서로 다릅니다.

9일차는 검사 결과와 실험을 관리하는 단계입니다.

5일차 광천김 검사의 기준을 한 가지 바꾸어 성능 차이를 기록하고, 
7일차에서는 조명 변화에 따른 오탐을 확인합니다. 
8일차에서는 One-shot과 Few-shot의 결과가 동일한 평가 이미지에서 나왔는지도 검증합니다.

9일차의 Hybrid 검사도 있습니다. 
하지만 이것은 광천김·OCR·병 이미지를 하나의 제품이라고 가정하여 실제 동시 검사한 것이 아닙니다. 
서로 다른 검사 모듈의 결과를 결합하는 Software Integration 데모이며, 
일부 Anomaly Score는 연동 검증을 위한 데모 값입니다.

10일차는 검사를 웹 서비스로 제공하는 단계입니다.

현재 확정 교재에서 실제로 구현한 서비스는 다음과 같습니다.

```
6일차 OCR Frozen Rule
        ↓
service_core.py
        ↓
실제 SN 문자 인식
        ↓
형식 검사 + 기준 번호 비교
        ↓
Final OK / NG + Reason
        ↓
FastAPI
        ↓
Web Dashboard
```

즉 10일차가 1~9일차의 모든 검사기를 다시 실행하고 통합 성능을 평가하는 날은 아닙니다. 안정적으로 동작하는 6일차 OCR 검사 모듈 하나를 대표 예제로 선택해 서비스로 만드는 날입니다.

|Deployment|검사 기능을 다른 프로그램에서 실행할 수 있도록 서비스화|

교과 9는 이 가운데 Feature 추출 → 검사 기준 생성 → Test → Evaluation을 매우 중요하게 다룹니다.

YOLO처럼 새로운 모델의 가중치를 반복적으로 학습시키는 방식이 아니어도, 데이터를 근거로 판정 기준을 만들고 새로운 이미지에서 성능을 검증하는 것은 충분히 의미 있는 머신비전 개발입니다.

### 최종적으로 이 수업을 어떻게 이해하면 좋을까요?

10일차 수업을 하나의 문장으로 연결하면 다음과 같습니다.

> 1~8일차에는 네 종류의 제조 검사 문제에 맞는 검사기를 만들고 성능을 평가하며, 
> 9일차에는 그 결과의 재현성과 운영 관리를 배우고, 
> 10일차에는 검증된 OCR 검사기를 FastAPI 웹 서비스로 연결합니다.

제가 교재를 검토하면서 가장 중요하다고 보는 부분은 **5일차의 Test 정확도 50%**입니다.

코드가 오류 없이 실행되었고 Calibration에서는 91.67%가 나왔는데도, 새로운 Test에서는 정상 제품 3장을 모두 불량이라고 판단했습니다. 이런 사례를 통해 학생들은 높은 정확도 수치 하나보다 데이터 분리, 새로운 데이터 검증, 실패 원인 분석이 왜 중요한지를 배울 수 있습니다.

따라서 이 교육은 단순히 OpenCV 함수를 사용해 보는 수준이 아니라, 검사 문제 정의부터 검증·실패 분석·서비스화까지 경험하는 머신비전 개발 입문 과정으로 이해하시면 됩니다.

그리고 현재 최종 교재에서 7~8일차는 사전학습 딥러닝 모델을 사용하므로, 교과 9 전체를 전통적인 ML만 배우는 수업이라고 설명하는 것은 기술적으로 정확하지 않습니다. 규칙 기반 컴퓨터비전과 딥러닝 기반 특징 추출을 함께 활용하는 수업입니다.
