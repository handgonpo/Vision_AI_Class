
생성형 AI가 코드를 만들어 주는 시대입니다.

그래서 처음 코딩을 배우는 사람이 모든 코드를 처음부터 끝까지 외워서 직접 작성해야 하는 것은 아닙니다.

AI에게 코드를 물어보고, 만들어진 코드를 활용해도 됩니다.

하지만 **그대로 복사해서 실행만 하고 끝내는 습관**은 피해야 합니다.

코드를 처음 배우는 단계에서는 다음 한 가지를 가장 중요하게 생각하면 됩니다.

> **코드를 외우는 것이 아니라, 이 코드가 왜 필요한지와 어떻게 움직이는지를 이해하는 연습을 합니다.**

---

# 1. AI가 코드를 만들어 줘도 괜찮습니다

코드를 직접 처음부터 작성하지 못한다고 해서 걱정할 필요는 없습니다.

처음에는 AI가 만들어 준 코드를 참고하면서 배워도 됩니다.

중요한 것은 다음과 같은 방식으로 끝내지 않는 것입니다.

```text
AI에게 코드 요청
        ↓
그대로 복사
        ↓
실행
        ↓
오류 없음
        ↓
끝
```

코드가 실행되었다고 해서 내가 그 코드를 이해한 것은 아닙니다.

또한 실행되었다고 해서 결과가 항상 올바른 것도 아닙니다.

따라서 AI가 코드를 만들어 주었다면 **최소한 무엇을 하는 코드인지 확인하고 실행하는 습관**을 가져야 합니다.

---

# 2. 코드를 볼 때 가장 먼저 세 가지만 확인합니다

처음부터 모든 줄을 이해하려고 하면 오히려 더 어렵습니다.

먼저 코드 전체를 보고 다음 세 가지를 확인합니다.

```text
무엇을 입력받는가?
        ↓
무엇을 하는가?
        ↓
무엇이 결과로 나오는가?
```

예를 들어 어떤 코드가 있다고 가정해 봅시다.

```text
폴더 위치 입력
        ↓
폴더 안의 파일 개수 확인
        ↓
필요한 개수와 비교
        ↓
결과 출력
```

이 정도로 설명할 수 있다면 코드의 큰 흐름은 이해한 것입니다.

처음부터 모든 문법을 외울 필요는 없습니다.

---

# 3. 초보자가 반복해야 할 가장 중요한 세 단계

## ① 읽을 수 있어야 합니다

코드를 보고 다음 질문에 답해 봅니다.

```text
이 코드는

무엇을 입력받고

무엇을 처리하고

무엇을 결과로 보여주는가?
```

코드 한 줄 한 줄을 번역하듯 읽을 필요는 없습니다.

먼저 **전체적으로 무슨 일을 하는 코드인지** 알아보는 것이 중요합니다.

---

## ② 자기 말로 설명할 수 있어야 합니다

코드를 보고 아주 짧게라도 자기 말로 설명해 봅니다.

예를 들면 다음 정도면 충분합니다.

> "이 코드는 폴더 안에 파일이 몇 개 있는지 확인하는 코드입니다."

또는

> "이 코드는 입력한 값을 확인하고 조건에 맞는지 검사하는 코드입니다."

처음부터 전문적인 표현을 사용할 필요는 없습니다.

**내가 이해한 말로 설명할 수 있는가**가 더 중요합니다.

설명이 안 된다면 아직 그 코드를 충분히 이해하지 못한 것입니다.

---

## ③ 조금 바꿀 수 있어야 합니다

코드를 그대로 실행해 본 뒤에는 아주 작은 부분이라도 직접 바꿔 봅니다.

예를 들면 다음과 같습니다.

```text
폴더 위치 바꾸기

파일 이름 바꾸기

사용하는 숫자 바꾸기

조건값 바꾸기

출력 문구 바꾸기
```

그리고 다시 실행합니다.

```text
코드 실행
        ↓
한 부분 변경
        ↓
다시 실행
        ↓
결과가 어떻게 달라졌는지 확인
```

이 과정을 반복하면 코드를 단순히 보는 것에서 끝나지 않고 **내가 직접 다룰 수 있는 코드**로 바뀌기 시작합니다.

---

# 4. 가장 좋은 훈련 방법

처음에는 다음 순서를 계속 반복하면 됩니다.

> **읽기 → 설명하기 → 바꿔보기**

```text
AI가 코드 작성
        ↓
코드를 읽어 본다
        ↓
무슨 코드인지 내 말로 설명한다
        ↓
한두 곳을 직접 바꿔 본다
        ↓
다시 실행한다
        ↓
결과가 어떻게 달라졌는지 확인한다
```

이 과정을 반복하는 것이 코드를 그대로 복사하는 것보다 훨씬 좋은 학습 방법입니다.

---

# 5. 모든 코드를 완벽하게 이해할 필요는 없습니다

초보자가 가장 많이 하는 실수 중 하나는 **코드의 모든 줄을 완벽하게 이해해야 한다고 생각하는 것**입니다.

그럴 필요는 없습니다.

예를 들어 다음과 같은 부분은 처음에는 대략적인 역할만 알아도 괜찮습니다.

```text
라이브러리 불러오기

파일 열기

폴더 만들기

결과 저장하기

화면에 문장 출력하기
```

반면 다음과 같은 부분은 조금 더 관심 있게 봐야 합니다.

```text
어떤 값을 입력으로 사용하는가?

중간에 어떤 조건을 검사하는가?

어떤 값을 계산하는가?

무엇을 기준으로 결과를 결정하는가?

최종 결과가 무엇인가?
```

즉,

> 모든 줄을 같은 깊이로 공부하지 말고, 프로그램의 결과를 결정하는 핵심 부분을 먼저 이해합니다.

---

# 6. 실행 전에 한 번 생각하고, 실행 후에도 한 번 확인합니다

코드를 바로 복사해서 실행하기 전에 잠깐 확인합니다.

```text
이 코드는 무엇을 하려고 만든 코드인가?

어떤 파일이나 값을 사용하는가?

실행하면 어떤 결과가 나와야 하는가?
```

그리고 실행한 뒤에는 다음을 확인합니다.

```text
내가 예상한 결과가 나왔는가?

이상한 결과는 없는가?

입력값을 바꾸면 결과도 자연스럽게 달라지는가?
```

이 습관이 중요합니다.

> 코드가 실행되었다는 것과 코드가 올바르게 동작했다는 것은 같은 뜻이 아닙니다.

---

# 7. 오류가 나오면 바로 새 코드를 받기 전에 원인을 먼저 봅니다

오류가 발생하면 당황할 필요가 없습니다.

오류도 코드를 배우는 과정입니다.

```text
오류 발생
        ↓
어디에서 오류가 났는지 확인
        ↓
입력값이나 경로 확인
        ↓
무엇이 문제인지 생각
        ↓
필요하면 AI에게 질문
        ↓
수정
        ↓
다시 실행
```

AI에게 오류를 물어봐도 괜찮습니다.

다만 AI가 수정한 코드를 그대로 붙여 넣고 끝내지 않습니다.

수정이 끝난 뒤 최소한 다음 한 문장은 말할 수 있어야 합니다.

> "무엇이 문제였고, 무엇을 바꾸어서 해결했는가?"

이 한 문장을 설명할 수 있다면 오류도 좋은 학습이 됩니다.

---

# 8. AI에게 질문할 때도 코드를 배우는 방식으로 질문합니다

AI에게 단순히

```text
코드 만들어 줘
```

라고 요청하는 것보다 다음과 같이 요청하는 것이 좋습니다.

```text
이 코드가 어떤 순서로 동작하는지 먼저 설명해 줘.

초보자가 이해할 수 있게 의사코드부터 작성해 줘.

중요한 부분과 단순 반복 부분을 구분해서 설명해 줘.

내가 직접 바꿔 볼 수 있는 부분을 알려 줘.

실행 결과에서 무엇을 확인해야 하는지 알려 줘.
```

이렇게 질문하면 AI를 단순히 **코드를 만들어 주는 도구**가 아니라 **코드를 이해하도록 도와주는 학습 도구**로 사용할 수 있습니다.

---

# 9. 수업 중에는 이 정도를 목표로 합니다

처음부터 혼자 모든 코드를 작성하는 것이 목표가 아닙니다.

다음 정도를 할 수 있다면 잘 배우고 있는 것입니다.

```text
코드를 보고 무슨 일을 하는지 알 수 있다.

        ↓

입력 → 처리 → 결과의 흐름을 설명할 수 있다.

        ↓

중요한 부분이 어디인지 찾을 수 있다.

        ↓

간단한 값이나 경로를 직접 바꿀 수 있다.

        ↓

실행 결과가 예상과 맞는지 확인할 수 있다.

        ↓

오류가 났을 때 어디부터 확인할지 생각할 수 있다.
```

---

# 10. 가장 중요한 원칙

코드를 외우려고 하지 마세요.

AI가 코드를 만들어도 괜찮습니다.

하지만 다음 세 가지는 꼭 반복합니다.

```text
읽기
↓
"무슨 코드인지 이해한다."


설명하기
↓
"내 말로 무엇을 하는 코드인지 말해 본다."


바꿔보기
↓
"한두 곳을 직접 수정하고 결과를 확인한다."
```

그리고 마지막으로 한 번 더 확인합니다.

```text
이 결과가 정말 내가 예상한 결과인가?
```

> AI가 작성한 코드를 그대로 사용하는 사람이 아니라, AI가 작성한 코드를 이해하고 확인하고 
> 조금씩 수정할 수 있는 사람이 되는 것이 목표입니다.
