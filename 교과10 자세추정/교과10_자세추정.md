
교과 10에서는 사람의 이미지와 영상에서 관절 위치를 찾고, 관절의 움직임을 숫자 데이터로 바꾸어 동작을 인식하는 전체 과정을 학습합니다.

사람의 동작을 인식하기 위해서는 단순히 한 장의 이미지에서 관절을 찾는 것만으로는 충분하지 않습니다. 관절 위치가 얼마나 정확한지 확인하고, 서로 다른 사람과 촬영 조건에서도 비교할 수 있도록 좌표를 정리한 뒤, 여러 Frame의 변화를 시간 순서로 연결해야 합니다.

교과 10에서는 이 과정을 작은 실습부터 단계적으로 확장합니다.

![[Group 21.png]]

교과 10의 목적은 Pose 모델 자체를 새로 학습하는 것이 아닙니다.

이미 학습된 Pose 모델을 사용하여 사람의 관절 정보를 얻고, 그 결과를 실제 동작인식 문제에 사용할 수 있는 데이터로 바꾸는 방법을 익힙니다. 또한 결과가 잘못되었을 때 모델만 확인하는 것이 아니라 입력 영상, Pose, Feature, Sequence, 동작분류, 실시간 처리까지 전체 Pipeline을 따라가며 문제의 원인을 찾는 방법을 학습합니다.

# 1. 교과 10의 전체 학습 흐름

교과 10은 **8시간 × 10일 = 80시간**으로 진행합니다.

10일 동안의 수업은 네 단계로 연결됩니다.

![[Pasted image 20260916135227.png]]

`38-D`는 한 Frame의 자세(Pose)를 38개의 숫자로 표현한 Feature Vector의 차원 수를 뜻합니다.
`38-D` 자체가 움직임을 나타내는 것은 아니라 한 개의 38-D는 한 순간의 자세를 숫자로 표현합니다.

==`38-D Frame Feature = 움직임을 숫자로 변환`==

더 정확한 표현은:

> 38-D Frame Feature  
> 한 Frame의 자세를  
> 34개 정규화 좌표 + 4개 관절각도로 표현

그리고 다음 단계인 Sequence에서:

> Sequence  
> 여러 Frame의 38-D Feature를  
> 시간 순서대로 연결하여 움직임을 표현

각 일차의 결과는 다음 수업에서 다시 사용됩니다.

```text
Pose
→ Keypoint
→ Feature
→ Sequence
→ Dataset
→ Action Model
→ Realtime
→ Tracking
→ Augmentation
→ Failure Analysis
```

따라서 교과 10의 실습은 매일 새로운 내용을 따로 만드는 방식이 아니라, 앞에서 만든 결과를 다음 단계로 확장하면서 하나의 동작인식 Pipeline을 완성하는 과정입니다.

| 일차 | 배우는 내용 | 핵심 결과 |
|---|---|---|
| 1일차 | 이미지·영상·IP Webcam에서 Pose 추론 | Pose 입력 Pipeline |
| 2일차 | Keypoint 좌표와 Confidence를 이용한 품질 확인 | Pose 품질 비교 결과 |
| 3일차 | 관절각도와 정규화를 이용한 Feature 생성 | 38-D Frame Feature |
| 4일차 | 여러 Frame Feature를 시간 순서로 연결 | Action Sequence |
| 5일차 | 여러 Subject의 데이터를 검수하고 분리 | QA · Subject-wise Split |
| 6일차 | Sequence를 이용한 동작분류 모델 학습 | Random Forest Baseline |
| 7일차 | 학습된 모델을 연속 영상에 적용 | 실시간 Action Recognition |
| 8일차 | 여러 사람을 추적하고 사람별 동작 분석 | Track ID별 Action Prediction |
| 9일차 | Keypoint 보강과 VAE 기반 패턴 비교 | Augmentation · Pattern Difference |
| 10일차 | 실패 원인 분석과 재현성 검증 | Failure Analysis · RUNBOOK |

# 2. 1일차 — Pose 전체 구조·개발환경·웹캠 이해

교과 10의 첫 단계에서는 이미지와 영상에서 사람의 관절을 찾는 **Pose Estimation의 기본 구조**를 학습합니다.

JPG는 한 장의 Frame을 가지고 있고, MP4는 여러 Frame이 시간 순서로 저장되어 있으며, IP Webcam은 Frame이 계속 들어오는 실시간 입력입니다. 입력 방식은 서로 다르지만 Frame을 얻은 이후에는 같은 Pose 처리 과정으로 연결할 수 있습니다.

```text
JPG · MP4 · IP Webcam
        ↓
Frame
        ↓
YOLO Pose
        ↓
Person Bounding Box
        ↓
COCO 17 Keypoint
        ↓
Skeleton
```

사전학습된 `yolo11n-pose.pt`를 사용하여 실제 이미지와 영상에서 사람이 검출되고 관절 위치가 표시되는 과정을 확인합니다.

또한 교과 10 전체에서 계속 사용할 프로젝트 구조와 Python 실행환경을 구성하고, OpenCV·PyTorch·Ultralytics가 정상적으로 동작하는지 확인합니다.

1일차를 마치면 **이미지·영상·실시간 카메라가 모두 Frame이라는 공통 형태로 Pose 모델에 입력된다는 구조**를 이해할 수 있습니다.

```text
1일차
Pose 결과 확인
        ↓
2일차
Pose 결과를 숫자로 읽고 품질 판단
```

# 3. 2일차 — 이미지·영상 Pose와 Keypoint 품질 확인

1일차에서는 Skeleton을 화면에 표시하여 Pose가 동작하는지 확인했습니다.

2일차에서는 화면에 보이는 Skeleton을 단순히 눈으로 확인하는 단계에서 벗어나, **Keypoint 좌표와 Confidence를 숫자로 읽는 방법**을 학습합니다.

사람의 자세가 같더라도 촬영 방향, 거리, 가림, 화면 이탈과 같은 조건이 달라지면 관절 검출 결과도 달라질 수 있습니다.

```text
Pose 결과
        ↓
Keypoint 좌표
        ↓
Confidence
        ↓
촬영 조건별 비교
        ↓
Pose 품질 판단
```

각 관절의 좌표와 Confidence를 확인하고, 정면·측면·가림·먼 거리 등의 조건에서 어떤 관절이 안정적으로 검출되고 어떤 관절이 불안정해지는지 비교합니다.

이 과정을 통해 Skeleton이 화면에 보인다는 사실만으로 Pose 결과가 항상 신뢰할 수 있는 것은 아니라는 점을 이해합니다.

2일차에서 Pose 품질을 확인하는 이유는 다음 수업에서 관절각도와 Feature를 계산할 때 잘못된 Keypoint를 그대로 사용하지 않기 위해서입니다.

```text
1일차 Pose
        ↓
2일차 Keypoint 품질
        ↓
3일차 Feature
```

# 4. 3일차 — 관절각도·정규화·Frame Feature

2일차에서 확인한 Keypoint 좌표는 사람의 관절 위치를 나타냅니다.

하지만 Pixel 좌표를 그대로 사용하면 사람이 화면의 왼쪽에 있는지 오른쪽에 있는지, 카메라에서 가까운지 먼지에 따라 값이 크게 달라질 수 있습니다.

3일차에서는 이러한 영향을 줄이기 위해 **몸 중심과 신체 크기를 기준으로 Keypoint 좌표를 정규화**합니다.

또한 어깨·팔꿈치·손목, 골반·무릎·발목처럼 세 개의 관절을 이용하여 관절이 얼마나 굽혀졌는지를 각도로 표현합니다.

```text
COCO 17 Keypoint
        ↓
관절각도 계산
        ↓
몸 중심 기준 위치 정규화
        ↓
신체 크기 기준 정규화
        ↓
34개 정규화 좌표
+
4개 관절각도
        ↓
38-D Frame Feature
```

이 과정을 거치면 한 Frame의 자세를 **38개의 숫자 Feature**로 표현할 수 있습니다.

3일차에서 만드는 Frame Feature는 이후 동작인식 과정의 기본 단위가 됩니다.

```text
한 Frame
→ 38-D Feature

여러 Frame
→ 여러 38-D Feature
→ 4일차 Sequence
```

# 5. 4일차 — Action Clip과 Sequence

3일차에서 만든 38-D Feature는 한 순간의 자세를 표현합니다.

하지만 동작은 한 순간의 자세가 아니라 **여러 Frame에서 자세가 시간에 따라 변하는 과정**입니다.

4일차에서는 준비된 6개의 Action Clip을 사용하여 각 Frame의 Feature를 시간 순서대로 연결합니다.

```text
Frame 1 → 38-D Feature
Frame 2 → 38-D Feature
Frame 3 → 38-D Feature
Frame 4 → 38-D Feature
...
        ↓
시간 순서 유지
        ↓
Sequence
        ↓
Action Label
```

예를 들어 `sit_stand` 동작은 서 있는 한 자세만으로 표현되지 않습니다.

```text
서기
→ 앉기
→ 다시 일어서기
```

이처럼 여러 Frame의 변화가 하나의 동작을 만듭니다.

4일차에서는 Pose와 Action의 차이, Clip과 Sequence의 차이를 이해하고, 영상의 각 Frame에서 38-D Feature를 만들면서 **동작을 시간 데이터로 표현하는 방법**을 익힙니다.

이 Sequence 구조는 5일차에서 여러 사람의 동작 데이터를 하나의 Dataset으로 구성하는 기반이 됩니다.

# 6. 5일차 — Keypoint Dataset QA와 Subject-wise Split

4일차에서는 한 사람이 수행한 6개 Action Clip으로 Sequence 구조를 확인했습니다.

5일차에서는 같은 6개 Action을 서로 다른 3명의 Subject가 수행한 **총 18개 MP4**로 확장합니다.

```text
3 Subjects
×
6 Actions
×
1 Take
=
18 MP4
```

동작인식 모델을 학습하기 전에는 영상이 정상적으로 읽히는지, Pose가 충분히 검출되는지, 필요한 관절이 누락되지 않았는지 먼저 확인해야 합니다.

따라서 5일차에서는 모델 학습보다 먼저 **Dataset QA**를 수행합니다.

```text
18 MP4
        ↓
Frame별 Pose 추론
        ↓
Keypoint Dataset
        ↓
자동 QA
        ↓
Human QA
        ↓
PASS / RESHOOT / EXCLUDE
        ↓
Approved Dataset
```

승인된 데이터는 사람을 기준으로 나눕니다.

```text
S01 → Train
S02 → Validation
S03 → Test
```

같은 사람의 Frame이 Train과 Test에 동시에 들어가면 모델이 새로운 사람의 동작을 잘 인식하는지 제대로 평가하기 어렵습니다.

따라서 5일차에서는 **Subject-wise Split과 Data Leakage 방지**의 중요성을 함께 학습합니다.

5일차에서 만든 Approved Dataset과 Split은 6일차 Action Recognition 모델의 직접적인 입력이 됩니다.

# 7. 6일차 — Action Recognition Baseline과 성능평가

6일차에서는 5일차에서 만든 Keypoint Dataset을 이용하여 처음으로 **Action Recognition 모델을 학습**합니다.

동영상마다 길이가 다르기 때문에 각 Clip의 Sequence 길이도 서로 다를 수 있습니다. 모델에 일정한 형태의 입력을 주기 위해 Sequence를 같은 수의 시간 지점으로 맞춥니다.

```text
Keypoint CSV
        ↓
38-D Frame Feature
        ↓
고정 길이 Sequence
        ↓
Sequence Feature
        ↓
Random Forest
        ↓
Validation
        ↓
Test
```

현재 수업에서는 Random Forest를 Baseline 모델로 사용합니다.

Baseline은 최종적으로 가장 좋은 모델이라는 뜻이 아니라, **전체 동작인식 Pipeline이 정상적으로 연결되는지 확인하고 이후 실험의 기준점을 만드는 모델**입니다.

모델을 학습한 뒤에는 Accuracy와 Macro F1을 확인하고, Confusion Matrix를 통해 어떤 동작끼리 혼동되는지 살펴봅니다.

또한 오분류된 결과는 숫자만 보는 것이 아니라 원본 영상과 다시 연결하여 실제 동작과 Pose 품질을 함께 확인합니다.

```text
성능 숫자 확인
        +
오분류 영상 확인
        ↓
모델이 무엇을 잘 구분하고
무엇을 헷갈리는지 분석
```

6일차에서 완성한 모델은 7일차에서 실시간 영상으로 확장됩니다.

# 8. 7일차 — Sliding Window와 실시간 동작인식

6일차에서는 시작과 끝이 정해진 완성된 Clip을 입력하여 동작을 분류했습니다.

실시간 카메라는 끝이 정해진 Clip이 아니라 Frame이 계속 들어옵니다.

따라서 7일차에서는 최근 일정 시간 동안 들어온 Frame을 모아 하나의 Sequence처럼 사용하는 **Sliding Window** 구조를 학습합니다.

```text
실시간 Frame
        ↓
Pose
        ↓
38-D Frame Feature
        ↓
최근 Frame Buffer
        ↓
Sliding Window
        ↓
Sequence Resampling
        ↓
6일차 Action Model
        ↓
실시간 Action Prediction
```

동작을 실시간으로 판단하면 한두 Frame의 변화 때문에 예측 Label이 빠르게 흔들릴 수 있습니다.

따라서 Prediction Confidence를 이용하여 신뢰도가 낮은 결과를 구분하고, 여러 예측 결과를 이용하여 Label을 안정화하는 방법도 함께 확인합니다.

저장영상을 먼저 Frame Stream처럼 처리하여 Runtime Pipeline을 검증한 뒤, IP Webcam에 연결하여 실제 동작을 수행합니다.

7일차를 통해 **저장영상에서 학습한 동작인식 모델을 실제 카메라 입력에 연결하는 방법**을 익힙니다.

```text
6일차
완성된 Clip 분류

        ↓

7일차
계속 들어오는 Frame에서
동작을 반복해서 판단
```

# 9. 8일차 — 다중 인물 Pose Tracking과 사람별 동작분석

7일차까지는 기본적으로 한 사람의 동작을 분석했습니다.

하지만 실제 영상에는 여러 사람이 동시에 나타날 수 있습니다.

8일차에서는 화면에 두 명 이상의 사람이 등장할 때 **각 사람이 누구인지 Frame 사이에서 계속 연결하는 Tracking**을 학습합니다.

```text
여러 사람
        ↓
Pose
        ↓
ByteTrack
        ↓
Track ID
        ↓
사람별 Feature Buffer
        ↓
사람별 Sliding Window
        ↓
사람별 Action Prediction
```

SBU 다중 인물 영상을 이용하여 두 사람이 가까워지거나 서로 겹치거나 빠르게 움직일 때 Track ID가 어떻게 유지되는지 확인합니다.

Tracking에서는 같은 사람의 ID가 중간에 바뀌는 ID Switch, 사람이 잠시 사라지는 Track Lost와 같은 문제가 발생할 수 있습니다.

이러한 문제는 Action Recognition에도 영향을 줄 수 있습니다. 서로 다른 사람의 Feature가 하나의 Buffer에 섞이면 잘못된 동작 결과가 만들어질 수 있기 때문입니다.

따라서 8일차에서는 **사람마다 독립된 Runtime State를 유지하는 구조**를 익힙니다.

```text
Person A
→ Track ID 1
→ Buffer 1
→ Action 1

Person B
→ Track ID 2
→ Buffer 2
→ Action 2
```

8일차를 통해 한 사람 중심의 동작인식 Pipeline을 여러 사람에게 확장하는 방법을 학습합니다.

# 10. 9일차 — Keypoint 보강과 VAE 이상 패턴 탐색

9일차에서는 새로운 원본 영상을 추가하지 않습니다.

5~6일차에서 만든 승인된 Keypoint Dataset과 Sequence를 다시 사용하여 두 가지 확장 실험을 진행합니다.

첫 번째 실험에서는 Train Keypoint를 Flip과 Jitter로 변형하여 **파생 학습 데이터**를 만듭니다.

```text
S01 Train Keypoint
        ↓
Horizontal Flip
+
Jitter
        ↓
38-D Feature 다시 계산
        ↓
Augmented Train Sequence
        ↓
Random Forest 재학습
        ↓
같은 S02 Validation과 비교
```

보강 데이터는 원본 데이터의 구조를 이용하여 만든 파생 데이터입니다.

새로운 사람을 촬영한 데이터와 같은 의미는 아니지만, 제한된 Train 데이터에서 모델이 다양한 변화를 경험하도록 만드는 방법을 이해할 수 있습니다.

두 번째 실험에서는 VAE를 이용하여 하나의 Reference 움직임과 다른 패턴을 찾습니다.

```text
wave Reference
        ↓
VAE
Encoder → Latent → Decoder
        ↓
Reconstruction Error
        ↓
Threshold
        ↓
Reference와 다른 패턴 후보
```

여기에서 Reconstruction Error가 높다고 해서 곧바로 위험행동이라고 판단하는 것은 아닙니다.

현재 실습에서 VAE는 **학습한 Reference 패턴과 얼마나 다른 움직임인지 확인하는 교육용 Pattern Difference Detector**로 사용합니다.

또한 9일차 프로젝트는 8일차에서 이어지지만, 실험에 사용하는 데이터는 SBU Tracking 영상이 아닙니다.

```text
프로젝트 흐름
8일차 → 9일차

데이터 흐름
5일차 Keypoint
→ 6일차 Sequence
→ 9일차 Augmentation / VAE
```

9일차의 결과는 10일차에서 시스템의 실패 원인을 분석할 때 보조 근거로 사용됩니다.

# 11. 10일차 — 실패분석·종합 Challenge·재현성 검증

10일차에서는 새로운 알고리즘을 많이 추가하지 않습니다.

1~9일차에서 만든 데이터, 모델, Runtime, Tracking, 보강 결과를 다시 연결하여 **동작인식 시스템의 실패 원인을 찾는 방법**을 학습합니다.

동작 예측이 틀렸다고 해서 바로 모델이 잘못되었다고 판단할 수는 없습니다.

문제는 입력 영상부터 시작될 수도 있고, Pose가 잘못 검출되었거나 Feature와 Sequence를 만드는 과정에서 발생했을 수도 있습니다.

```text
Input
        ↓
Pose
        ↓
Data
        ↓
Feature
        ↓
Sequence
        ↓
Action
        ↓
Realtime
        ↓
Tracking
```

따라서 결과가 잘못되었을 때는 Pipeline을 앞에서부터 확인하며 **문제가 처음 나타난 단계**를 찾습니다.

```text
1~9일차 결과
        ↓
Failure Catalog
        ↓
실패 증상 확인
        ↓
최초 실패 단계 추적
        ↓
Root Cause Hypothesis
        ↓
한 변수 A/B 실험
        ↓
Before / After 비교
```

문제 원인을 확인할 때는 여러 조건을 한꺼번에 바꾸지 않습니다.

한 번에 하나의 변수만 변경하여 Before와 After를 같은 입력과 같은 기준으로 비교해야 어떤 변화가 결과에 영향을 주었는지 설명할 수 있습니다.

마지막에는 새로운 Subject의 영상 또는 기존 Hold-out 입력에 전체 Pipeline을 다시 적용합니다.

```text
Final Challenge
        ↓
기존 Pipeline 재사용
        ↓
새로운 입력 실행
        ↓
결과 확인
        ↓
실패 시 원인 추적
```

또한 다른 사람이 같은 환경에서 같은 결과를 다시 실행할 수 있도록 실행 순서, 환경, 설정, 모델 정보를 정리합니다.

이 과정을 통해 **실패분석과 재현성**이 모델 성능만큼 중요한 개발 과정이라는 점을 익힙니다.

# 12. 교과 10에서 익히는 전체 Pipeline

교과 10의 각 일차는 서로 다른 기술을 따로 배우는 과정이 아닙니다.

사람의 영상을 입력으로 받아 동작인식 결과를 만들기까지 하나의 Pipeline을 단계적으로 완성하는 과정입니다.

```text
사람 영상을 입력한다
        ↓
Pose 모델로 관절을 찾는다
        ↓
Keypoint의 품질을 확인한다
        ↓
관절을 비교 가능한 Feature로 바꾼다
        ↓
여러 Frame을 Sequence로 연결한다
        ↓
여러 사람의 Dataset을 구성한다
        ↓
Action Recognition 모델을 학습한다
        ↓
실시간 영상에 적용한다
        ↓
여러 사람을 Tracking한다
        ↓
Train 데이터를 보강한다
        ↓
Reference와 다른 패턴을 탐색한다
        ↓
실패 원인을 단계별로 분석한다
        ↓
같은 결과를 다시 재현한다
```

이 전체 흐름을 이해하면 새로운 동작이나 새로운 영상이 주어졌을 때도 어느 단계에서 무엇을 준비하고 확인해야 하는지 판단할 수 있습니다.

# 13. 교과 15와의 연결

교과 10은 산업안전 동작인식 프로젝트를 수행하기 전에 **Pose 기반 Action Recognition의 기본 구조를 충분히 경험하는 과정**입니다.

교과 10에서 사용한 작은 교육용 Dataset이나 Random Forest 모델 자체가 최종 프로젝트의 결과물이 되는 것은 아닙니다.

교과 10에서 익힌 Pipeline과 문제 해결 방법을 바탕으로 교과 15에서는 새로운 동작과 더 많은 데이터를 사용하는 프로젝트로 확장합니다.

```text
교과 10

Pose
→ Keypoint
→ Feature
→ Sequence
→ Action Recognition
→ Realtime
→ Tracking
→ Failure Analysis

        ↓

교과 15

프로젝트용 동작 정의
→ 데이터 수집
→ 동작 Class 확대
→ 실시간 PC · Webcam 시스템
→ Accuracy · FPS 검증
→ 실패분석과 개선
```

교과 10을 마친 뒤에는 단순히 Pose 모델을 실행하는 것에서 끝나지 않고, **사람 영상이 동작인식 결과로 바뀌는 전체 과정을 설명하고 직접 연결할 수 있어야 합니다.**

새로운 영상에서 결과가 좋지 않을 때도 모델만 다시 학습하는 것이 아니라 Pose 품질, 데이터 구성, Feature, Sequence, Runtime과 Tracking까지 차례로 확인하여 문제의 원인을 찾을 수 있어야 합니다.

이러한 경험이 교과 15의 산업안전 동작인식 프로젝트를 설계하고 구현하는 기본 역량이 됩니다.
